## 二、uni-app 开发硬约束

1. **标签使用 uni-app 组件**：容器用 `view`、文本用 `text`、按钮用 `button` 或自有 `xf-button`，禁止把点击事件绑在普通 `view` 上模拟按钮（无点击态、无防抖、无障碍缺失、易点击穿透）。
2. **禁止 Web 专属 API**：不得使用 `document`、`window`、`navigator` 等 DOM/BOM 对象；跨端能力一律走 uni API（`uni.getSystemInfoSync`、`uni.createSelectorQuery` 等）。
3. **尺寸单位统一 `rpx`**：禁止给组件/页面写死 `px` 宽高（字体可用 uni.scss 中字号变量）；布局用 flex + 百分比/ rpx，禁止固定像素拼页面。
4. **禁止大量 `position: absolute` 拼页面**，防止父容器塌陷、滚动错乱；仅允许用于角标、浮层等确实需要脱离文档流的场景。
5. `scroll-view` 必须给定明确高度约束；长列表考虑分页、触底加载和骨架屏。
6. **底部固定按钮必须避让全局底栏**：非 tab 页（navigateTo 进入）底部按钮用 `margin-top: auto` + 容器 `padding-bottom: calc(var(--tab-bar-height, 0px) + 间距)`，**禁用 `position: fixed`**（会被 H5 全局底栏遮挡），**禁用 `var(--window-bottom)`**（scoped 内可能为 0px，见 `docs/H5-tabbar机制与全局底栏.md`）。

## 三、按钮与组件设计规范（重点：禁止乱设计、乱布局）

### 3.1 按钮

1. **必须复用**：优先使用 `components/xf-button.vue` 或 uview-plus 的 `u-button`，禁止每次新造一套按钮样式。
2. **固定四级层级，不得混用**：主填充按钮（主色 `#fe3c72`）、次描边按钮、文本按钮、危险按钮（`$uni-color-error`）；同页面主次必须可一眼区分，取消按钮不得比提交按钮醒目。
3. **点击热区**：可点击元素高度最小 `88rpx`，图标按钮同样不小于 88rpx，保证手指容错。
4. **状态完备**：每个按钮必须有默认、禁用（`$uni-opacity-disabled`）、加载（loading）、点击反馈态；禁用态必须真正拦截点击，不只是变灰；loading 时文字与转圈不得重叠。
5. **按钮组**：同行按钮统一高度、统一基线，间距用 `gap: 24rpx`；小屏自动折行，禁止横向溢出；图标+文字组合的图标位置、大小、间距全站一致。
6. **防重复提交**：表单提交按钮点击后立即进入 loading/禁用，配合防抖，禁止重复发请求。
7. **固定底部操作栏**：必须处理软键盘遮挡与底部安全区（`safe-area-inset-bottom`），z-index 不得高于弹窗/Toast，避免浮层层级陷阱。
8. 一个卡片/一行内操作按钮不超过 3 个；查看、复制等次要操作不得做成填充主按钮；悬浮按钮不得遮挡列表内容与弹窗。
9. **品牌渐变与无障碍**：主品牌渐变统一为玫红→珊瑚 `linear-gradient(135deg, #fe3c72, #ff655b)`（变量 `$uni-gradient-primary`），禁止再用旧的紫→粉渐变；主色白字对比度仅 3.44:1（满足 AA Large），浅底小字/小图标必须用深变体 `#c2185b`（`$uni-color-primary-deep`），禁止在 `#ffeff5` 等浅底上用主色写普通字号文本。旧冷粉 `#ff5e9c` 已废弃，禁止继续使用。

### 3.2 表单组件

1. label 位置、必填星号位置、校验提示位置全站统一（提示固定在字段下方，禁止上下飘动）。
2. 输入框圆角、边框引用 uni.scss 变量（输入框 `16rpx`），禁止各页面一套值。
3. 键盘类型必须匹配：数字/验证码输入拉起数字键盘（`type="number"` / `confirm-type` 正确设置）。
4. 未满足必填/校验规则前，提交按钮保持禁用。

### 3.3 弹窗、抽屉、下拉浮层

1. 优先使用 `a11y-dialog`、uview-plus 弹层组件；禁止写死宽高导致小屏溢出，弹窗内部长内容必须可滚动。
2. 遮罩点击关闭、关闭按钮位置、按钮横/竖排方式全站统一。
3. 下拉/级联/筛选浮层必须自动判断上下展开方向，不得超出屏幕边界；禁止用 `view` 自造无无障碍能力的原生下拉替代品。

### 3.4 标签、状态、卡片

1. 状态色只允许引用 Token：成功 `$uni-color-success`、警告 `$uni-color-warning`、错误 `$uni-color-error`，禁止同一状态跨页面颜色不一致。
2. Tag/徽章大小、圆角统一；长文本截断（`ellipsis`），禁止撑开容器。
3. 卡片圆角用 `24rpx`（`$uni-border-radius-lg`），阴影、内边距全站统一；禁止卡片套卡片、所有模块无差别套卡片。

### 3.5 图标（选型已锁定，详见 `docs/icon-icons.md`）

1. **新图标一律用 UnoCSS Icons + Phosphor**：类名 `i-ph-{图标名}`（如 `i-ph-heart`、`i-ph-heart-bold`、`i-ph-heart-fill`），依赖 `unocss` + `@iconify-json/ph`。
2. **`uni-icons` 冻结**：存量约 46 处保留可运行，禁止新增任何 `uni-icons` 引用，禁止把 Phosphor 回退为 uni-icons；禁止引入 u-icon/IconPark/FontAwesome 等未评审图标库做主方案。
3. **类名规则**：只用中划线，禁止冒号写法（小程序会拆成两个类名）；动态拼接/后端返回的类名必须在 `unocss.config.ts` 的 `safelist` 登记。
4. 图标颜色走主题变量 class（禁止硬编码十六进制），浅底小图标遵守对比度规则；大小用 class 控制。
5. **tabbar 定制图形例外**：继续用 `scripts/gen-tabbar-icons.py` 生成的 PNG，禁止改成通用字体图标。
6. 存量迁移按页面分批进行（P0 优先），禁止一次性全量重写。

## 四、布局与间距体系

1. **间距只能取刻度值**：`16rpx / 24rpx / 32rpx / 48rpx`（紧凑场景可用 8rpx），禁止出现 12、14、18 等随手写的 margin/padding/gap。
2. **对齐基准统一**：同页面元素左对齐基线一致，列表项垂直对齐规则统一，禁止左对齐/居中/右对齐随意切换。
3. **自适应**：禁止硬编码宽高；必须验证小屏不溢出、大屏不空旷，兼顾不同机型与折叠屏。
4. **安全区**：顶部避开状态栏/刘海，底部避开小黑条；全面屏机型不得裁切按钮。
5. **动态内容必做边界处理**：昵称、地址等长文本截断；图片固定尺寸 + `mode` 防变形；数据条数变化不得导致布局错位。
6. **页面状态齐全**：每个数据页必须实现加载中（`skeleton`）、空数据（`empty-state`）、网络异常/错误态（`error-boundary`、`network-status-bar`），禁止只留空白。

## 五、样式与一致性

1. 颜色、圆角、字号、透明度一律引用 `uni.scss` 变量，禁止硬编码十六进制色值；主色只有 `#fe3c72`（珊瑚 `#ff655b`、深变体 `#c2185b`），禁止出现 `#1677ff`、`#2080ff` 等近似色漂移，禁止使用已废弃的 `#ff5e9c`。
2. 字号层级引用 Token：`$uni-font-size-sm/base/lg`，标题、正文、辅助文字粗细层级分明。
3. 同一业务组件（搜索栏、底部栏、弹窗、按钮等）跨页面必须完全一致，禁止每次重新生成一套样式。
4. 新增组件前先检查 `components/` 与 uview-plus 是否已覆盖；确需新增时，同时支持上述全部状态并接入 Token，命名采用 `xf-` 或清晰的 kebab-case。

## 六、典型问题黑名单（生成结果中出现即视为不合格，必须返工）

- 主/次/取消按钮样式趋同，视觉层级失效
- 按钮小于 88rpx、热区拥挤、图标按钮难以点中
- 只有默认态，无禁用/loading/点击反馈；禁用按钮仍可点
- 底部按钮被软键盘或小黑条遮挡、被弹窗盖住或盖住弹窗
- 写死 px 宽高、小屏横向溢出、大量 absolute 定位
- 间距一页一个值（12/14/18 等随机数）、元素肉眼不对齐
- 状态色、主色硬编码且跨页面不一致
- 用 view 模拟按钮/下拉、无无障碍与键盘支持
- 长文本撑破布局、无空状态/加载态/错误态
- 重复造已有组件、同业务组件跨页面长得不一样
- 新增 uni-icons 或把 Phosphor 图标回退、使用冒号类名、动态类名未 safelist
- 把 tabbar 定制 PNG 改成通用字体图标
- 表单可重复提交、点击无任何 Toast/加载反馈

## 七、输出前自检清单（每次交付前逐项核对）

1. 按钮层级：主/次/危险/文本是否清晰，是否复用了 xf-button 或 u-button
2. 热区：所有可点击元素是否 ≥ 88rpx
3. 状态：默认/禁用/loading/反馈是否齐全且真实生效
4. 遮挡：软键盘、安全区、z-index 层级是否处理
5. 单位与自适应：是否全 rpx + flex，小屏/大屏是否验证无溢出
6. 间距：是否全部落在 8/16/24/32/48rpx 刻度，对齐基线是否统一
7. Token：颜色/圆角/字号是否全部引用 uni.scss，有无硬编码
8. 边界：长文本截断、空/加载/错误三态、动态数据布局是否稳定
9. 复用：是否存在重复造轮子，跨页面组件是否一致
10. 图标：新增图标是否全部 `i-ph-*`（无新增 uni-icons）、类名中划线、动态类名已 safelist、tabbar 未被改字体图标
11. 类型检查：`pnpm type-check`（vue-tsc）是否通过

- 文档与 README 中的截图必须来自真实运行环境实测，禁止占位或过时截图。
- **任务完成必须更新文档**：技术栈/基础设施升级（含 Gitea、Runner、JDK、Node、中间件、框架大版本）同步版本基线到 README、相关部署文档，并在 `CHANGELOG.md` 顶部按既有格式留痕（版本号、备份/回滚方式、验证结果）；普通开发任务同样登记 CHANGELOG。

## 九、多 Agent 协作（看板认领协议）

多个 agent（subagent）并行开发时，强制使用 `.claude/board/` 任务看板（协议全文见 `.claude/board/README.md`，该目录不入库）：

1. **开卡时机**：并行 ≥2 个 agent、或任务涉及 ≥3 个文件/多阶段时，编排者（主控 Claude）必须先在 `.claude/board/tasks/` 按 `_template.md` 建卡（含硬边界文件清单与验收标准），再派单。
