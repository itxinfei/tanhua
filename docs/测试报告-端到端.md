## 一、测试概述

### 1.1 测试目标

验证 App 全部功能域在**正常场景、边界场景、异常场景**下的行为正确性，覆盖每一个可点击元素与每一个表单输入项，确认无功能遗漏、无交互项遗漏。

### 1.2 测试环境

| 项 | 值 |
|---|---|
| 后端 JDK | 25.0.3 LTS |
| BFF 端口 | 18081（`xfjy-server`） |
| 网关端口 | 8090（`xfjy-gateway`） |
| Nacos | 192.168.20.133:8848 |
| MySQL | 192.168.20.133:3306 |
| Redis | 192.168.20.133:6379 |
| 前端构建 | Node 24.18.0 / Vite / `@dcloudio/*` 3.0.0-5030420261029002 |
| 浏览器 | Chromium 1248（Playwright 本地） |
| 视口 | 320×568 / 390×844 / 768×1024 / 1440×900 |

### 1.3 测试方法说明

本报告采用三层验证：

1. **代码契约扫描**：从 Controller 注解提取真实路由、方法、参数，从前端源码提取表单校验规则与常量上限，确保用例设计与实现一致（而非凭需求文档想象）。
2. **真实服务冒烟**：启动 BFF 与网关，对公开接口与受保护接口发起真实 HTTP 请求，记录实际状态码与响应体。
3. **多视口渲染验证**：用 Playwright 加载页面，测量元素实际尺寸、热区、溢出，模拟按压验证交互反馈。

### 1.4 缺陷分级标准

| 级别 | 定义 | 处理要求 |
|---|---|---|
| P0 | 阻塞核心流程，数据丢失或资金风险 | 立即修复，禁止发布 |
| P1 | 核心功能不可用或结果错误 | 本迭代修复 |
| P2 | 非核心功能异常或体验明显受损 | 排期修复 |
| P3 | 轻微体验问题 | 记录观察，择机优化 |

## 三、鉴权与安全链路测试

### 3.1 测试依据

`AGENTS.md` §4 定义的四层鉴权链：网关限流 → BFF Token 校验 → 后台角色 → 领域服务内部 token。

### 3.2 实测结果

**受保护接口无 token 访问（BFF 直连 18081）**

| 接口 | 方法 | 预期 | 实测 | 结论 |
|---|---|---|---|---|
| `/users` | GET | 401 | 401 | 通过 |
| `/users/counts` | GET | 401 | 401 | 通过 |
| `/users/vip/status` | GET | 401 | 401 | 通过 |
| `/users/settings` | GET | 401 | 401 | 通过 |
| `/xfjy/todayBest` | GET | 401 | 401 | 通过 |
| `/small-videos` | GET | 401 | 401 | 通过 |
| `/comments` | GET | 401 | 401 | 通过 |
| `/users/friends/like` | GET | 401 | 401 | 通过 |
| `/users/blacklist` | GET | 401 | 401 | 通过 |
| `/users/questions` | POST | 401 | 401 | 通过 |
| `/users/verify` | POST | 401 | 401 | 通过 |
| `/users/logoff` | POST | 401 | 401 | 通过 |
| `/baidu/location` | POST | 401 | 401 | 通过 |

**结论**：13/13 全部返回 401，鉴权拦截生效。响应体为空、仅 `setStatus(401)`，符合 §4 记录的既有形态。

### 3.3 网关限流测试

`RateLimitGlobalFilter` 规则：仅 POST 的 `/movements`、`/comments`、`/small-videos`、`/users/report`，5 次/60s/IP，超限 429。

| 请求序号 | `/comments` 实测 | 预期 | 结论 |
|---|---|---|---|
| 1–4 | 401 | 401（限流未触发） | 通过 |
| 5 | 401 | 401 | 通过 |
| 6 | **429** | 429（超限） | 通过 |
| 7 | **429** | 429 | 通过 |

**结论**：限流阈值精确（第 6 次触发），60s 窗口正确。

### 3.4 内部 Token 校验

| 接口 | 预期 | 实测 | 结论 |
|---|---|---|---|
| `/agreements/user`（无内部 token） | 403 | 403 `{"code":403,"message":"Forbidden: invalid internal token"}` | 通过 |
| `/kefu/faq`（无内部 token） | 403 | 403 同上 | 通过 |

### 3.5 发现的问题

| 编号 | 级别 | 描述 | 证据 | 处理建议 |
|---|---|---|---|---|
| BUG-01 | P2 | 网关层偶发 503：`/comments` 在第 5 次请求返回 503 而非 401 | 见 §3.3 复测 | 本地测试环境存在旧 jar 注册到 Nacos（`192.168.10.81:18081`），网关轮询命中。**非代码缺陷**，重新打包并清理 Nacos 注册即可 |
| BUG-02 | P3 | 部分 GET 接口路径前缀与直觉不符（`/xfjy/todayBest` 而非 `/match/todayBest`） | 代码 `@RequestMapping("xfjy")` | 属历史命名，不影响功能；建议统一为 `/match` |
