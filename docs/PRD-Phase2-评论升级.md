## 一、背景与目标

### 1.1 业务背景

当前评论功能仅支持纯文本、平铺展示，缺少：
- 表情回复（用户只能用文字表达情绪）
- @ 功能（无法在评论中提及他人）
- 回复某条评论（只能全量评论，无法形成对话感）

### 1.2 数据目标

| 指标 | 当前 | 目标 |
|------|:---:|:---:|
| 人均评论字数 | 8 字 | 15+ 字 |
| 评论回复深度（二级评论率）| 0% | 20%+ |
| 评论表情使用率 | 0% | 40%+ |

### 2.3 @ 提及功能

**输入触发**：
1. 输入 `@` → 弹出选择面板
2. 面板展示：最近互动过的用户（最多 8 人）+ 帖子作者 + 二级评论作者
3. 可继续输入关键词实时搜索
4. 点击选中 → 插入 `@昵称 ` 到输入框
5. 发送时，被 @ 的用户收到推送提醒「XXX 在评论中提到了你」

**展示规则**：
- `@昵称` 在评论中以**蓝色高亮**显示
- 点击 `@昵称` 跳转到该用户主页（复用 detail.vue）

### 2.4 表情面板

- 20 个常用 emoji（😀😁😂🤣😍😘😎😢😡👍❤️😴🤔🥵❄️🎉🍻🔥💯）
- 面板底部固定，点击即插入光标位置
- 不做自定义表情商城（二期迭代）

## 四、接口设计

### 4.1 评论列表（改造）

- **接口**：`GET /circle/{postId}/comments?page=1&pageSize=20`
- **逻辑**：
  - 返回顶级评论（parentId=0）
  - 每条顶级评论带 `replies[]`（二级嵌套，最多 3 条）
  - 若二级条数 > 3，显示"查看 N 条回复"（点击加载更多，分页）

### 4.2 发送评论（改造）

- **接口**：`POST /circle/{postId}/comments`
- **请求体**：

```json
{
  "content": "这个周末真的太热了 🥵",
  "parentId": 0,
  "replyUserId": 0,
  "atUserIds": []
}
```

- **被 @ 用户非 0 时**：后端调用 PushService.atNotify()

### 4.3 @ 搜索用户

- **接口**：`GET /circle/{postId}/comments/at-search?keyword=`
- **响应**：

```json
{
  "code": 200,
  "data": {
    "recentUsers": [
      { "userId": 101, "nickname": "小王", "avatar": "..." },
      { "userId": 102, "nickname": "小李", "avatar": "..." }
    ],
    "postAuthor": { "userId": 201, "nickname": "作者", "avatar": "..." }
  }
}
```

### 4.4 二级回复分页

- **接口**：`GET /circle/{postId}/comments/{parentId}/replies?page=1&pageSize=10`
- **请求**：点击"查看 N 条回复"时调用

## 五、边界场景

| 场景 | 处理 |
|------|------|
| @ 后用户改名 | @ 显示发送时的快照昵称（不联动更新），点击跳转到最新用户主页 |
| 表情输入超长 | content 字段大溢：数据库 VARCHAR(1000)，超出部分截断 + 前端校验 |
| 二级回复中子评论被删 | 对话中的"该评论已删除"占位，后续评论继续展示 |
| 被 @ 的用户已封禁/注销 | 推送不发，仅展示文本但不跳转 |
| 回复二级评论 | parentId = 二级评论 ID，replyUserId = 二级评论作者 ID |
| 复制评论文本 | uni.getClipboardData 获取纯文本（去除 @ 标记和 emoji）|
