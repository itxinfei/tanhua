# PRD：女用户保护与平台安全机制（Phase 3 P2）

> FR-ID: **FR-SAFE-01**  
> 优先级：**P2**  
> 负责人：前端 1 人 + 后端 1 人  
> 预估工时：前端 1.5d + 后端 2d = 3.5d

> FR-ID（需求文档关联）：FR-USER-01（用户账户）/ FR-MATCH-01（匹配）

## 一、背景与目标

### 1.1 业务背景

陌生人社交平台的**核心风险**是女用户体验恶化 → 女用户流失 → 男用户匹配池萎缩 → 平台死亡。

**触目惊心的行业数据**：
- 探探/ Soul 女用户卸载主因：被骚扰占 63%
- 女用户收到第一条消息后 24h 内不回复概率 > 50%（因为骚扰占比过高）
- 女用户向好友推荐陌生人社交 App 的意愿仅 3%（因为"太乱了"）

**当前产品安全机制缺失**：
1. 女用户首次使用无安全引导
2. 聊天时无快捷屏蔽/举报入口
3. 举报流程无截图上传
4. IM 图片无 AI 敏感检测
5. 无"仅匹配已认证用户"保护选项
6. 无边控关键词自动拦截

### 1.2 数据目标

| 指标 | 当前 | 目标 |
|------|:---:|:---:|
| 女用户 7 日留存 | ≈男用户（无差异保护）| 女用户超过男用户 20%+ |
| 骚扰举报率 | — | < 0.5%（占总消息比）|
| 举报处理 48h 响应率 | — | 95%+ |
| 女用户 NPS（净推荐值）| — | > 30 |
| 已认证用户被喜欢数 vs 未认证 | — | 2x+ |

### 1.3 非目标

- 不在本版本实现 AI 鉴黄/暴恐图片检测（预留扩展位，一期规则 + 人工为主）
- 不做实时人脸年龄检测（合规留到二期）
- 不做公安联网身份核验（预留接口，暂不接）

### 2.5 IM 图片敏感检测（规则引擎）

**发送方检测**：用户发送图片时，客户端做一级检测，命中敏感图不允许发送

```typescript
// utils/sensitive-image.ts（一期规则检测）
export async function checkImageSensitive(filePath: string): Promise<{ blocked: boolean; reason: string }> {
  // 一期：文件大小校验 + 格式校验
  // 文件大小 > 50MB 不允许
  // 非图片格式不允许
  // 保留 AI 鉴黄 SDK 扩展位（二期接入）
  
  // 返回
  return { blocked: false, reason: '' };
}
```

**接收方保护**：女用户开启「不接受陌生人图片」开关后，非好友发来的图片不在前端渲染

### 2.6 内容安全策略频率限制

| 场景 | 规则 | 前端提示 |
|------|------|---------|
| 同一条消息内容 | 10s 内只能发送 3 次（防刷屏）| 按钮 disabled 3s + toast"发送太频繁，请稍候" |
| 同一收信人 | 1min 内最多发 10 条消息 | 按钮 disabled + toast"发送频率过高，请稍后再试" |
| 陌生人首次消息 | 仅允许纯文字 + 系统破冰语（图片/语音需对方回复 1 条后才可发）| 图片/语音按钮灰显 + tooltip"对方回复后可发送图片" |
| 新注册用户 24h 内 | 最多发 50 条私信 | 超限后 toast"新手期每日限发 50 条私信，明天继续" + 输入框 disabled |

## 五、边界场景

| 场景 | 处理 |
|------|------|
| 同一用户多次举报 | 限制 1 小时内只能举报同一用户 1 次（防刷举报）|
| 举报被驳回 | 被举报用户无感知，邀请方收到"经审核未发现违规"通知 |
| 误报导致用户被误封 | 被举报用户可申诉 → 运营 48h 内复核 |
| 黑名单已满 | 上限 200 人，超出后提示"请先清理黑名单" |
| 女用户开启"仅匹配已认证"后推荐池为空 | 展示引导："当前认证用户较少，是否放宽匹配？"+ 切换按钮 |
| 图片敏感检测 SDK 不可用（网络问题）| 踢过后备方案：允许发送 + 增加人工审核标记频率 |
