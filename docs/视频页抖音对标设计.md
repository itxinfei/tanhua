## 一、设计目标与对标原则

1. **完全对标抖音**：全屏沉浸式竖版视频、上下滑动切换、右侧竖排操作栏、底部毛玻璃导航。
2. **信息密度与抖音一致**：数字缩写规则、图标尺寸、间距统一，不引入抖音没有的多余元素（如系统音量控件、无意义圆形底）。
3. **实用为王、拒绝过度设计**：仅实现可在真实环境运行的能力；依赖后端的能力（语音评论）明确标注依赖与分阶段路径，不做无法闭环的“假功能”。
4. **品牌融合**：在抖音形态基础上，主色使用心飞品牌色（`#ff5e9c` 粉、`#b13bff` 紫、渐变 `linear-gradient(135deg,#b13bff,#ff5e9c)`）。

## 三、数字展示规则（重点）

### 3.1 抖音规则（心飞完全采用）

抖音**没有“千”单位**，1 万以下一律显示完整数字；达到 1 万才以“万”缩写，1 亿以上以“亿”缩写。

| 原始数值 | 显示 | 说明 |
|---|---|---|
| 0 | `0` | |
| 999 | `999` | |
| **1000** | **`1000`** | 不缩写、不显示“1千” |
| 9999 | `9999` | |
| 10000 | `1万` | 小数为 0 时省略小数点 |
| 10500 | `1.1万` | 四舍五入保留 1 位小数 |
| 12300 | `1.2万` | |
| 12345 | `1.2万` | |
| 99999 | `10万` | |
| 100000 | `10万` | |
| 1235000 | `123.5万` | |
| 99999999 | `1亿` | 四舍五入进位，不允许出现“10000万” |
| 100000000 | `1亿` | |
| 150000000 | `1.5亿` | |
| 1234567890 | `12.3亿` | |

### 3.2 规则口径

1. 入参先 `Number()` 转换，非法值统一兜底为 `0`。
2. 先向下取整（`Math.floor`），不显示小数个位数。
3. “万/亿”单位保留 **1 位小数**，使用四舍五入（`Math.round(x*10)/10`）；小数部分为 0 时不显示 `.0`。
4. 万分支若四舍五入后达到 10000（即进位到 1 亿），改用“亿”显示。
5. 适用范围：视频右侧**点赞数、评论数**，评论区**评论点赞数**，以及后续所有计数场景。

### 3.3 实现

- 公共函数：`xfjy-app/src/utils/format.ts` → `formatCount(value)`。
- 已在 `pages/video/index.vue`、`components/video-comment-drawer.vue` 接入，禁止各页面自行手写缩写逻辑。

## 四、播放与手势交互规范

### 4.1 自动播放

- 进入页面当前视频自动播放、循环（`loop`）。
- 因浏览器自动播放策略，H5 首次以**静音（muted）起播**；在用户首次点击或滑动（用户手势）后自动解除静音恢复声音。
- 不提供系统音量控件——App/H5 无法控制系统音量，音量由设备物理按键控制。

### 4.2 单击：暂停 / 播放（延迟判定）

为区分单击与双击，采用抖音式延迟判定，判定窗口 **280ms**：

1. 第一次点击：**不立即暂停**，启动 280ms 定时器。
2. 280ms 内无第二次点击：到点执行暂停（或播放），暂停时显示中央大播放键。
3. 280ms 内出现第二次点击：判定为双击，清除待执行的单击（不会闪一下暂停）。

### 4.3 双击：点赞 + 飞心

1. 280ms 内连续两次点击 → 点赞（未赞则点赞，已赞不重复）。
2. 在点击位置生成飞心动画（粉色爱心放大上浮淡出），右侧点赞图标执行弹动（`likePop`：scale 1→1.35→0.9→1）。
3. 双击后视频保持播放，不暂停。
4. 设置双击冷却期（280ms），冷却期内忽略浏览器/触摸产生的残留点击事件，避免误触发暂停。

### 4.4 上下滑动：切换视频

1. 上滑切下一条、下滑切上一条，swiper 竖向分页。
2. 切换时**先暂停旧视频，再播放新视频**，重置播放状态与进度，避免多视频同时发声或状态错乱。
3. 接近列表末尾（当前 index ≥ 总数-2）自动加载更多（`loadMoreVideos`）。

> 桌面测试环境无法注入真实触摸手势（合成事件 `isTrusted=false` 不被 swiper 接受），真机手势需在手机/移动模拟下最终确认；切换的命令式 pause/play 逻辑已通过验证。

## 五、右侧操作栏规范

右侧竖排，自上而下，图标白色、30px，数字白色带文字阴影；去除抖音没有的透明圆形底（`icon-circle`）。

| 顺序 | 元素 | 图标 | 交互 |
|---|---|---|---|
| 1 | 作者头像 + 关注加号 | 头像（白边）+ 粉色 `+` | 点击关注/取消关注；已关注则隐藏 `+` |
| 2 | 点赞 | `heart` / `heart-filled`（选中粉 `#ff5e9c`） | 单击切换点赞，弹动动画；数字按 `formatCount` |
| 3 | 评论 | `chatbubble` | 点击打开评论抽屉；数字按 `formatCount` |
| 4 | 分享 | `redo`（右上箭头，替代粗糙文本 `↗`） | 点击打开分享面板（微信/朋友圈/复制链接） |

- 音乐唱片固定在右下，播放时旋转。
- 所有可点元素保留按压反馈（`btn-feedback`）与无障碍 label。

## 六、底部 tabBar 与发布“+”

### 6.1 发布键对标抖音（本次改动）

- 中间发布入口**只保留一个“+”**，不显示图标方块、不显示“发布”文字。
- “+”由品牌渐变两笔构成（横 + 竖，圆角端点），透明底、无外框方块。
- 点击打开发布页（`pages/circle/publish`）。

### 6.2 实现位置

| 端 / 场景 | 实现 |
|---|---|
| H5 原生 tabBar | `pages.json` 的 `midButton` 移除 `iconPath` 与 `text`，仅保留尺寸；`App.vue` 全局样式用 `.uni-tabbar__mid::before/::after` 绘制渐变“+” |

| 微信小程序 | 不支持 midButton，保留第 5 个 tab 项作为发布入口（条件编译） |

## 七、评论区与语音评论设计（重点）

### 7.1 文字评论（现状）

- 评论抽屉：圆角顶部弹出，标题“评论 + 总数”，有关闭按钮、Esc 关闭、打开时焦点管理。
- 每条评论：头像、昵称、内容、时间、评论点赞（爱心 + 计数）。
- 底部输入栏：输入框 + 发送，支持回车发送；空态“暂无评论，快来抢沙发”。
- 时间显示：后端部分日期含异常分隔符（`??`），前端 `formatDate` 兜底清洗（连续问号替换为空格）。

### 7.2 语音评论（新增设计，对标抖音/微信“按住说话”）

#### 7.2.1 入口与模式

- 评论输入栏增加**麦克风按钮**，在“文字输入”与“按住说话”间切换。
- 语音模式下输入区显示“按住说话”；长按录音、松开发送、上滑取消。

#### 7.2.2 录音交互

1. 按下开始录音，调用 `uni.getRecorderManager()`，格式优先 `mp4`（H5/App）或 `aac`，采样率 8000/16000。
2. 单条时长限制：**最短 1 秒、最长 60 秒**；不足 1 秒提示“说话时间太短”；达到 60 秒自动停止并发送。
3. 录音中界面：显示录音时长倒计时、音量波形/音量条（`onFrameRecorded` 或音量回调），文案“松开发送，上滑取消”。
4. 上滑超过阈值进入取消态，文案变“松开手指，取消发送”，松手不发送。
5. 录音权限 `scope.record`：首次申请；被拒绝后引导至 `uni.openSetting` 开启，不允许静默失败。

#### 7.2.3 语音评论展示与播放

1. 语音评论在评论区以**语音条**呈现：播放图标 + 时长（秒）+ 波形/音量条（可选），点击播放、再次点击暂停。
2. 全局**互斥播放**：播放新语音时自动暂停上一条；离开页面/关闭抽屉停止所有语音。
3. 播放中语音条显示进度（图标切换为播放态/声波动画）。
4. 语音条宽度可按时长分级（最短与最长宽度区间），但不随超长无限拉伸。

#### 7.2.4 数据与依赖

- 评论数据需区分类型：文字评论 `type=1`、语音评论 `type=2`。
- 语音评论字段：`audioUrl`（音频文件地址）、`duration`（秒，整数）、可选 `wave`（波形数组）。
- 录音文件先通过现有上传能力上传到 MinIO（`192.168.20.133:9000`），再以返回地址提交评论。

#### 7.2.5 分阶段落地路径

| 阶段 | 内容 | 依赖 |
|---|---|---|
| P1（后端就绪前） | 前端录音 UI、RecorderManager 录音、权限处理、上传复用、语音条播放组件（可先用本地/演示数据验证） | 无后端强依赖，可先联调上传 |
| P2（后端改造） | 评论表/接口增加 `type/audioUrl/duration`，评论列表返回语音字段，点赞/分页复用 | 后端评论服务 + 数据库字段 |
| P3（联调上线） | 端到端：录音→上传→提交→列表展示→互斥播放，真机回归 | P1 + P2 |

> 说明：当前后端评论接口仅支持文字，语音评论**不在本次前端单独闭环**，按上表分阶段推进，避免上线无法发送的“假语音”。

## 八、数据结构与接口改动

### 8.1 评论对象（前端类型建议）

```ts
interface Comment {
  id: string;
  nickname: string;
  avatar: string;
  content: string;          // 文字内容（语音评论可为空）
  type: 1 | 2;              // 1=文字，2=语音
  audioUrl?: string;        // 语音地址（type=2）
  duration?: number;        // 语音时长（秒，type=2）
  createDate: string;
  likeCount: number;
  hasLiked: 0 | 1;
}
```

### 8.2 后端接口改动点（需求侧）

1. `POST /smallVideos/{id}/comments`：请求体支持 `type`、`audioUrl`、`duration`。
2. `GET /smallVideos/{id}/comments`：返回项包含 `type/audioUrl/duration`，分页与文字评论一致。
3. 评论表新增字段：`type`（默认 1）、`audio_url`、`duration`。
4. 修复日期格式化异常分隔符（当前返回 `2026年10月31??19:22`，应输出正常空格或标准 `yyyy-MM-dd HH:mm:ss`）。

## 九、技术约束与已验证结论

1. **uni-h5 不支持 `paused` 属性绑定**：Video 组件渲染原生 `<video>` 时仅绑定 `muted/loop/src/poster/autoplay`，不绑定 `paused`。因此 `:paused` 在 H5 是死代码，播放控制必须用命令式 `uni.createVideoContext(id).play()/pause()`。
2. 命令式调用需传入组件实例：`uni.createVideoContext(id, instance?.proxy)`，以正确定位页面作用域。
3. H5 自动播放必须先静音（muted），在用户手势后解除静音。
4. 计数统一走 `formatCount`，禁止页面重复实现。
5. 不控制系统音量，不放置音量/静音控件。

## 十、验收标准

| 编号 | 验收项 | 标准 |
|---|---|---|
| AC-1 | 自动播放 | 进入页面当前视频自动播放、循环，`paused=false`，画面持续推进 |
| AC-2 | 单击暂停/播放 | 点击后约 280ms 暂停并显示大播放键，再点恢复并解除静音，状态与原生一致 |
| AC-3 | 双击点赞 | 双击点赞、飞心、图标弹动，视频不暂停；数字按 `formatCount` 显示 |
| AC-4 | 数字格式化 | 1000 显示 `1000`，10000 显示 `1万`，12300 显示 `1.2万`，1 亿显示 `1亿`，无“10000万” |
| AC-5 | 滑动切换 | 真机上下滑动切换，旧视频暂停、新视频播放，接近末尾自动加载 |
| AC-6 | 评论/分享 | 评论抽屉、分享面板正常打开，数据真实，控制台无报错 |
| AC-7 | 发布“+” | 中间仅显示渐变“+”，无图标方块、无“发布”文字，点击进入发布页 |
| AC-8 | 语音评论 | 按 §7 分阶段：录音/取消/权限/语音条互斥播放闭环，后端字段就绪后端到端可用 |
| AC-9 | 类型与质量 | `vue-tsc --noEmit` 退出码 0，控制台无 error/warning |
