## 一、背景与目标

### 1.1 业务背景

配对成功后直接进入聊天页，导致：
- 80% 的配对以"你好"开头、以沉默结束
- 首条消息率仅 35%（行业头部 60-70%）
- 收到消息的用户中仅 30% 回复

**核心问题**：配对成功 ≠ 有社交建立。缺少"共同点感知"和"破冰话术帮助"。

### 1.2 数据目标

| 指标 | 当前 | 目标 |
|------|:---:|:---:|
| 配对成功 → 发送首条消息率 | 35% | 55%+ |
| 首条消息 → 回复率 | 30% | 45%+ |
| 匹配后 24h 内双向消息数 | 平均 8 条 | 平均 15+ 条 |

### 1.3 非目标

- 不在本版本实现 AI 自然语言生成（nlg）开场白
- 不做语音/视频通话联动破冰
- 不引入匹配后的时间限定（如"24h 内不聊即消失"）

## 二、共同标签（Common Tags）

### 2.1 功能描述

配对成功弹窗中，两人头像之间展示共同兴趣标签：
- 取双方兴趣标签的交集
- 最多展示 3 个（不够 3 个时展示"你们都是有趣的人"安慰文案）
- 按相关性排序（commonTagWeight = 双方权重乘积）

### 2.2 视觉效果

```
  ┌─────────┐   ┌─────────┐
  │  [我的头像] │   │ [TA的头像]  │
  │         │   │         │
  └─────────┘   └─────────┘
       ↑    ❤️    ↑
  
  ┌───────────────────────────────┐
  │  你们都喜欢： 📷摄影 · 🏕露营 · 🎵音乐  │  ← 最多3个
  └───────────────────────────────┘
```

### 2.3 数据逻辑

```
function computeCommonTags(tagsA: Interest[], tagsB: Interest[]): CommonTag[] {
  // 1. 取交集 tagKey
  const commonKeys = intersect(tagsA.map(t => t.tagKey), tagsB.map(t => t.tagKey));
  
  // 2. 计算联合权重 = weightA * weightB / 10
  const scored = commonKeys.map(key => ({
    tagKey: key,
    tagName: tagNameMap[key],
    combinedWeight: tagsA.find(t => t.tagKey === key).weight * tagsB.find(t => t.tagKey === key).weight / 10
  }));
  
  // 3. 权重排序 + 截断 3 个
  return scored.sort((a,b) => b.combinedWeight - a.combinedWeight).slice(0, 3);
}
```

## 三、智能开场白推荐（Ice Breaker）

### 3.1 功能描述

配对成功后，弹窗下方提供 3 条对话开场白推荐：
- 点击任一条 → 进入聊天页 + 自动填入输入框（用户可编辑后再发送）
- 推荐话术基于双方资料差异点（职业、学校、签名）、共同兴趣、流行语设计

### 3.2 推荐规则引擎（一期规则，非 AI）

```
rule_engine(p, q):
    // p = 当前用户资料，q = 配对对象资料
    
    candidates = []
    
    // 规则 1：基于共同兴趣
    commonInterests = intersect(p.interests, q.interests)
    if commonInterests.length > 0:
        pick = randomChoice(commonInterests)
        candidates.push(`看你首页说也喜欢${pick}，你平时都怎么玩的？`)
        candidates.push(`${pick}爱好者 +1！有机会一起呀`)
    
    // 规则 2：基于对方职业
    if q.occupation && q.occupation !== p.occupation:
        candidates.push(`对${q.occupation}很好奇，平时都做什么呀？`)
    
    // 规则 3：基于对方签名
    if q.signature:
        candidates.push(`"${q.signify}" —— 所以是真的吗？😄`)
    
    // 规则 4：通用开场白（兜底）
    candidates.push(`Hi~ 终于匹配到你了，聊聊？`)
    candidates.push(`哈哈哈匹配到了！我先打个招呼 👋`)
    
    return randomSample(candidates, 3)  // 不重复随机3条
```

## 四、接口设计

### 4.1 获取匹配卡片时含共同标签

- **接口**：`POST /match/cards`（改造现有接口）
- **响应新增字段**：

```json
{
  "code": 200,
  "data": {
    "cards": [
      {
        "userId": 1234,
        "nickname": "林妙可",
        "avatar": "https://...",
        "age": 24,
        "city": "北京",
        "interests": ["摄影","宠物","露营"],   // ← 新增：对方兴趣标签
        "signature": "喜欢摄影和猫"             // ← 新增：对方签名
      }
    ]
  }
}
```

### 4.2 配对发生时计算共同标签 + 推荐开场白

- **接口**：`POST /match/ice-breaker`（新增）
- **请求体**：`{"matchedUserId": 1234}`（当前登录用户从 token 取）
- **响应**：

```json
{
  "code": 200,
  "data": {
    "matchedUserId": 1234,
    "commonTags": ["摄影", "露营", "音乐"],
    "iceBreakers": [
      { "id": 1, "content": "看你首页说也喜欢摄影，你平时都怎么玩的？" },
      { "id": 2, "content": "有机会一起露营呀" },
      { "id": 3, "content": "终于匹配到同好了！聊聊？" }
    ],
    "expireAt": null  // null=不过期（一期不做限时）
  }
}
```

## 五、边界场景

| 场景 | 处理 |
|------|------|
| 双方无共同兴趣 | commonTags=[]，展示安慰文案："你们都是有趣的人，慢慢了解" |
| 一方无兴趣标签 | 该方不参与交集计算 |
| 两人无签名 + 同一职业 + 无共同兴趣 | 全部 3 条都用兜底通用文案 |
| 部分文字超长 | 前端截断 + "…"，最多 30 字符 |
| 接口超时 | 前端本地计算（前端已拿到 interests 数据）推荐降级版（仅职业+签名规则）|

## 六、测试验收

| # | Given | When | Then |
|---|-------|------|------|
| T1 | 匹配时双方有共同兴趣 | 配对成功弹窗 | 展示共同标签（最多 3 个）+ 3 条开场白 |

| T5 | 匹配成功 → 点击"我自己来" | 跳转聊天 | 输入框为空 |
| T6 | 连续 2 次匹配同一个人 | 第一次弹窗展示正常，第二次命中合并去重 | 正常显示 |
