# 心飞交友 C 端 App 用户体验优化文档

> 适用范围：`xfjy-app/`（uni-app H5 + 微信小程序）  
> 审计视角：**终端用户**（非开发者）  
> 生成日期：2026-11-01  
> 基线版本：v1.0（对应代码commit基线 nov-1）

---

## 〇、审计方法论

### 0.1 审计维度

| 维度 | 权重 | 审计要点 |
|---|:---:|---|
| **可用性** | 30% | 核心流程是否走得通？报错是否友好？ |
| **性能体感** | 25% | 首屏/切换是否流畅？加载等待是否过长？ |
| **交互反馈** | 20% | 操作是否有明确响应？手势是否符合心智模型？ |
| **信息架构** | 15% | 页面层级是否清晰？用户是否知道"我在哪、能去哪"？ |
| **情感化** | 10% | 动画/文案/空状态是否让人愉悦而非焦虑？ |

### 0.2 竞品参照系

以 **探探**（滑动匹配）、**Soul**（兴趣社交）、**陌陌**（LBS 社交）为对标。低于三者平均体验的项标记 ⚠️。

### 0.3 问题严重度定义

| 级别 | 定义 | 处置 |
|:---:|---|---|
| **P0-阻断** | 核心流程无法完成，用户流失 | 立即修复 |
| **P1-严重** | 体验显著折损，用户困惑/抱怨 | 当周修复 |
| **P2-体验** | 能用但不爽，可被感知的瑕疵 | 排期修复 |
| **P3-打磨** | 锦上添花的优化 | 有资源时修复 |

## 一、新用户首次体验（FTUE）

### 1.1 登录页（`pages/auth/login.vue`）

#### 当前体验流程

```
进入 App → 冷启动兜底（无 token 跳登录）→ 品牌区 + 验证码登录
                                         ↓
                              勾选协议 → 60s 倒计时 → 登录成功 → switchTab("match/index")
```

#### 做得好 ✅

| 项 | 说明 |
|---|---|
| 倒计时自动清除 | `onUnmounted` 清理 `countdownTimer`，避免离页后定时器泄漏 |
| 手机号实时校验 | `PHONE_REGEX = /^1[3-9]\d{9}$/` 输入即反馈 |
| 链接跳转协议详情 | `openAgreement('user' \| 'privacy')` 跳转协议查看页 |
| 无障碍 | `aria-labelledby` 关联 label 与 input，读屏可识别 |
| 加载态 | 按钮显示"登录中..." + 禁用双击 |

#### 体验痛点（按严重度排序）

| # | 问题 | 级别 | 建议 |
|---|------|:---:|---|
| FTUE-1 | 发送验证码失败时**仅有 toast"验证码已发送"或什么都不显示**——用户不知道是"已发出"还是"发送失败" | P1 | catch 分支增加失败 toast（网络错误 / 号码限制等），区分"已发送"与"发送失败"两种状态 |
| FTUE-2 | 登录按钮文案 **"登录 / 注册"** 对用户不透明——手机号首次登录自动注册，用户不知道也不需要知道；字眼让人紧张（"注册要填很多资料吗？"） | P2 | 改为 **"登录"** 或 **"手机号一键登录"**，不主动提"注册" |
| FTUE-3 | **图片验证码缺失**：当前流程仅短信验证码，无图形验证。刷票/攻击风险高且真实平台均有图形滑块 | P2 | 接入图形滑块（如极验/腾讯防水墙）或小程序原生 `code-button` |
| FTUE-4 | 未登录用户**无法浏览任何 tab 页**——tabBar 首页即为 match，必须登录才能看内容 | P2 | 允许未登录浏览 "match"（仅展示，互动需登录），降低准入门槛；探探/Soul 均允许先浏览 |
| FTUE-5 | 协议勾选无视觉反馈动画——`agree` 状态切换仅靠 ✓ 字符显隐 | P3 | 增加 checkbox 弹跳动画 (`btn-feedback` 复用) |

### 1.2 完善资料引导页（`pages/guide/guide.vue`）

#### 当前体验流程

```
登录成功 → 资料完整度 < 阈值 → 强制跳转 guide → 头像 / 昵称 / 性别 / 生日 / 城市 / 学历
                                          ↓
                                    滚动到底部 → "保存并继续" → tab("match/index")
```

#### 做得好 ✅

| 项 | 说明 |
|---|---|
| 进度条 | `role="progressbar"` + `aria-valuenow`，读屏告知完整度百分比 |
| 分段保存 | 无需一次填完（页面支持暂存），降低心理压力 |
| 性别单选 | `a11y-radio-group` 语义正确，键盘可操作 |
| 生日 picker | 原生 `picker mode="date"` 体验统一 |

#### 体验痛点

| # | 问题 | 级别 | 建议 |
|---|------|:---:|---|
| FTUE-6 | **完整度算法不透明**——用户不知道"还差多少才算 100%"，只能靠猜 | P2 | 进度条旁加一行提示（例："上传头像+30分，填写学历+15分"），或显示"还差 X 项" |
| FTUE-7 | **保存按钮不在可视区**：表单较长（6~8 个字段），用户必须滚动到底部才能保存 | P1 | 底部固定悬浮保存按钮（`position: fixed; bottom: calc(20rpx + env(safe-area-inset-bottom))`），表单区 flex: 1 自适应 |
| FTUE-8 | 上传头像**失败无反馈**：`uni.chooseImage` → `uni.uploadFile` 失败仅静默 | P1 | 上传失败时 toast + 错误原因（格式不支持 / 文件过大）；显示上传中 Loading |
| FTUE-9 | 资料完整度 0% 时**进入引导页无任何欢迎语**——用户不知道为什么要填这些 | P2 | 顶部加欢迎语："完善资料，让更多人发现你 ✨"，配合品牌色渐变 |
| FTUE-10 | 离开引导页无二次确认——用户若误触返回，已填内容丢失 | P3 | 返回时若有未保存修改，弹窗"资料尚未保存，确定离开吗？" |

## 二、核心功能体验

### 2.1 匹配页（`pages/match/index.vue`）

#### 当前体验流程

```
进入 → 加载推荐列表 → 卡片全屏堆叠（底部 5 键操作栏）
  ↓                          ↓
左滑：不喜欢          5 键：回看 / 不喜欢 / 超级喜欢 / 心动 / 曝光提升
右滑：喜欢 → 双向匹配 → 弹窗"It's a Match!"
```

#### 做得好 ✅

| 项 | 说明 |
|---|---|
| 骨架屏 | `skeleton variant="match"` 首屏加载占位 |
| 空状态 | `empty-state title="暂无推荐" desc="稍后再来看看，缘分不期而至"`——文案友好 |
| 卡片堆叠 | 多张卡片 Z 轴层叠 + 缩放，立体感好 |
| 滑动视觉反馈 | "喜欢/不喜欢"hint 随手势不透明度变化 |
| 匹配成功弹窗 | 心跳动画 + 渐变文字 + 明确 CTA（"发消息"/"继续逛逛"）|
| 触觉反馈 | 高仿真手机触发 `selector` 振动（若 API 支持）|
| 九宫格标签 | `card.tags.slice(0, MAX_TAG_COUNT)` 限制展示，避免溢出 |

#### 体验痛点

| # | 问题 | 级别 | 建议 |
|---|------|:---:|---|
| MATCH-1 | **"曝光提升"按钮无引导**——用户不知道这是干嘛的（是 VIP 权限？是广告？）| P1 | 首次点击时底部弹出 tooltip："提升曝光让更多人看到你（VIP 特权）"；非 VIP 引导开通 |
| MATCH-2 | **"回看"功能无次数限制提示**——用户不知道每天能回看几次（VIP 无限？普通用户 1 次/天？）| P1 | 回看按钮旁显示剩余次数（"剩余 1 次"）；次数用完 toast "今日回看已用完，明日再来" |
| MATCH-3 | **卡片信息密度太低**——仅显示头像、昵称、年龄、标签、缘分值，缺乏"最近在线" / "距离" | P2 | 增加最近在线状态（绿点：在线 / 灰点：3天内）和距离标签（"3km"），提升决策质量 |
| MATCH-4 | **滑动顿挫**：快速连滑时手势事件竞争，会出现卡片"跳一下" | P2 | 滑动过程中禁用新 touchstart 或加 debounce |
| MATCH-5 | **匹配成功后 IM 连通性无校验**——弹窗显示"发消息"但 IM 可能并未连通（登录失败是静默的）| P0 | 点击"发消息"前调用 `isIMLoggedIn()`，未连通时 toast"消息服务连接中，请稍后再试"；或者在弹窗 hook 时阻塞直到 IM ready |

### 2.2 聊天会话页（`pages/chat/chat.vue`）

#### 当前体验流程

```
通知中心列表 → 点进会话 → 消息气泡列表（左收右发）+ 时间分隔
            → 底部输入栏：文字 / 表情 / 图片 / 语音 / 更多（位置/名片）
```

#### 做得好 ✅

| 项 | 说明 |
|---|---|
| 消息类型丰富 | text / image / voice / location / card 五种气泡，场景覆盖全 |
| 时间分隔线 | 超过阈值自动插入时间（"昨天 14:30"），符合心智模型 |
| 发送状态三态 | sending（转圈）/ sent（无图标）/ failed（感叹号+点击重发）|
| 语音播放 | 播放中声波动画，同一时刻只播一条 |
| 读屏语义 | 头像 aria-label / 语音气泡 label="播放语音，X 秒" |
| 自动滚动 | `scroll-into-view` 发消息后自动滚到底 |

#### 体验痛点

| # | 问题 | 级别 | 建议 |
|---|------|:---:|---|
| CHAT-1 | **🔴 IM 登录是坏的**——`App.vue onShow` 调用 `loginIM` 直连 WuKongIM，但 token 派生方式 `xfjy_${uid}_im_token` **是否真正在 WuKongIM 服务端注册未验证** | P0 | 必须在 WuKongIM 端创建与 token 对应的用户，否则所有 IM 功能不可用；当前最核心的体验阻断 |
| CHAT-2 | 发送图片前无压缩——原图上传，30MB 限制，大图发送慢 | P1 | 发送前 canvas 压缩（MAX 1080p / quality 0.7），上传前显示压缩进度 |
| CHAT-3 | **无"对方正在输入"状态**——用户不知道对方是否在回复，缺少即时感 | P2 | WuKongIM 支持 typing indicator；服务端需透传 typing 事件，前端监听后底部显示对方昵称+"正在输入…" |
| CHAT-4 | **无"消息已读"标识**——发送后无法知道对方是否看到 | P2 | WuKongIM 支持 read receipt；双蓝勾 UI（单灰勾=发送成功 / 双灰勾=对方收到 / 双蓝勾=已读）|
| CHAT-5 | 聊天页无**网络状态提示**——断网发送失败只显示红点，但断网环境不知道是"消息没发出去"还是"网络断了" | P1 | 顶部增加连接状态 indicator（绿色圆点=已连 / 灰色=断开）；断网时 disable 输入区 |
| CHAT-6 | **消息气泡长按菜单缺失**——无法复制/撤回/删除消息 | P2 | 长按气泡弹出 `uni.showActionSheet`（复制 / 撤回(2min内) / 删除）|
| CHAT-7 | 表情面板——当前 emoji 直接写死在模板里，缺少 emoji 分组/最近使用 | P2 | 接入 emoji 分组（最近 / 笑脸 / 动物 / 礼物...），`uni.setStorage` 记录最近使用 |

### 2.3 圈子 Feed（`pages/circle/index.vue`）

#### 当前体验流程

```
进入 → 加载 feed 列表 → scroll-view 信息流
      → 双击心形点赞 → 评论 → 分享
      → 底部悬浮"+"按钮 → 发布页
```

#### 做得好 ✅

| 项 | 说明 |
|---|---|
| feed 分页 | 上拉加载更多，分页数据由后端PageSize 控制 |
| 图片懒加载 | `lazy-load` + `mode="aspectFill"`，大图不白屏 |
| 双击点赞 | 心形飘升动画（`heart-beat` class），符合抖音式体验 |
| 发布入口 | 底部悬浮 "+" 按钮，tabBar 中间键（自定义 CSS） |
| 骨架屏 | `variant="feed"` 类型卡片 |

#### 体验痛点

| # | 问题 | 级别 | 建议 |
|---|------|:---:|---|
| CIRCLE-1 | **🔴 性能风险：全量 DOM 渲染**——`v-for` 渲染所有 feed 卡片，> 50 条后滚动掉帧明显 | P1 | 引入 `uni-recycle-list` 虚拟列表；或改为触底分页 + 离屏节点销毁（仅保留视口上下各 5 条外 + 内）|
| CIRCLE-2 | 无下拉刷新——旧版本没有 `onPullDownRefresh` | P2 | 实现下拉刷新：顶部显示 loading icon + "松开刷新" 文案 |
| CIRCLE-3 | **加载失败无提示**——网络异常时 feed 静默白屏 | P1 | 请求失败时顶部显示"加载失败，点击重试"条（复用 vip 页 load-error 模式）|
| CIRCLE-4 | 发布动态成功后无反馈——"发布"按钮点击后用户不知道是否成功（需等跳转） | P1 | 发布成功后 toast"发布成功 ✨" + 自动跳转圈子详情 |
| CIRCLE-5 | 双击点赞无触觉反馈——物理反馈缺失 | P3 | 双击点赞时触发短振动（`uni.vibrateShort`），增强确认感 |
| CIRCLE-6 | feed 卡片无加载优先级区分——用户滚动快时图片加载顺序混乱 | P2 | 当前视口图片优先加载，离屏图片延迟 500ms 或用 IntersectionObserver 触发加载 |

| VIDEO-5 | 评论区空状态无引导——空评论显示空白 | P3 | 空评论展示"尚无评论，成为第一个发言的人 💬" |

## 三、付费体验

### 3.1 VIP 购买页（`pages/mine/vip.vue`）

#### 做得好 ✅

| 项 | 说明 |
|---|---|
| 状态展示 | 已购 VIP 卡片显示等级 + 到期时间 |

## 四、全局体验

### 4.1 网络状态感知

| 项 | 现状 | 建议 |
|---|---|---|
| 断网提示 | ❌ 无 | 顶部黄色提示条 + 阻止交互蒙层 |
| 弱网环境 | ❌ 无感知 | 请求超时 10s 后显示"网络环境较差" toast |
| API 错误信息 | 后端 message 字段透传，但缺乏兜底文案 | 全局兜底："出了点小问题，请稍后重试" + 错误码（便于反馈）|

### 4.2 错误信息友好度

| 场景 | 当前文案 | 评价 | 建议 |
|---|---|:---:|---|
| 登录失败 | "登录失败" + 后端 message | ⚠️ | 增加失败原因引导（"账号不存在，请先注册" / "验证码已过期"）|
| 网络异常 | 无 | ❌ | 增加"网络连接失败，请检查后重试"+ 重试按钮 |
| IM 失败 | 无（静默） | ❌ | 连接失败时顶部显示"消息服务断连，正在重连…"+ 重连失败 toast |
| 接口 500 | 透传后端错误 | ⚠️ | 生产环境统一为"服务器繁忙，请稍后"，不暴露堆栈 |

### 4.3 操作反馈一致性

| 类型 | 用法 | 问题 |
|---|---|---|
| 成功 | `uni.showToast({ title: "xxx成功", icon: "success" })` | ✅ 一致 |
| 失败 | `uni.showToast({ title: "xxx失败", icon: "none" })` | ⚠️ 部分场景无失败提示 |
| 加载中 | 按钮 loading 态 + disable | ✅ 一致 |
| 不可点击 | `:disabled` + CSS `.disabled` class | ⚠️ 部分场景 disabled 态无视觉区分度 |

**建议**：统一封装 `ux.ts`：
```ts
ux.success(msg)   → toast + success icon + 2s 自动消失
ux.fail(msg)      → toast + none icon + 3s + 红色左边图标
ux.loading(msg)   → showLoading（需手动 hide）
ux.networkError() → 全屏网络错误页 + 重试按钮
```

### 4.4 首屏加载速度

| 阶段 | 当前耗时估算 | 问题 | 建议 |
|---|---|:---:|---|
| HTML 加载 | ~300ms | 无骨架屏 | index.html 内嵌骨架 SVG |
| JS 解析执行 | ~800ms | vendor chunk 未拆分 | 已三分包 ✅ |
| 首屏接口请求 | ~500ms | 串行请求 | 并行 `Promise.all` [checkLogin, loadFeed] |
| 首屏渲染 | ~200ms | 大组件未懒加载 | 仅渲染首屏 tab 页；其他 tab 进入时再 init |
