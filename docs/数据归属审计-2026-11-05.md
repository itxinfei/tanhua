# 数据归属审计（AGENTS.md §3 按表写入方核查）— 2026-11-05

依据 AGENTS.md §3「一张表/一个集合只能有一个写入方」「BFF 禁止新增持久化表」「禁止在 BFF 为领域服务补写业务表」执行。

## 一、审计方法
1. 枚举全仓 @TableName（MySQL）与 @Document(collection=...)（MongoDB）实体，定位表/集合真源。
2. 枚举各模块 BaseMapper / MongoTemplate 写入点，确认唯一写入方。
3. 重点核查 §3 强制校验命令及 BFF（xfjy-server）是否越权写入领域表。

## 四、发现的违规与问题

### 违规 1（§3 红线）：MySQL tb_user 双写 — 已修复（2026-11-05）
- 现象：xfjy-sso 与 xfjy-server（BFF）均直写 tb_user。
- 证据：
  - sso：xfjy-sso/.../UserService.java:138 insert、:217 update；UserPurgeTask.java:71 update。
  - BFF：xfjy-server/.../AdminUserService.java:335/347/357 userMapper.updateById/update；UsersService.java:444 userMapper.updateById（注销清理设备绑定）。
- 违反：AGENTS.md §3「一张表只能有一个写入方」「禁止在 BFF 为领域服务补写业务表」。
- 根因：xfjy-api 中无供 BFF 委托用户写操作的 UserApi（仅有到 match-service 的 RecommendUserApi），BFF 被迫直写。
- 建议修复（需设计决策，非本次审计范围）：
  1. 在 sso 暴露用户管理 API（更新资料/冻结解冻/注销），于 xfjy-api 新增 UserApi；
  2. BFF AdminUserService / UsersService 改为调用 userApi，移除 BFF 的 UserMapper 与 User 实体；
  3. 一致性按 §3「本地事务 + 消息/补偿」处理，禁止分布式事务。

### 问题 2（校验命令误报）：§3 强制校验命令会命中注释
- 现象：rg -n "tb_pay_order|tb_vip_package" xfjy-server/src/main/java 命中 AdminVipService.java:15 的 Javadoc 注释（套餐（tb_vip_package）支持完整 CRUD），实际 BFF 不持有支付表 Mapper（经 PayApi 委托 pay-service）。
- 已处理：将 §3 校验命令改为 rg -n "tb_pay_order|tb_vip_package" xfjy-server/src/main/java | rg -v "//|\*" -> 0（排除注释），保持 CI 校验准确。

## 五、结论
- MongoDB 集合与绝大多数 MySQL 表写入方单一，符合 §3。
- 唯一实质违规为 tb_user 被 BFF 与 sso 双写，需补 UserApi 并收敛写入方至 sso 后修复。
- 其余 BFF 表均为自有管理表，无需变更。


## 六、修复状态（2026-11-05 补充）

违规 1 已修复，方案如下：

- **sso 新增内部用户管理能力**：UserService 增加 freezeUser / unfreezeUser / resetPassword / deactivateUser（直写 tb_user，sso 为唯一写入方）；UserController 暴露 /internal/user/{freeze,unfreeze,reset-password,deactivate}（路径不含 /user 前缀，网关不路由，仅 xfjy-server 经内部网络可达）。
- **xfjy-api 新增 UserApi**：与 PayApi 同风格的 @HttpExchange 契约。
- **xfjy-server 改为委托**：HttpServiceProxyConfig 增加 ssoServiceProxyFactory + userApi Bean（注入 ln 内部头）；AdminUserService.freezeUser/unfreezeUser/resetPassword 与 UsersService.logoff 改为调用 userApi，移除 BFF 对 tb_user 的全部 userMapper.update/insert/delete 写点。
- **安全说明（已加固，2026-11-05 补充）**：sso 现已依赖 xfjy-api，由 InternalTokenAutoConfiguration 激活 XInternalTokenInterceptor，对 /** 校验 X-Internal-Token；BFF 与网关均注入 X-Internal-Token（头名一致，全仓不存在 ln 与 X-Internal-Token 不一致问题），token 值经 internal.auth.tokens 在各服务统一。/internal/user/** 内部端点仅 BFF 经内部网络调用、携合法 X-Internal-Token 通过校验；网关未路由该路径形成双重隔离。注：此前记录的「ln 与 X-Internal-Token 不一致」经复核不成立——BFF 注入头实际即 X-Internal-Token。
- **验证**：rg userMapper.(update|updateById|insert|delete) xfjy-server/src/main/java -> 0 命中；mvn -o -DskipTests compile -pl xfjy-sso,xfjy-server -am EXIT=0。
