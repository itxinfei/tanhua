## 一、产品概述

### 1.1 产品定位
心飞交友是一款面向年轻群体的**陌生人社交平台**（类似陌陌/探探），通过 LBS 地理位置、智能推荐算法和实时音视频互动，帮助用户发现附近有趣的人，建立社交连接。

### 1.2 目标用户
| 维度 | 描述 |
|------|------|
| 年龄 | 18-35 岁 |
| 场景 | 想拓展社交圈、结识附近新朋友的年轻用户 |
| 特征 | 移动端为主，注重颜值与兴趣匹配 |

### 1.3 核心价值
- **发现**：基于地理位置 + 协同过滤算法，精准推荐附近的人
- **互动**：圈子动态、小视频、即时聊天，多维度建立连接
- **匹配**：探花卡片左右滑动 + 陌生人问题，增加破冰趣味性
- **增值**：VIP 会员体系，付费解锁更多社交特权

## 四、功能需求

### 4.1 用户账户模块

#### FR-AUTH-01 注册/登录（SSO 服务）
- **描述**：用户通过手机号 + 短信验证码完成注册或登录
- **规则**：
  - 新手机号自动注册并创建 `tb_user` 记录
  - 登录成功由 Sa-Token 签发 Token（`StpUtil.login()`），Token 存 Redis 共享会话，后续请求通过 Header 携带
  - Token 校验由各服务 `SaInterceptor` 统一拦截（`@SaIgnore` 注解标记免登录接口），所有服务共享同一 Redis 即可校验，无需回调 SSO

#### FR-USER-01 用户资料读取
- **接口**：`GET /users?userID=&huanxinID=`
- **描述**：查询用户资料（支持按用户 ID 或环信 ID 查询）
- **字段**：昵称、头像、性别、生日、城市、学历、婚姻状态、收入、行业、个性签名、照片列表

#### FR-USER-02 用户资料更新
- **接口**：`PUT /users`
- **描述**：更新当前登录用户资料，更新后清除用户缓存（`@CacheEvict`）

#### FR-USER-03 关系统计
- **接口**：`GET /users/counts`
- **描述**：统计互相喜欢数、喜欢数（我关注）、粉丝数

#### FR-USER-04 关系列表
- **接口**：`GET /users/friends/{type}?page=&pagesize=&nickname=`
- **type 定义**：1=互相关注，2=我关注，3=粉丝，4=谁看过我
- **支持**：按昵称模糊搜索、分页

#### FR-USER-05 取消喜欢
- **接口**：`DELETE /users/like/{uid}`

#### FR-USER-06 关注粉丝
- **接口**：`POST /users/fans/{uid}`

#### FR-USER-07 注销账号
- **接口**：`POST /users/logoff`（body: code）
- **描述**：用户注销账号（软删除），需校验短信验证码防止误操作
- **规则**：
  - 验证码校验：Redis 缓存验证码 或 开发万能验证码（DEV_MASTER_CODE）
  - 软删除：`tb_user.status = DELETED`，数据保留 30 天后由定时任务清理
  - 立即踢下线：Sa-Token 按 userId 注销所有会话（`StpUtil.logout()`）
  - 已注销账号登录拦截：sso 登录/token 校验拦截 DELETED 状态用户
- **验证**（2026-10-25 实测）：注销 200 → 旧 token 401 → 重新登录 401 → DB status=DELETED

#### FR-USER-08 用户举报
- **接口**：`POST /users/report`
- **参数**：targetUserId（被举报用户ID）、targetType（USER/POST/COMMENT/MESSAGE）、targetId（举报对象ID）、reason（举报原因）、description（详细描述）、evidence（证据截图URL，逗号分隔）
- **描述**：用户提交举报，写入 `tb_report`（status=PENDING），由管理端处理
- **规则**：
  - 不可举报自己（400）
  - reason 必填（400）
  - 举报记录供管理端举报处理模块使用
- **验证**（2026-10-25 实测）：200，中文入库 HEX 校验通过（UTF-8 正确）

### 4.10 推荐引擎模块

#### FR-ENGINE-01 实时评分收集（xfjy-recommend）
- **输入**：RocketMQ 消息（topic: `xfjy-quanzi` / `xfjy-video`）
- **评分规则（圈子）**：

| 行为类型 | type | 评分 |
|----------|------|------|
| 发布动态 | 1 | 1~3 分（按文字长度）+ 图片数量加分 |
| 浏览动态 | 2 | +1 |
| 点赞 | 3 | +5 |
| 喜欢 | 4 | +8 |
| 评论 | 5 | +10 |
| 取消点赞 | 6 | -5 |
| 取消喜欢 | 7 | -8 |

- **存储**：按日分集合写入 MongoDB（`recommend_quanzi_yyyyMMdd` / `recommend_video_yyyyMMdd`）

#### FR-ENGINE-02 推荐排序（xfjy-server 混合评分，Spark ALS 已退役）
- **算法**：混合评分 = ALS 分数归一化×w1 + Haversine 距离衰减×w2 + 画像相似度（tags Jaccard+年龄差+同城）×w3，数据缺失维度自动降级，权重 YML 可配
- **数据源**：MongoDB `recommend_user`（ALS 历史产出，5060 条）+ ES 位置 + MySQL 画像
- **产出**：推荐列表/探花卡片按混合缘分值（0~100）降序排序
- **演进**：阶段 2 双塔模型（数据积累达标后渐进启用，行为>1000 条/用户>50）

#### FR-ENGINE-03 ID 生成（dubbo-service IdService）
- **方式**：Redis 自增 + Hashids 混淆
- **键**：`XFJY_HASH_ID_` / `XFJY_ID_`
- **用途**：生成动态、视频等业务 ID

### 4.11 VIP 会员/支付模块（xfjy-pay-service）

#### FR-PAY-01 VIP 套餐查询
- **接口**：`GET /users/vip/packages`
- **描述**：查询上架的 VIP 套餐列表（月卡/季卡/年卡）
- **数据**：`tb_vip_package`（name/level/price/original_price/duration_days/description/status/sort）

#### FR-PAY-02 创建支付订单
- **接口**：`POST /users/vip/order`（body: packageId）
- **描述**：当前登录用户为指定套餐创建支付订单
- **规则**：
  - 订单号生成：`VIP` + yyyyMMdd + 6 位序列（Redis 自增）
  - 订单状态：PENDING（待支付）
  - 过期时间：下单后 30 分钟
- **数据**：`tb_pay_order`（order_no 唯一约束）

#### FR-PAY-03 模拟支付确认（沙箱）
- **接口**：`POST /users/vip/pay/confirm`（body: orderNo）
- **描述**：沙箱支付回调入口，确认订单支付完成
- **规则**：
  - 校验订单存在、非本人、状态允许、未过期
  - 订单状态 → PAID，记录 paid_time
  - 开通/续费 VIP：`tb_user_vip` 写入/更新
  - **续费顺延**：已有 VIP 未到期时，新有效期 = 旧到期时间 + 套餐天数（非从当前时间起算）
  - **等级保留**：续费低等级套餐时保留已达到的最高等级
- **生产切换**：替换为真实支付网关（支付宝/微信）回调即可，沙箱逻辑仅确认入口
- **验证**（2026-10-25 实测）：两单月卡 → expire 11-24 顺延至 12-24 ✅

#### FR-PAY-04 VIP 状态查询
- **接口**：`GET /users/vip/status`
- **描述**：查询当前登录用户 VIP 状态（level/expire_time）
- **数据**：`tb_user_vip`（user_id 唯一约束）

#### FR-PAY-05 订单详情查询
- **接口**：`GET /users/vip/order/{orderNo}`
- **描述**：根据订单号查询订单详情

## 五、非功能需求

### 5.1 性能
| 指标 | 要求 |
|------|------|
| 接口响应时间 | P95 < 500ms（缓存命中 < 50ms） |
| 推荐列表加载 | 首屏 < 1s |
| 消息消费延迟 | RocketMQ 消费延迟 < 2s |
| 并发能力 | 单服务支持 1000 QPS |

### 5.2 缓存策略
| 缓存 | TTL | 失效策略 |
|------|-----|----------|
| 用户资料（userInfo） | 1 小时 | 资料更新时 @CacheEvict 主动失效 |
| 公告列表（announcement） | 1 小时 | 按分页键缓存，自然过期 |

### 5.3 安全
- Sa-Token 认证（Redis 共享会话），各服务 SaInterceptor 统一拦截
- 环信密码 MD5 加盐（`userId + "_xfjy"`）
- OSS 上传走服务端签名
- 敏感配置（AK/SK）独立 properties 文件，不入库

### 5.4 可靠性
- RocketMQ 消息持久化，消费者异常记录日志不丢失（at-least-once）
- MongoDB 副本集部署
- ES 位置数据可重建（从 MongoDB UserLocation 同步）

### 5.5 可扩展性
- 服务间 HTTP Service 接口解耦，可独立扩缩容
- 推荐评分按日分集合，避免单集合膨胀
- 混合评分权重可通过配置热调，无需重启
