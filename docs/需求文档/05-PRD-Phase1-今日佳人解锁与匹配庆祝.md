## 一、背景与目标

### 1.1 业务背景

当前"今日佳人"仅作为每日 1 次推荐的静态展示，缺少**稀缺感**和**期待感**：
- 用户刷新即得，无参与感
- 滑完 50 张卡片后无目标感，流失概率高达 60%
- 匹配成功仅一个弹窗，情感化不足

### 1.2 数据目标

| 指标 | 当前 | 目标 |
|------|:---:|:---:|
| 滑动深度（人均 50 次用完率）| 60%用完 → 40%中途离开 | 90%用完 |
| 单日滑动次数（活跃用户）| 平均 35 次 | 平均 48 次 |
| 匹配成功→进入聊天率 | 40% | 60%+ |
| 匹配成功→发送首条消息率 | 35% | 50%+ |

### 1.3 非目标

- 不在本版本实现"重新看一次已滑过的人"付费功能
- 不引入匹配后即时视频通话（后续版本迭代）
- 不做复杂的多阶段解锁（如"看 3 个广告解锁"）

## 二、功能描述

### 2.1 今日佳人解锁进度条

#### 组件位置

`pages/match/index.vue` 顶部

#### 视觉设计

```
┌──────────────────────────────────────────┐
│  🔮 再滑动 4 次解锁今日佳人               │
│  [████████████████████░░░░░░] 6/10          │
└──────────────────────────────────────────┘
```

- 进度条位于滑动卡片下方，TabBar 上方
- 实时更新（每滑动一张更新进度）
- 解锁时进度条满 → 全屏庆祝动画 → 佳人展示

#### 交互逻辑

```
当前滑动次数 N = totalSwipes || 0
已用次数 U = usedSwipes || 0
解锁阈值 T = unlockThreshold (Nacos 配置，默认 10)

progress = min((U / T) * 100, 100)
remaining = max(T - U, 0)

解锁时：
  - POST /match/unlock-best 记录解锁事件（⚠ 待实现：`xfjy-server` 当前无该路由）
  - 触发今日佳人全屏展示（替代原弹窗）
  - 进度条清空重置（下一天重新计数）
```

#### 规则细节

| 规则 | 说明 |
|------|------|
| 跨日重置 | 每天 00:00 重置解锁进度（服务端控制）|
| 滑动回退 | 左滑不计数，右滑 +1 计数 |
| 超级喜欢 | 超级喜欢不计入解锁计数（奖励用户）|
| 断网 | 本地记录已滑次数，网络恢复后批量上报 |

## 三、接口设计

### 3.1 获取今日解锁进度

- **接口**：`GET /match/progress`
- **⚠ 实现状态：待实现**。`xfjy-server` 现仅有 `GET /todayBest` 等接口，无 `/match/progress` 路由；
  本文档为接口规划口径，落地前需先在 `TodayBestController` 或新增 `MatchController` 注册该路径。
- **描述**：获取用户当日滑动进度和解锁状态
- **响应**：

```json
{
  "code": 200,
  "data": {
    "swipeCount": 6,
    "swipeLimit": 50,
    "unlockThreshold": 10,
    "unlocked": false,
    "remaining": 4,
    "progress": 0.6
  }
}
```

### 3.2 触发解锁今日佳人

- **接口**：`POST /match/unlock-best`
- **⚠ 实现状态：待实现**（同 3.1，当前无该路由；本节含服务端防作弊校验要求，接入时一并实现）。
- **描述**：用户滑动次数达到阈值时调用，触发今日佳人展示
- **请求体**：`{"swipeCount": 10}`
- **⚠ 服务端校验**：接口服务端必须再验一次当日有效 swipe 数（防作弊：前端断网本地计数后上报数不足时拒绝解锁）。校验逻辑：`if (serverSwipeCount < unlockThreshold) throw BusinessException("滑动次数不足")`
- **响应**：返回今日佳人卡片信息（复用 `Card` 类型）

```json
{
  "code": 200,
  "data": {
    "todayBest": { "id": 1234, "nickname": "林妙可", "avatar": "...", "age": 24, "occupation": "设计师", "signature": "喜欢摄影和猫", "commonTags": ["摄影", "宠物"] }
  }
}
```

### 3.3 接口错误响应

| 接口 | HTTP | 错误码 | 场景 | 后端返回 message |
|------|:---:|:---:|------|----------------|
| `GET /match/progress` | 401 | `AUTH_FAILED` | Token 过期或未登录 | "请先登录" |
| `POST /match/unlock-best` | 400 | `INVALID_PARAM` | swipeCount 为负或缺失 | "参数不合法" |
| `POST /match/unlock-best` | 402 | `SWIPES_NOT_ENOUGH` | 服务端校验滑动数不足（与 `SwipeLimitException` 口径一致） | "滑动次数不足，无法解锁" |
| `POST /match/unlock-best` | 409 | `ALREADY_UNLOCKED` | 当日已解锁（UNIQUE 冲突）| "今日已解锁，明日再来" |
| `POST /match/unlock-best` | 503 | `SERVICE_DOWN` | 推荐服务不可用 | "服务暂不可用，请稍后重试" |

> **能力对齐（2026-11-03）**：`xfjy-server` 的 `GlobalExceptionHandler` 目前只映射
> `400`（BusinessException/参数校验）、`402`（滑动/权益耗尽）、`404`、`500`；上表的
> `401`、`403`、`409`、`503` **尚无统一映射**，需在实现 `/match/*` 时一并补齐（401 由拦截器、
> 403 由 `@RequireRole`/内部 token、409 需新增 `DataIntegrityViolationException` 映射、
> 503 需新增降级映射），否则实际会退化为 400/500。

> 前端统一处理 401 → 跳转登录页；402 → 跳付费墙；403/409 → toast；503 → 降级展示缓存卡片并后台重试。

## 四、边界场景

| 场景 | 处理 |
|------|------|
| 用户滑动断网 | 本地记录滑动次数，网络恢复后批量同步（不上报错误）|
| 今日佳人已展示再次达到阈值 | 当日不重复展示（UNIQUE 约束保证），toast"今日已解锁，明日再来" |
| 解锁时接口失败 | 展示降级：直接展示缓存卡片 + 重试 3 次 |
| 用户切换账号 | 清空本地进度，从服务端重新拉取 |
