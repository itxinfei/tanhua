## 一、背景与目标

### 1.1 业务背景

当前评论功能仅支持纯文本、平铺展示，缺少：
- 表情回复（用户只能用文字表达情绪）
- @ 功能（无法在评论中提及他人）
- 回复某条评论（只能全量评论，无法形成对话感）

### 1.2 数据目标

| 指标 | 当前 | 目标 |
|------|:---:|:---:|
| 人均评论字数 | 8 字 | 15+ 字 |
| 评论回复深度（二级评论率）| 0% | 20%+ |
| 评论表情使用率 | 0% | 40%+ |

### 2.3 @ 提及功能

**输入触发**：
1. 输入 `@` → 弹出选择面板
2. 面板展示：最近互动过的用户（最多 8 人）+ 帖子作者 + 二级评论作者
3. 可继续输入关键词实时搜索
4. 点击选中 → 插入 `@昵称 ` 到输入框
5. 发送时，被 @ 的用户收到推送提醒「XXX 在评论中提到了你」

**展示规则**：
- `@昵称` 在评论中以**蓝色高亮**显示
- 点击 `@昵称` 跳转到该用户主页（复用 detail.vue）

### 2.4 表情面板

- 20 个常用 emoji（😀😁😂🤣😍😘😎😢😡👍❤️😴🤔🥵❄️🎉🍻🔥💯）
- 面板底部固定，点击即插入光标位置
- 不做自定义表情商城（二期迭代）

## 三、数据模型变更

> ⚠ **存储引擎对齐**：评论数据存于 MongoDB `quanzi_comment` 集合（circle-service 管辖），**非 MySQL 表**。本 PRD 此前误用 ALTER TABLE 写法，已修正为 Mongo 文档结构扩展。

### 3.1 MongoDB quanzi_comment 文档结构扩展

```javascript
// 现有 quanzi_comment 文档新增字段
{
  // --- 已有字段 ---
  "_id": ObjectId,
  "postId": String,           // 动态 ID（Hashids）
  "userId": Number,           // 评论作者 ID
  "content": String,          // 评论内容（最多 1000 字符）
  "createdAt": ISODate,
  
  // --- 本次新增 ---
  "parentId": Number,         // 父评论 ID（0=顶级评论，默认 0）
  "replyUserId": Number,      // 被回复用户 ID（0=无，默认 0）
  "atUserIds": [Number],      // 被@的用户 ID 数组（上限 10 人）
  "status": String            // 评论状态：VISIBLE / HIDDEN / DELETED
}
```

### 3.2 索引变更

```javascript
// 新建索引（circle-service 启动时 ensureIndex）
db.quanzi_comment.createIndex({ "postId": 1, "parentId": 1, "createdAt": -1 });
db.quanzi_comment.createIndex({ "parentId": 1, "createdAt": -1 });
```

### 3.3 emoji 说明

- **不存储 `emoji_count` 冗余字段**，由前端解析 content 计算。
- content 字段上限：**1000 字符**（MongoDB 按字符数校验，与字节数无关）。

## 四、接口设计

### 4.1 评论列表（改造）

> ⚠ **接口路径对齐**：本 PRD 此前使用 `/circle/{postId}/comments`（RESTful），已对齐主文档 FR-ACT-03/04 的 `/comments?movementId=` 风格。postId 在此等价于 movementId（Hashids 编码的动态 ID）。

- **接口**：`GET /comments?movementId={postId}&page=1&pageSize=20`
- **逻辑**：
  - 返回顶级评论（parentId=0）
  - 每条顶级评论带 `replies[]`（二级嵌套，最多 3 条）
  - 若二级条数 > 3，显示"查看 N 条回复"（点击加载更多，分页）

### 4.2 发送评论（改造）

- **接口**：`POST /comments`（body 含 `movementId`）
- **请求体**：

```json
{
  "content": "这个周末真的太热了 🥵",
  "parentId": 0,
  "replyUserId": 0,
  "atUserIds": []
}
```

- **被 @ 用户非 0 时**：后端调用 PushService.atNotify()

### 4.3 @ 搜索用户

- **接口**：`GET /comments/at-search?movementId={postId}&keyword=`
- **排序规则**：recentUsers 按「互动类型权重 × 时间衰减」排序，去重规则：同一用户仅取最近一次互动，postAuthor 置顶。
- **响应**：

```json
{
  "code": 200,
  "data": {
    "recentUsers": [
      { "userId": 101, "nickname": "小王", "avatar": "..." },
      { "userId": 102, "nickname": "小李", "avatar": "..." }
    ],
    "postAuthor": { "userId": 201, "nickname": "作者", "avatar": "..." }
  }
}
```

### 4.4 二级回复分页

- **接口**：`GET /comments/replies?movementId={postId}&parentId={parentId}&page=1&pageSize=10`
- **请求**：点击"查看 N 条回复"时调用

## 五、评论状态机

```
VISIBLE ──[被管理员/Hidden]──→ HIDDEN ──[恢复正常]──→ VISIBLE
   │                              │
   └──[用户删除/违规]──→ DELETED ←──[管理员删除]──┘
```

| 状态 | 含义 | 前端展示 | 谁可触发 |
|------|------|---------|---------|
| VISIBLE | 正常可见 | 正常展示 | — |
| HIDDEN | 被管理员隐藏 | "该评论已被隐藏" | ADMIN/OPERATOR |
| DELETED | 已删除 | "该评论已删除"占位 | 作者本人 / ADMIN |

## 六、接口错误响应

| 接口 | 400 | 401 | 403 | 404 |
|------|-----|-----|-----|-----|
| GET /comments | movementId 为空 | 未登录（可匿名浏览则不发）| — | 动态不存在 |
| POST /comments | content 为空/超 1000 字/命中敏感词 | 未登录 | — | 动态不存在 |
| GET /comments/at-search | keyword 为空返回全部 recentUsers | 未登录 | — | — |
| GET /comments/replies | parentId 无效 | — | — | 父评论不存在 |

## 七、边界场景

| 场景 | 处理 |
|------|------|
| @ 后用户改名 | @ 显示发送时的快照昵称（不联动更新），点击跳转到最新用户主页 |
| 表情输入超长 | content 字段大溢：数据库 VARCHAR(1000)，超出部分截断 + 前端校验 |
| 二级回复中子评论被删 | 对话中的"该评论已删除"占位，后续评论继续展示 |
| 被 @ 的用户已封禁/注销 | 推送不发，仅展示文本但不跳转 |
| 回复二级评论 | parentId = 二级评论 ID，replyUserId = 二级评论作者 ID |
| 复制评论文本 | uni.getClipboardData 获取纯文本（去除 @ 标记和 emoji）|

## 九、UI 设计规范与功能边界

> 本节为样式与功能约束，开发时**必须遵守**，禁止自行发挥视觉风格或超出边界实现。

### 9.1 设计系统引用（强制）

| 规范层 | 来源 | 关键约束 |
|--------|------|---------|
| 品牌色 | `docs/AI-agent交接-品牌主色切换.md` | @ 昵称高亮用品牌语义色（蓝色 `#3b82f6`，非品牌色）；点赞红 `#ef4444`；**禁止品牌色 `#fe3c72` 与语义色混淆**；禁止硬编码色值 |
| 图标 | `docs/icon-icons.md` | 表情按钮用 `i-ph-smiley`；发送用 `i-ph-paper-plane-tilt`；**禁止 emoji 充当 UI 图标**（用户输入的 emoji 内容不在此列） |
| 组件 | `docs/需求文档/03-开发规范.md` §3 | 输入框复用 `u-input`；表情面板自建但样式走主题变量；**禁止重复造轮子** |
| 暗色模式 | `docs/需求文档/03-开发规范.md` | 强制支持；评论卡片暗色底 `#1e1e1e` |

### 9.2 页面级 UI 规格

| 元素 | 规格 |
|------|------|
| 评论输入框 | 底部固定，高 88rpx，圆角 pill，浅灰底 `--color-bg-secondary`，表情按钮右侧 |
| 表情面板 | 输入框上方弹出，高 400rpx，白底（暗色 `#1e1e1e`），网格 8 列 |
| @ 昵称高亮 | 蓝色 `#3b82f6`，可点击跳转用户主页 |
| 二级回复缩进 | 左侧缩进 48rpx + 竖线 2rpx `--color-border` |
| 评论卡片 | 圆角 `$uni-border-radius-base(16rpx)`，内边距 20rpx，头像 56rpx 圆形 |
| "查看 N 条回复" | 24rpx，品牌色 `$uni-color-primary`，点击展开分页 |
