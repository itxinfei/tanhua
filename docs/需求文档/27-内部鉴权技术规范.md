# 心飞交友（xfjy）内部鉴权技术规范

> 版本：v1.0（一次性确定，不再变更）
> 更新日期：2026-11-03
> 状态：**冻结基线**。本文档是内部服务鉴权的唯一权威定义，所有 AI 工具与开发者必须遵守。
> 对应 `AGENTS.md` §4 第 4 条与 `02-技术约束.md` CONST-SEC-013。

---

## 一、适用范围

本规范定义 **xfjy 微服务之间**（网关 → BFF → 域服务）的内部调用鉴权机制。

**不包含**：
- 外部用户鉴权（App/Admin 登录态，由 Sa-Token 负责，见 `AGENTS.md` §4 第 1-3 条）
- 中间件鉴权（MySQL/Redis/MongoDB/Nacos，见 CONST-SEC-012）
- 第三方回调鉴权（支付回调等，单独规范）

---

## 二、技术栈锁定（禁止变更）

| 项 | 选型 | 禁止 |
|---|---|---|
| 鉴权方式 | 共享 Token（`X-Internal-Token` 请求头） | JWT、mTLS、OAuth2、服务网格 |
| Token 存储 | 配置文件 / 环境变量（明文，不加密） | 数据库、Redis、密钥管理服务 |
| Token 格式 | 逗号分隔字符串（支持多 Token） | 数组、JSON、单一固定值 |
| 校验方式 | 内存 Set 精确匹配 | 模糊匹配、前缀匹配、正则 |
| 失败响应 | HTTP 403 + JSON 错误体 | 重定向、401、500 |
| 热更新 | 支持（`@Value` 注入，重启生效） | 运行时动态刷新（当前不实现） |

**变更流程**：如需修改本规范任何条目，必须在 PR 描述中给出「规则变更理由」，经人工评审合并后方可生效。

## 三、调用链与职责

```
┌─────────────┐     X-Internal-Token      ┌─────────────┐     X-Internal-Token      ┌─────────────┐
│  外部请求    │ ──────────────────────────▶│  网关        │ ──────────────────────────▶│  BFF        │
│  (App/Admin) │                            │  xfjy-gateway│                            │  xfjy-server │
└─────────────┘                            └─────────────┘                            └──────┬──────┘
                                                                                             │
                                                                                             │ X-Internal-Token
                                                                                             ▼
                                                                                      ┌─────────────┐
                                                                                      │  域服务      │
                                                                                      │ circle/video │
                                                                                      │ match/message│
                                                                                      │ pay/user     │
                                                                                      │ elasticsearch│
                                                                                      │ recommend    │
                                                                                      └─────────────┘
```

### 3.1 网关 `xfjy-gateway`（InternalTokenFilter）

- **职责**：给所有经网关转发的请求**自动注入** `X-Internal-Token` 头
- **触发条件**：`internal.auth.tokens` 配置非空
- **Token 取值**：取逗号分隔的**第一个** Token（`split(",")[0].trim()`）
- **执行顺序**：`Ordered` = 0（在限流之后、路由之前）
- **代码位置**：`xfjy-gateway/src/main/java/com/xfjy/gateway/filter/InternalTokenFilter.java`

### 3.2 BFF `xfjy-server`（HttpServiceProxyConfig）

- **职责**：调用域服务时**自动注入** `X-Internal-Token` 头
- **触发条件**：`internal.auth.tokens` 配置非空
- **Token 取值**：取逗号分隔的**第一个** Token（与网关一致）
- **注入方式**：`RestClient.Builder.defaultHeader()`
- **代码位置**：`xfjy-server/src/main/java/com/xfjy/server/config/HttpServiceProxyConfig.java`

### 3.3 域服务（XInternalTokenInterceptor）

- **职责**：**校验** `X-Internal-Token` 头是否在有效 Token 集合中
- **触发条件**：所有进入域服务的 HTTP 请求（除健康检查外）
- **校验逻辑**：`validTokens.contains(token)`，精确匹配
- **失败响应**：HTTP 403 + `{"code":403,"message":"Forbidden: invalid internal token"}`
- **代码位置**：每个域服务 `interceptor/XInternalTokenInterceptor.java`

## 四、配置规范

### 4.1 YAML 配置格式（MUST）

**正确格式**（字符串）：
```yaml
internal:
  auth:
    tokens: xfjy-internal-dev-token-change-in-prod
```

**错误格式**（YAML 列表，会导致 Token 值带方括号）：
```yaml
internal:
  auth:
    tokens: -xfjy-internal-dev-token-change-in-prod   # ❌ 禁止
```

**多 Token 格式**（逗号分隔）：
```yaml
internal:
  auth:
    tokens: token-a,token-b,token-c
```

### 4.2 环境变量覆盖（生产环境）

生产环境通过 `INTERNAL_AUTH_TOKENS` 环境变量覆盖：
```yaml
internal:
  auth:
    tokens: ${INTERNAL_AUTH_TOKENS:-xfjy-internal-dev-token-change-in-prod}
```

**部署要求**：
- 开发/测试环境：配置文件明文（允许）
- 生产环境：通过部署注入 `INTERNAL_AUTH_TOKENS`，配置文件中的默认值仅为占位符

### 4.3 配置一致性（MUST）

**所有服务的 `internal.auth.tokens` 必须完全一致**，包括：
- `xfjy-gateway`
- `xfjy-server`
- `xfjy-circle-service`
- `xfjy-video-service`
- `xfjy-match-service`
- `xfjy-message-service`
- `xfjy-pay-service`
- `xfjy-user-service`
- `xfjy-elasticsearch`
- `xfjy-recommend`

**校验命令**：
```bash
grep -r "internal.auth.tokens" --include="*.yml" xfjy-*/src/main/resources/
# 所有值必须一致（环境变量占位符除外）
```

## 五、Token 管理

### 5.1 生成规则

- 长度：≥ 32 字符
- 字符集：字母 + 数字 + 连字符
- 示例：`xfjy-internal-dev-token-change-in-prod`
- 生产环境：使用随机生成的唯一 Token，禁止复用开发 Token

### 5.2 轮换策略（SHOULD）

- 定期轮换（建议 90 天）
- 轮换时支持多 Token 并存（新旧 Token 同时有效）
- 轮换流程：
  1. 在 `internal.auth.tokens` 中追加新 Token（`old,new`）
  2. 部署所有服务
  3. 确认所有服务使用新 Token
  4. 从配置中移除旧 Token

### 5.3 泄露响应

- 立即在部署环境变量中更换 Token
- 重新部署所有服务
- 审计日志确认泄露范围

## 六、故障排查

### 6.1 403 Forbidden

**可能原因**：
1. Token 配置不一致（网关/BFF 与域服务）
2. YAML 格式错误（列表 vs 字符串）
3. Token 值前后有空格（未 `trim()`）

**排查步骤**：
1. 检查请求头：`curl -H "X-Internal-Token: <token>" ...`
2. 对比配置：`grep -r "internal.auth.tokens" ...`
3. 查看域服务日志：`[XInternalToken] 非法调用`

### 6.2 500 Internal Server Error

**可能原因**：
1. 域服务未启动
2. 网络不通（Docker 容器地址不可达）
3. 服务发现路由到错误实例

**排查步骤**：
1. 检查服务状态：`curl http://<service>/actuator/health`
2. 检查 BFF 配置：`xfjy.*.service.url` 是否正确
3. 检查 Nacos 注册实例

## 七、禁止事项（MUST NOT）

1. **禁止**在域服务中信任外部传入的用户身份头（如 `X-User-Id`）
2. **禁止**绕过 `XInternalTokenInterceptor` 直接暴露域服务端口
3. **禁止**在日志中打印完整 Token 值
4. **禁止**将 Token 硬编码在代码中（必须配置化）
5. **禁止**使用 YAML 列表格式配置 Token
6. **禁止**在网关/BFF 中修改或删除 `X-Internal-Token` 头
7. **禁止**为内部鉴权引入新的技术栈（JWT/mTLS/服务网格）

---

## 八、代码审查清单

每次涉及内部鉴权的 PR 必须检查：

- [ ] 新增域服务是否配置了 `XInternalTokenInterceptor`
- [ ] 新增域服务是否在 `WebMvcConfig` 中注册了拦截器
- [ ] `internal.auth.tokens` 配置格式是否为字符串（非列表）
- [ ] 所有服务的 Token 值是否一致
- [ ] 是否误删/修改了 `InternalTokenFilter` 或 `HttpServiceProxyConfig`
- [ ] 是否在代码中硬编码了 Token 值
