# PRD：女用户保护与平台安全机制（Phase 3 P2）

> FR-ID: **FR-SAFE-01**  
> 优先级：**P2**  
> 负责人：前端 1 人 + 后端 1 人  
> 预估工时：前端 1.5d + 后端 2d = 3.5d  
> 依赖项：内容审核（已有 DFA 敏感词）、举报（已有基础接口）  
> FR-ID（需求文档关联）：FR-USER-01（用户账户）/ FR-REC-02（匹配）

## 一、背景与目标

### 1.1 业务背景

陌生人社交平台的**核心风险**是女用户体验恶化 → 女用户流失 → 男用户匹配池萎缩 → 平台死亡。

**触目惊心的行业数据**：
- 探探/ Soul 女用户卸载主因：被骚扰占 63%
- 女用户收到第一条消息后 24h 内不回复概率 > 50%（因为骚扰占比过高）
- 女用户向好友推荐陌生人社交 App 的意愿仅 3%（因为"太乱了"）

**当前产品安全机制缺失**：
1. 女用户首次使用无安全引导
2. 聊天时无快捷屏蔽/举报入口
3. 举报流程无截图上传
4. IM 图片无 AI 敏感检测
5. 无"仅匹配已认证用户"保护选项
6. 无边控关键词自动拦截

### 1.2 数据目标

| 指标 | 当前 | 目标 |
|------|:---:|:---:|
| 女用户 7 日留存 | ≈男用户（无差异保护）| 女用户超过男用户 20%+ |
| 骚扰举报率 | — | < 0.5%（占总消息比）|
| 举报处理 48h 响应率 | — | 95%+ |
| 女用户 NPS（净推荐值）| — | > 30 |
| 已认证用户被喜欢数 vs 未认证 | — | 2x+ |

### 1.3 非目标

- 不在本版本实现 AI 鉴黄/暴恐图片检测（预留扩展位，一期规则 + 人工为主）
- 不做实时人脸年龄检测（合规留到二期）
- 不做公安联网身份核验（预留接口，暂不接）

### 2.6 内容安全策略频率限制

| 场景 | 规则 | 前端提示 |
|------|------|---------|
| 同一条消息内容 | 10s 内只能发送 3 次（防刷屏）| 按钮 disabled 3s + toast"发送太频繁，请稍候" |

## 三、举报处理状态机

```
PENDING ──[运营审核通过]──→ ACCEPTED ──[如需封禁]──→ FROZEN
   │                              │
   └──[运营审核驳回]──→ REJECTED   └──[30 天后自动]──→ ACCEPTED（解除封禁）
```

| 状态 | 含义 | 触发谁可操作 |
|------|------|-------------|
| PENDING | 待审核（初始态）| — |
| ACCEPTED | 审核通过（举报成立）| ADMIN/OPERATOR |
| REJECTED | 举报驳回 | ADMIN/OPERATOR |
| FROZEN | 用户被封禁（终态，需 SUPER_ADMIN 解除）| SUPER_ADMIN |

## 五、接口设计

### 5.1 黑名单操作

> ⚠ **接口路径对齐**：黑名单接口与主文档 FR-SET-03 对齐为 RESTful `/users/blacklist/{uid}`。

| API | 描述 |
|-----|------|
| `POST /users/blacklist/{uid}` | 加入黑名单（body 含 `source`） |
| `DELETE /users/blacklist/{uid}` | 移出黑名单 |
| `GET /users/blacklist` | 获取已屏蔽列表（分页） |

### 5.2 举报升级

- **接口**：`POST /users/report`（改造）
- **请求体**：

```json
{
  "targetUserId": 456,
  "reasons": ["sexual_content", "harassment"],
  "description": "一直发黄图",
  "screenshotUrls": ["https://oss.xfjy.com/report/xxx.jpg"]
}
```

### 5.3 设置隐私开关

| API | 描述 |
|-----|------|
| `GET /users/settings/privacy` | 获取隐私设置 |
| `PUT /users/settings/privacy` | 更新隐私设置 `{verifiedOnly, blockImages}` |

### 5.4 接口错误响应

| 接口 | HTTP | 错误码 | 场景 | message |
|------|:---:|:---:|------|---------|
| `POST /users/blacklist/{uid}` | 400 | `INVALID_USER` | uid 为自己或不存在 | "操作不合法" |
| `POST /users/blacklist/{uid}` | 409 | `ALREADY_BLOCKED` | 已拉黑该用户 | "该用户已在黑名单" |
| `POST /users/blacklist/{uid}` | 429 | `BLACKLIST_LIMIT` | 黑名单数已达上限 200 | "黑名单已满，请先清理" |
| `DELETE /users/blacklist/{uid}` | 404 | `NOT_BLOCKED` | 用户不在黑名单 | "该用户不在黑名单" |
| `POST /users/report` | 400 | `INVALID_REASON` | reasons 为空或格式错误 | "请选择举报原因" |
| `POST /users/report` | 409 | `DUPLICATE_REPORT` | 24h 内重复举报同一用户 | "您已举报过该用户" |
| `POST /users/report` | 413 | `SCREENSHOT_LIMIT` | 截图超过 3 张 | "举报截图最多上传 3 张" |
| `PUT /users/settings/privacy` | 400 | `INVALID_SETTING` | 设置值格式错误 | "设置值不合法" |

> 前端统一处理：409 → toast（静默隐藏操作入口）；429/413 → toast + 阻止提交；400 → 弹窗提示。

## 六、边界场景

| 场景 | 处理 |
|------|------|
| 同一用户多次举报 | 限制 1 小时内只能举报同一用户 1 次（防刷举报）|
| 举报被驳回 | 被举报用户无感知，邀请方收到"经审核未发现违规"通知 |
| 误报导致用户被误封 | 被举报用户可申诉 → 运营 48h 内复核 |
| 黑名单已满 | 上限 200 人，超出后提示"请先清理黑名单" |
| 女用户开启"仅匹配已认证"后推荐池为空 | 展示引导："当前认证用户较少，是否放宽匹配？"+ 切换按钮 |
| 图片敏感检测 SDK 不可用（网络问题）| 踢过后备方案：允许发送 + 增加人工审核标记频率 |

## 八、UI 设计规范与功能边界

> 本节为样式与功能约束，开发时**必须遵守**，禁止自行发挥视觉风格或超出边界实现。

### 8.1 设计系统引用（强制）

| 规范层 | 来源 | 关键约束 |
|--------|------|---------|
| 品牌色 | `docs/AI-agent交接-品牌主色切换.md` | 安全主题用语义色（警示橙 `#f59e0b` / 成功绿 `#22c55e` / 危险红 `#ef4444`），**不使用品牌色做安全标识**；禁止硬编码色值 |
| 图标 | `docs/icon-icons.md` | 盾牌用 `i-ph-shield-check`；举报用 `i-ph-flag`；锁定用 `i-ph-lock`；**禁止 emoji 充当图标** |

| 暗色模式 | `docs/需求文档/03-开发规范.md` | 强制支持 |

### 8.2 页面级 UI 规格

| 元素 | 规格 |
|------|------|
| 首次登录安全页 | 全屏，30s 倒计时，盾牌图标 120rpx + 安全提示文案 + "我已了解"按钮 |
