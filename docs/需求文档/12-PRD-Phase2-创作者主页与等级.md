## 一、背景与目标

### 1.1 业务背景

当前用户无法查看作者主页、无法追踪其全部作品、无法与创作者建立更深关系。优秀创作者没有成长激励，平台缺少 PGC（专业生成内容）生态。

### 1.2 数据目标

| 指标 | 当前 | 目标 |
|------|:---:|:---:|
| 内容消费者访问作者主页率 | 0% | 15%+ |
| 创作者 7 日回访率 | 40% | 60%+ |
| 创作者月均发布作品数 | 3.2 条 | 8+ 条 |
| 内容平均互动率（创作者粉丝 vs 非粉丝）| — | 粉丝 3x+ |

## 二、创作等级体系

### 2.1 等级设计

| 等级 | 图标 | 升级条件 | 权益 |
|:---:|:---:|------|------|
| Lv.1 新人 | ⭐ | 注册即送 | 基础曝光 |
| Lv.2 活跃 | ⭐⭐ | 粉丝 ≥ 10 + 发布 ≥ 3 条内容 | 内容加权推荐 + 可自定义主页背景 |
| Lv.3 人气 | ⭐⭐⭐ | 粉丝 ≥ 100 + 周更 ≥ 3 条 | 认证标识 + 主页推荐位 |
| Lv.4 达人 | 💎 | 粉丝 ≥ 1000 + 周更 ≥ 5 条 | 钻石认证 + 内容加热折扣 |
| Lv.5 明星 | 💎💎 | 运营邀请制 | 官方认证 + 流量保障 + 广告分成 |

> ⚠ **与积分等级的区别**：此处 `creator_level` 是内容创作等级（由粉丝数、发布频率决定），与用户积分体系的 `score_level`（由签到、任务等行为积分决定）**两者独立计算**。创作者主页展示 `creator_level`，积分页和等级进度条展示 `score_level`，前端上下文需明确区分，不可混淆。

### 2.2 等级进度可视化

```
┌────────────────────────────────────────┐
│  当前等级：Lv.3 ⭐⭐⭐                    │
│                                        │
│  ┌──────────────────────────┐          │
│  │ Lv.1  Lv.2  [Lv.3]  Lv.4 Lv.5  │  ← 游标指示当前位置
│  └──────────────────────────┘          │
│                                        │
│  距离下一等级还需：                        │
│  · 再增加 15 个粉丝（已有 85/100）         │
│  · 再发布 2 条内容（本周已有 1/3）         │
│  · 连续 7 天活跃（当前 3/7）              │
│                                        │
└────────────────────────────────────────┘
### 2.3 等级状态机与升降级规则

```
申请升级（定时任务 00:00）              降级（定时任务 02:00）
       │                                      │
       ▼                                      ▼
  检查升级条件                           检查降级条件
  （粉丝+发布+活跃）                   （30 天无新发布）
       │                                      │
       ├── 满足 ──→ 升级 ──→ 推送通知          ├── 命中 ──→ 降级 1 级
       │               + 庆祝动效              │            + 推送提醒
       └── 不满足 ──→ 保持                     └── 未命中 ──→ 保持
```

| 规则 | 判定条件 | 操作 |
|------|---------|------|
| 升级 | 每日 00:00 定时任务，粉丝/发布/活跃三维度均满足下一等级条件 | level +1 + 推送 + 庆祝动效 |
| 降级 | 滚动 30 天窗口内发布数为 0（短视频或动态均计）| level -1（最低降至 Lv.1）+ 推送"多创作恢复等级" |
| 休眠标记 | 滚动 14 天窗口内发布数为 0 | 标记"休眠"（不降级，主页显示"创作休眠中"），达到 30 天触发降级 |
| 冻结 | 账号被封禁（`status=FROZEN`）| 主页不展示创作者信息，等级隐藏 |
| 星标（Lv.5）| 运营邀请制，不走自动升降级 | 需 SUPER_ADMIN 手动设定 |

> ⚠ **降级策略**：降级时保留历史最高等级记录在 `creator_level_history` 中，用户可在"等级详情页"查看；降级后权益即时收回（如主页推荐位），但不追溯已享受的权益。

## 三、数据模型变更

### 3.1 用户表新增创作者等级字段

```sql
ALTER TABLE tb_user ADD COLUMN creator_level TINYINT NOT NULL DEFAULT 1 COMMENT '创作者等级: 1=Lv.1 新人, 2=Lv.2 活跃, 3=Lv.3 人气, 4=Lv.4 达人, 5=Lv.5 明星';
ALTER TABLE tb_user ADD COLUMN creator_active_days INT NOT NULL DEFAULT 0 COMMENT '连续活跃天数（用于升级评估）';
ALTER TABLE tb_user ADD COLUMN creator_last_publish_time DATETIME COMMENT '最近一次发布时间（用于降级判定）';
```

### 3.2 创作者等级历史表

```sql
CREATE TABLE tb_creator_level_history (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  old_level TINYINT NOT NULL,
  new_level TINYINT NOT NULL,
  reason ENUM('UPGRADE','DOWNGRADE','ADMIN_SET') NOT NULL,
  created DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_user(user_id)
) COMMENT='创作者等级变动历史';
```

### 5.3 等级定时任务（每日 00:00 升级评估）

```java
@Scheduled(cron = "0 0 0 * * ?")
public void evaluateCreatorLevel() {
    // 查询所有达人级别以下用户
    List<Creator> candidates = creatorService.findUpgradeCandidates();
    for (Creator c : candidates) {
        int newLevel = calculateLevel(c.getFollowers(), c.getPosts(), c.getActiveDays());
        if (newLevel > c.getLevel()) {
            creatorService.upgrade(c.getUserId(), newLevel);
            pushService.push(c.getUserId(), "⭐ 恭喜升级到 Lv." + newLevel, PushType.LEVEL_UP, null);
        }
    }
}
```

## 六、边界场景

| 场景 | 处理 |
|------|------|
| 自己访问自己的创作者主页 | 显示"编辑封面"和"查看数据"入口，不显示"关注"按钮 |

| 等级升级瞬间 | 展示全屏庆祝动效 + 推送通知 + 升级弹窗 |

| 规范层 | 来源 | 关键约束 |
