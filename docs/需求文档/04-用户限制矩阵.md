# 心飞交友 — 用户限制矩阵（Free vs VIP）

> 版本：v1.0  
> 更新日期：2026-11-01  
> 用途：**限制类需求的唯一真源（Single Source of Truth）**  
> 配套文档：`01-需求文档.md`（业务需求）、`deploy/mysql/init/02-schema.sql`（权益种子数据）、`xfjy-app/src/store/match.ts`（前端计数常量）  
> 适用范围：C 端 App（uni-app）+ BFF（xfjy-server）+ 支付服务（xfjy-pay-service）

---

## 一、设计原则

1. **任何次数/数量限制必须在此文档登记**，不在文档中的限制一律不得在前端或后端执行
2. **免费限制硬编码在 `match.ts` 前端常量（`MAX_FREE_SWIPE`、`MAX_FREE_REWIND`）**，防止用户绕过；VIP 限制在后端 `tb_value_added_service` 维护，可动态调整（Nacos 配置 + DB 权益表）
3. **前端限制用体验引导**（用完后引导页/弹窗），**后端限制用接口拦截**（返回 402 + 弹窗），双重兜底
4. **用户可以清楚看到剩余次数**（始终展示"剩余 N 次"），禁止"静默丢弃操作"

## 三、详细限制说明

### 3.1 滑动推荐（Swipe Limit）

| 维度 | 详情 |
|------|------|
| **普通用户** | 每日**右滑（喜欢 / 超级喜欢）上限 50 次**；**左滑（跳过）不计数、不限次** |
| **VIP 月卡** | 同 Free（右滑 50 次），**不额外增加** |
| **VIP 季卡+** | **无限右滑**（`hasUnlimitedSwipe=true`，绕过 50 次校验）|
| **口径来源** | 对齐探探（2026-11-04 裁决）：探探免费用户每日右滑 120 次、**左滑不计数**，VIP 特权仅「无限喜欢次数」不含无限左滑；「滑错无限反悔」左右滑均可反悔。本项目将上限设为 50 次，其余口径一致 |
| **前端实现** | `xfjy-app/src/store/match.ts` → `const MAX_FREE_SWIPE = 50`；`doSwipe()` 仅对 like/superlike 执行 `swipeCount++`，dislike 直接 return；`pages/match/index.vue` 的 `swipeOut()` 仅对非 dislike 校验 `canSwipe()` |
| **后端实现** | `xfjy-server/BFF` → `TodayBestService.likeUser()` 调用 `checkSwipeLimit(action)` 并写 `tb_swipe_log`；`disLikeUser()` **不校验次数、不写日志**（写会让额度被跳过动作吃掉） |
| **触发引导** | 第 51 次**右滑**被拦截 → 跳转 `pages/match/swipe-out.vue` 全屏引导页；左滑不受限 |
| **计数跨日** | 本地以 `xfjy_count_date`（storage）为标记，00:00 自动清零 + 服务端以 `CURDATE()` 为准 |
| **历史数据** | 2026-11-04 前的 `tb_swipe_log` 含 dislike 记录，但 `countTodaySwipes` 按 `DATE(created)=CURDATE()` 只统计当天，跨日后不影响新口径 |

### 3.2 撤销上滑（Rewind Limit）

| 维度 | 详情 |
|------|------|
| **限制逻辑** | 每日可免费回看 **3 次**，超出需看广告 1 次 或 开通 VIP。**回看不限滑动方向**（左滑/右滑都能反悔，对齐探探「滑错无限反悔」）|
| **前端实现** | `match.ts` → `const MAX_FREE_REWIND = 3`；`canRewind()` 返回 `rewindCount.value < MAX_FREE_REWIND`；`undoSwipe()` 对 dislike 直接 return（无后端状态变更、也未计次）|
| **VIP 提升** | Lv2+ 无限撤销（无需做后端校验，`hasUnlimitedRewind` 由权益接口返回）|

### 3.3 超级喜欢（Super Like）

| 维度 | 详情 |
|------|------|
| **普通用户** | **不可使用**（前端按钮灰显 + tooltip"开通 VIP 解锁超级喜欢"）|
| **VIP 月卡** | 每日 **5 次**（前端"超级喜欢 × 5" 角标，后端扣减）|
| **VIP 季卡** | 每日 **10 次** |
| **VIP 年卡** | 每日 **15 次** |
| **后端权益码** | `super_like`，`vip_level_required=1`，`daily_limit=5`（DB 数据）|
| **校验流程** | 用户点超级喜欢 → 前端 POST `/users/vip/benefit/usage` {serviceCode: "super_like"} → 后端校验 hasBenefit + remainingToday > 0 → 成功调用 matchService.superLike(userId, targetUserId) → 失败返回 402 + toast"今日超级喜欢已用完" |
| **跨日重置** | 每日 00:00 重置（由权益消费记录 `tb_benefit_usage` CURDATE 筛选）|

### 3.4 查看"谁喜欢我"（See Who Likes Me）

| 维度 | 详情 |
|------|------|
| **普通用户** | 仅显示数量（"3 人喜欢你"）+ 头像高斯模糊预览（CSS blur 8px）|
| **后端接口** | `GET /match/blurred-likes?limit=3` → 非 VIP 返回 avatar（原图）但前端 blur 处理 |
| **VIP 用户** | 返回完整列表（头像清晰）+ 支持分页加载 |
| **升级引导** | 模糊头像旁显示 🔒 图标 + "开通 VIP 查看完整" 按钮 |

### 3.5 高级筛选（Advanced Filters）

| 维度 | 详情 |
|------|------|
| **普通用户** | 无此功能（筛选区不显示学历/收入/身高筛选器）|
| **VIP 月卡** | 每日 **1 次** 免费体验（用后回到基础筛选，tooltip"今日已用，明天再来"）|
| **VIP 季卡+** | **无限使用** |
| **前端实现** | 筛选区增加 VIP filter 区域 → 点击时 checkBenefit("advanced_filter") → 未购买弹窗引导 |
| **后端权益码** | `advanced_filter`（待新增），`vip_level_required=1`，`daily_limit=1` |

### 3.6 隐身访问（Stealth Visit）

| 维度 | 详情 |
|------|------|
| **普通用户** | 访问他人主页时写 `tb_visitors`（留下访客记录）|
| **VIP 季卡+** | 前端开关默认开启 → 调用 `POST /users/stealth-visit?enabled=true` → 后端写入访客记录时跳过 |
| **后端实现** | `UserProfileService` 判断 `userVipLevel >= 2` + `stealthVisitEnabled=true` → 跳过 visitors 写入 |

## 五、接口拦截规范

### 5.1 后端限制拦截响应

当用户触发任何次数限制时，后端统一返回：

```json
{
  "code": 402,
  "message": "今日滑动次数已用完",
  "data": {
    "limitType": "swipe_daily_limit",
    "currentUsage": 50,
    "maxLimit": 50,
    "resetAt": "次日 00:00",
    "upgradeHint": "开通 VIP 季卡，解锁无限滑动 →",
    "upgradeUrl": "/pages/mine/vip?source=swipe_out"
  }
}
```

前端接收 402 后统一跳转拦截处理：
- 已定义引导页的 → 跳对应引导页
- 未定义的 → 通用 toastmessage + 弹出 VIP 引导弹窗

### 5.2 前端拦截前先后端校验

```
前端本地计数 >= 阈值 → 先拦截不发请求（避免浪费服务端 QPS）
   ↓ (如果 hasUnlimitedSwipe 权益)
直接放行
   ↓ (如果是 Free 用户)
阻止滑动 → 跳转引导页
   ↓ (用户绕过前端直接调接口)
后端再次校验 → 返回 402
```

### 5.3 后端校验实现映射（已落地）

> **图例**：✅ = 已部署后端兜底；🛠️ 前端低风险，暂纯前端

| 限制项 | 后端校验位置 | 触发条件 | 异常类型 | 状态 |
|------|------------|---------|---------|:---:|
| 每日滑动 50 次 | `TodayBestService.checkSwipeLimit()` → `SwipeLogApi.countTodaySwipes()` | action=like/superlike 写前校验 | `SwipeLimitException` (402) | ✅ |
| 超级喜欢每日限次 | `TodayBestService.checkSuperLikeBenefit()` → `PayApi.checkBenefit("super_like")` | action=superlike 写前校验 + 后端扣减 | `BenefitLimitException` (402) | ✅ |
| 每日撤销 3 次 | 纯前端 `canRewind()` | storage 读取 → 前端判断 | — | 🛠️ 低风险 |
| 语音 60s 上限 | 纯前端 `chat.vue` | 录音时 UI 拦截 | — | 🛠️ 低风险 |
| 动态 9 张 / 500 字 | 纯前端 `circle/publish.vue` | UI 文件数量/字数限制 | — | 🛠️ 低风险 |
| 私信频控 10 条/分 | `ChatService` 限流 | Redis 计数 | 业务 400 | ✅ 既有 |

#### 5.3.1 滑动次数校验时序（love 接口）

```
用户点击右滑/超级喜欢
    ↓
前端 doSwipe(action="like"/"superlike") →（dislike 在此分流，不进入本链路）
    ↓
BFF TodayBestController.likeUser(id, action) →
    ↓
checkSwipeLimit(action)
  ├─ PayApi.checkBenefit(unlimited_swipe) → VIP 有权 → 放行
  └─ 无权益 → SwipeLogApi.countTodaySwipes() >= 50 → 402 SwipeLimitException
    ↓
checkSuperLikeBenefit(userId, action)
  ├─ action≠superlike → 跳过
  ├─ 无 super_like 权益 → 402 BenefitLimitException
  ├─ 今日剩余 ≤ 0 → 402 BenefitLimitException
  └─ 有权 → PayApi.recordBenefitUsage (后端扣减)
    ↓
userLikeApi.saveUserLike() → 写 tb_swipe_log（仅右滑）→ Neo4j 同步 → IM 匹配

用户点击左滑（跳过）
    ↓
前端 doSwipe(action="dislike") → unloveUser → 直接 return（不计数）
    ↓
BFF TodayBestController.disLikeUser(id) →
    ↓
（无次数校验、不写 tb_swipe_log）
    ↓
deleteUserLike() → Neo4j removeLikeRelation()
```

> **左滑不计次的原因**：若 `disLikeUser` 也写 `tb_swipe_log`，`countTodaySwipes` 会把跳过动作算进右滑额度，
> 导致用户「还没开始喜欢就被拦」。故 dislike 既不校验也不落库（对齐探探）。
