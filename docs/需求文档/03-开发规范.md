## 零、通用原则

### 0.1 三条底线

1. **不写重复逻辑**：同一段业务规则只能有一处实现。发现第二处时，抽方法或抽组件。
2. **不吞异常**：`catch` 后必须做三件事之一——记录日志、转换为业务异常、向上抛出。禁止空 `catch`。
3. **不留半成品**：提交的代码必须能编译、能运行、无 `TODO` 占位（除非带负责人与日期）。

### 0.2 命名总则

| 对象 | 规则 | 正例 | 反例 |
|------|------|------|------|
| 类 | 大驼峰，名词 | `AdminReportService` | `ReportMgr` |
| 方法 | 小驼峰，动词开头 | `handleReport`、`queryUserPage` | `report()`、`data()` |
| 变量 | 小驼峰，见名知意 | `pendingReviewCount` | `a`、`tmp1`、`list2` |
| 常量 | 全大写下划线 | `ROLE_SUPER_ADMIN` | `superAdmin` |
| 包 | 全小写 | `com.xfjy.server.service` | `com.xfjy.Server.Service` |
| 表 | `tb_` + 小写下划线 | `tb_pay_order` | `PayOrder` |
| Mongo 集合 | 小写下划线 | `quanzi_time_line` | `timeLine` |
| 前端组件 | 大驼峰文件 | `StatCard.vue` | `statcard.vue` |
| 前端 composable | `use` + 大驼峰 | `useAuthStore` | `authStore2` |
| CSS 变量 | `--xfjy-` 前缀 | `--xfjy-primary` | `--blue` |
| API 路径 | 小写 kebab-case | `/small-videos` | `/smallVideos` |

**禁止**：拼音缩写（`yhgl`）、无意义编号（`var2`）、单字母变量（循环下标 `i`/`j` 除外）。

### 0.3 API 路径与网关路由命名（强制）

**统一规则：所有对外 HTTP API 路径一律用 kebab-case（小写连字符），禁止 camelCase。**

| 规则 | 说明 |
|------|------|
| 路径风格 | 全小写 + 连字符，如 `/small-videos`、`/movements`、`/kefu-config` |
| 禁止混用 | 不得出现 `/smallVideos`、`/small_videos`、`/SmallVideos` |
| Controller `@RequestMapping` | 与路径风格一致，不加前导斜杠，如 `@RequestMapping("small-videos")` |
| 网关路由 `Path` | **必须与 Controller `@RequestMapping` 前缀完全一致**，包括连字符 |
| 网关路由 `StripPrefix` | 若用 `StripPrefix=1`，去掉的是第一段前缀，后续段仍须 kebab-case |
| 前端调用 | 一律用 kebab-case 路径，与后端契约一致 |

**网关路由必须与 Controller 前缀逐一对齐**——这是本项目高频踩坑点：

```yaml
# xfjy-gateway application.yml 路由示例（Path 须与 VideoController @RequestMapping("small-videos") 一致）
- id: xfjy-server
  uri: lb://xfjy-server
  predicates:
    - Path=/users/**,/movements/**,/comments/**,/messages/**,/small-videos/**,/baidu/**,/xfjy/**,/admin/**,/test-media/**,/kefu/**,/upload/**
```

> **根因教训（2026-11-01）**：源码已统一 kebab-case（`/small-videos`），但线上网关容器跑的是**旧镜像**（`latest` tag，内含 camelCase 路由 `/smallVideos`），导致 App 请求 `/small-videos` 返回 404。排查方向：先比对「源码路由」与「运行容器内 jar 路由」是否一致，再查镜像 tag 是否被 `up -d` 正确切换（见下文「部署与镜像 tag」）。

### 0.4 部署与镜像 tag（防止旧容器残留）

**每次 CI 构建产出的新镜像 tag = git commit 短哈希（如 `ee545d8`），部署时必须用该 tag 重建容器，禁止依赖 `latest`。**

| 规则 | 说明 |
|------|------|
| 镜像 tag | 由 CI 写入 `deploy/.env` 的 `IMAGE_TAG`，值为 `git rev-parse --short HEAD` |
| compose 镜像引用 | `image: xfjy/xfjy-gateway:${IMAGE_TAG:-latest}`，**部署时必须注入 IMAGE_TAG** |
| 部署命令 | `IMAGE_TAG=<commit> docker compose -p xfjy-app -f docker-compose.app.yml --env-file .env up -d --force-recreate` |
| `pull_policy: never` | 镜像只在本地 `docker build` 产出，不拉远程；`latest` tag 不会自动指向新镜像 |
| 禁止 `up -d` 不带 `--force-recreate` | 同 tag 同配置下 `up -d` 不重建容器；镜像内容变了必须 `--force-recreate` |

> **根因教训（2026-11-01）**：CI 已构建新镜像 `xfjy/xfjy-gateway:ee545d8`（含正确路由），但部署时 `IMAGE_TAG` 未注入，`up -d --build` 回退到 `latest` tag（Oct 31 旧镜像），容器未重建 → 线上仍跑旧 jar。**排查口诀：容器镜像 ID ≠ 最新 tag 镜像 ID → 旧容器残留，`--force-recreate` 重建。**

### 0.5 注释

- 注释解释**为什么**，不解释**是什么**（代码本身说明是什么）。
- 公共方法必须有 Javadoc / JSDoc，说明参数、返回值、异常。
- 复杂业务规则（如续费顺延、混合评分）必须写清楚规则来源。
- 禁止保留被注释掉的代码块（用 Git 历史即可）。

```java
// 好：解释业务原因
// 续费时从旧到期时间顺延，避免用户提前续费损失剩余天数
Date newExpire = max(now, oldExpire) + durationDays;

// 差：重复代码含义
// 设置过期时间
order.setExpireTime(expireTime);
```

## 一、后端开发规范

### 1.1 模块结构

```
xfjy-<module>/
├── src/main/java/com/xfjy/<module>/
│   ├── XfjyXxxApplication.java      # 启动类
│   ├── config/                       # 配置类
│   ├── controller/                   # HTTP 入口，只做参数校验与转发
│   ├── service/                      # 业务逻辑
│   ├── mapper/                       # MyBatis-Plus Mapper
│   ├── pojo/                         # 数据库实体（与表一一对应）
│   ├── vo/                           # 视图对象（返回给前端）
│   ├── dto/                          # 入参对象（可选，简单参数可用 Map）
│   ├── annotation/                   # 自定义注解
│   ├── aspect/                       # 切面
│   ├── interceptor/                  # 拦截器
│   └── utils/                        # 工具类
└── src/main/resources/
    ├── application.yml               # 公共配置
    └── application-<profile>.yml     # 环境配置
```

**必须**：
- 一个模块只负责一个业务域，不得在 `xfjy-server` 中直接实现圈子/视频的业务逻辑。
- `xfjy-api` 只放 `@HttpExchange` 契约与纯 DTO（见 `CONST-ARCH-005`）。

### 1.2 分层职责

| 层 | 职责 | 禁止 |
|----|------|------|
| Controller | 接收请求、参数校验、调用 Service、组装响应 | 写业务逻辑、直接调 Mapper、写 SQL |
| Service | 业务规则、事务边界、编排多个 Mapper/API | 处理 HTTP 细节（`HttpServletRequest`） |
| Mapper | 单表 CRUD | 跨表业务逻辑、调用 Service |

**反例（必须整改）**：

```java
// Controller 里写业务判断 —— 禁止
@PutMapping("{id}")
public ResponseEntity<Void> update(@PathVariable Long id, @RequestBody Map<String, String> param) {
    Admin admin = adminMapper.selectById(id);       // 直接调 Mapper
    if ("SUPER_ADMIN".equals(admin.getRole())) {    // 业务规则
        return ResponseEntity.badRequest().build();
    }
    ...
}
```

**正例**：

```java
@PutMapping("{id}")
public Result<Void> update(@PathVariable Long id, @RequestBody AdminUpdateParam param) {
    if (!adminAccountService.canUpdate(id, param.getRole())) {
        // 权限类失败优先由 @RequireRole / AdminTokenInterceptor 拦截；
        // 注意：GlobalExceptionHandler 目前把所有 BusinessException 映射为 HTTP 400。
        throw new BusinessException(400, "不能修改自己的角色");
    }
    adminAccountService.updateAdmin(id, param);
    return Result.success(null);
}
```

### 1.3 Controller 规范

```java
@RestController
@RequestMapping("admin/reports")          // 不加前导斜杠，与现有风格一致
@RequireRole({"SUPER_ADMIN", "ADMIN", "OPERATOR"})   // 类级注解必须与前端路由一致
public class AdminReportController {

    private static final Logger LOGGER = LoggerFactory.getLogger(AdminReportController.class);

    @Autowired
    private AdminReportService adminReportService;

    @GetMapping
    public Result<PageInfo<ReportVo>> queryPage(
            @RequestParam(defaultValue = "1") Integer page,
            @RequestParam(defaultValue = "10") Integer pageSize,
            @RequestParam(required = false) String status) {
        return Result.success(adminReportService.queryPage(page, pageSize, status));
    }
}
```

**必须**：
- 类上必须有 `@RequireRole`（`/admin/**`）。
- `@RequestParam` 必须有 `defaultValue` 或 `required = false`，避免 400。
- 分页参数统一 `page` / `pageSize`，`pageSize` 上限 100。
- 入参超过 3 个字段时用 DTO，禁止无限膨胀的 `Map<String, String>`。
- 异常必须记录日志，`LOGGER.error("业务描述", e)`，不得只打 `e.getMessage()`。

### 1.4 Service 规范

**必须**：
- 方法名动词开头：`query` / `create` / `update` / `delete` / `handle` / `freeze`。
- 返回 `Boolean` 表示成败的，调用方必须判断，不得忽略。
- 多表写操作必须加 `@Transactional(rollbackFor = Exception.class)`。
- 涉及状态流转的方法，必须校验前置状态。

```java
@Transactional(rollbackFor = Exception.class)
public Boolean handleReport(Long id, String result, String note) {
    Report report = reportMapper.selectById(id);
    // 前置状态校验：已处理的举报不允许重复处理
    if (report == null || !"PENDING".equals(report.getStatus())) {
        return false;
    }
    report.setStatus(result);
    report.setHandleResult(note);
    report.setHandler(currentAdminNickname());
    report.setHandledAt(new Date());
    boolean updated = reportMapper.updateById(report) > 0;

    // 确认违规后封禁用户；封禁失败不回滚举报处理结果
    if (updated && "RESOLVED".equals(result) && report.getTargetUserId() != null) {
        try {
            adminUserService.freezeUser(report.getTargetUserId(), "举报违规：" + report.getReason());
        } catch (Exception e) {
            LOGGER.warn("举报 {} 封禁用户 {} 失败", id, report.getTargetUserId(), e);
        }
    }
    return updated;
}
```

**禁止**：
- Service 方法返回 `null` 表示失败（用 `Boolean` / `Optional` / 抛异常）。
- 在循环内调用 Mapper 或远程 API（N+1，见 `CONST-PERF-002`）。
- 用 `e.printStackTrace()`。

### 1.5 异常处理

**必须**：
- 每个对外服务必须有全局异常处理器（`CONST-API-004`）。
- 业务异常用自定义 `BusinessException(code, message)`（默认 code=400），由全局处理器转成 `Result<T>` 响应体。
- 系统异常记录 `LOGGER.error`，返回 500 且不暴露堆栈。

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    private static final Logger LOGGER = LoggerFactory.getLogger(GlobalExceptionHandler.class);

    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBiz(BusinessException e) {
        return Result.fail(e.getCode(), e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<Void> handleValid(MethodArgumentNotValidException e) {
        String msg = e.getBindingResult().getFieldErrors().stream()
                .map(fe -> fe.getField() + " " + fe.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return Result.fail(400, msg);
    }

    @ExceptionHandler(NoHandlerFoundException.class)
    public Result<Void> handle404(NoHandlerFoundException e) {
        return Result.fail(404, "接口不存在");
    }

    @ExceptionHandler(Exception.class)
    public Result<Void> handleUnknown(Exception e) {
        LOGGER.error("未捕获异常", e);
        return Result.fail(500, "服务异常，请稍后重试");
    }
}
```

### 1.6 日志规范

| 级别 | 使用场景 |
|------|----------|
| `ERROR` | 需要人工介入的异常（数据库故障、第三方不可用、数据不一致） |
| `WARN` | 可自愈但需关注（降级、重试、封禁失败） |
| `INFO` | 关键业务节点（登录、下单、支付确认、举报处理） |
| `DEBUG` | 调试信息，生产关闭 |

**必须**：
- 用占位符 `{}`，不用字符串拼接。
- 异常对象作为最后一个参数传入，保留堆栈：`LOGGER.error("查询失败 id={}", id, e)`。
- 禁止在日志中输出密码、Token、完整手机号（`CONST-SEC-006`）。

```java
// 好
LOGGER.warn("举报 {} 封禁用户 {} 失败", reportId, userId, e);

// 差
LOGGER.warn("举报 " + reportId + " 失败 " + e.getMessage());
```

### 1.7 事务规范

- `@Transactional` 只加在 Service 的 public 方法上。
- 必须指定 `rollbackFor = Exception.class`（默认只回滚 `RuntimeException`）。
- 事务内禁止调用远程接口（HTTP / MQ），否则事务时间不可控。
- 事务内禁止 `Thread.sleep`。

### 1.8 MyBatis-Plus 规范

```java
// 查询：显式指定条件
QueryWrapper<Report> wrapper = new QueryWrapper<>();
wrapper.eq("status", "PENDING")
       .eq(StringUtils.isNotBlank(targetType), "target_type", targetType)
       .orderByDesc("created");

// 更新：需要置 null 时用 UpdateWrapper
LambdaUpdateWrapper<User> wrapper = new LambdaUpdateWrapper<>();
wrapper.eq(User::getId, userId)
       .set(User::getStatus, "NORMAL")
       .set(User::getFreezeReason, null);
userMapper.update(null, wrapper);
```

**必须**：
- `updateById` 默认忽略 `null` 字段；要把字段置空必须用 `UpdateWrapper.set(field, null)`。
- 分页用 `Page<T>` + `PaginationInnerInterceptor`。
- 禁止 `SELECT *`（`CONST-DATA-006`）。
- 表前缀由全局配置 `table-prefix: tb_` 处理，实体类名不加 `Tb` 前缀。

### 1.12 接口契约（@HttpExchange）

```java

    @GetExchange("/{userId}")
    UserLocationVo queryByUserId(@PathVariable("userId") Long userId);
```

**必须**：

### 1.13 内部服务鉴权（X-Internal-Token）

域服务之间通过 `xfjy-server` 调用时，**必须**校验 `X-Internal-Token` 请求头，防未授权访问。

**链路**：
1. **网关层** (`xfjy-gateway`): `InternalTokenFilter` (GlobalFilter) 自动为所有转发请求注入 `X-Internal-Token` 头
2. **BFF层** (`xfjy-server`): `@LoadBalanced RestClient` 的 `defaultHeader` 自动携带 token
3. **域服务层** (8 个 `*-service`): `XInternalTokenInterceptor` (HandlerInterceptor) 校验 token

```java
// 域服务拦截器（每服务一份，放 interceptor/ 包）
@Component
public class XInternalTokenInterceptor implements HandlerInterceptor {
    @Value("${xfjy.internal.auth.tokens}") private String allowedToken;

    @Override
    public boolean preHandle(HttpServletRequest req, HttpServletResponse res, Object handler) {
        if (req.getRequestURI().startsWith("/actuator")) return true;  // 监控白名单
        if (!allowedToken.equals(req.getHeader("X-Internal-Token"))) {
            res.setStatus(403); return false;
        }
        return true;
    }
}

// 注册拦截器（放 config/WebMvcConfig.java）
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {
    @Autowired private XInternalTokenInterceptor tokenInterceptor;
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(tokenInterceptor).addPathPatterns("/**").excludePathPatterns("/actuator/**");
    }
}
```

**必须**：
- `application.yml` 配置 `xfjy.internal.auth.tokens`
- 白名单路径（`/actuator/**`）跳过校验
- 生产环境 token 必须替换为高强度随机值（32+ 字符）

### 1.14 可选中间件降级模式

Qdrant / Neo4j / LiveKit 等 P2 中间件**不部署时主链路不得中断**。所有客户端调用必须 try-catch 降级。

```java
@Service
public class RecommendService {
    @Value("${xfjy.qdrant.enabled:false}") private boolean qdrantEnabled;

    public List<Long> recallCandidates(Long userId) {
        if (!qdrantEnabled) return Collections.emptyList();
        try {
            return qdrantClient.searchSimilar(userId, 100).stream().map(ScoredPoint::getId).toList();
        } catch (Exception e) {
            LOGGER.warn("Qdrant 降级，userId={}", userId, e);
            return Collections.emptyList();  // 降级为空，主评分链路继续
        }
    }
}
```

**必须**：
- `@Value` 配 `enabled:false` 开关
- 调用包围 try-catch，catch 内**必须** log.warn（否则降级无迹可查）
- 降级返回值安全（空集合 / null / 保底数据），不得抛异常

### 2.4 状态管理（Pinia）

```ts
// stores/auth.ts
export const useAuthStore = defineStore('auth', () => {
  const token = ref(localStorage.getItem('xfjy_admin_token') || '')
  const adminInfo = ref<AdminInfo | null>(null)

  function hasRole(roles?: string[]) {
    if (!roles || roles.length === 0) return true
    const current = adminInfo.value?.role
    return current ? roles.includes(current) : false
  }

  async function logout() {
    try {
      await logoutApi()
    } catch {
      // 网络异常也要清本地
    } finally {
      token.value = ''
      adminInfo.value = null
      localStorage.removeItem('xfjy_admin_token')
      localStorage.removeItem('xfjy_admin_info')
    }
  }

  return { token, adminInfo, hasRole, logout }
})
```

**必须**：
- 使用 setup 语法定义 store。
- 跨页面共享的状态才放 store；页面局部状态用 `ref`。
- 禁止在 store 中直接操作 DOM。

#### 3.4.2 圆角必须用 SCSS 变量（强制）

`uni.scss` 已定义，`<style lang="scss">` 内直接引用：输入框 `$uni-border-radius-base`(16rpx)、卡片 `$uni-border-radius-lg`(24rpx)、弹窗 `$uni-border-radius-xl`(32rpx)、胶囊 `$uni-border-radius-pill`(999rpx)。

#### 3.4.3 暗色模式（强制）

新增样式必须通过引用 CSS 变量自动获得暗色变体；禁止写只有浅色表现的样式（如固定 `background: #fff`）。仅当变量无法覆盖时才写 `@media (prefers-color-scheme: dark)` 显式覆盖。

#### 3.4.4 设备适配与安全区（强制）

异形屏（iOS 刘海屏/灵动岛、Android 挖孔屏/水滴屏）的安全区避让规则，新页面/组件**必须**遵守：

**1. 顶部安全区（状态栏/刘海/挖孔）**

- `navigationStyle: custom` 页面：顶部内容必须动态避让，取 `uni.getWindowInfo().statusBarHeight`（px 单位），加设计间距后设为 padding-top；**禁止写死固定值**（如 `padding-top: 180rpx`）。
  ```html
  <!-- ✅ 正确：动态获取 -->
  <view class="header" :style="{ paddingTop: statusBarHeight + 20 + 'px' }">
  ```
  ```html
  <!-- ❌ 错误：固定值，刘海屏会遮挡 -->
  <view class="header" style="padding-top: 180rpx">
  ```
- 兜底值：`statusBarHeight` 取不到时用 `44`（iOS 刘海屏典型值）；Android 通常 24-48px。
- 原生导航栏页面（未设 custom）：状态栏由系统导航栏自动处理，**禁止重复加** paddingTop。
- 全屏沉浸式页面（视频页）：叠加浮层用 CSS 方案 `calc(env(safe-area-inset-top, 0px) + 间距)`。

**2. 底部安全区（Home 指示条/小黑条）**

- 必须用全局类 `.safe-area-bottom`（App.vue 已定义，constant+env 双写法）或 `calc(基础间距 + env(safe-area-inset-bottom, 0px))`。
- **禁止裸写 `env()` 不带 fallback**：`env(safe-area-inset-bottom)` 在不支持的设备上返回无效值，必须写 `env(safe-area-inset-bottom, 0px)`。
- 底部固定元素（操作栏/支付栏）与 H5 全局底栏的避让规则见 §3.7.2 第 6 条。

**3. iOS vs Android 差异**

| 维度 | iOS | Android |
|------|-----|---------|
| 顶部遮挡 | notch/灵动岛，`statusBarHeight` 44-59px | 挖孔/水滴，`statusBarHeight` 通常已含遮挡高度 |
| 底部指示条 | Home Indicator，`safe-area-inset-bottom` ≈34px | 多数无（手势导航机型部分有，值较小） |
| viewport | H5 端依赖 `viewport-fit=cover`（index.html 已动态注入，**禁止删除**） | 原生支持，无需额外配置 |
| constant() | iOS < 11.2 需 `constant()` 兼容 | 不需要，但双写法无害 |

- `constant()` + `env()` **双写法**（App.vue `.safe-area-bottom` 已示范）：先写 `constant(safe-area-inset-bottom)` 再写 `env(safe-area-inset-bottom, 0px)`，后者覆盖前者。

**4. 弹窗/抽屉/底部浮层**

- 底部抽屉（如评论抽屉、分享面板）内容区必须加底部安全区：`padding-bottom: calc(基础间距 + env(safe-area-inset-bottom, 0px))`。
- 顶部浮层（如断网提示条）fixed 定位时必须加 `top: env(safe-area-inset-top, 0px)`（原生导航栏页面 env 返回 0，不影响）。

**5. 横屏（预留）**

当前全站竖屏锁定。若未来开放横屏（视频页），需同时处理 `safe-area-inset-left/right`（刘海在侧边时）。

### 3.7 交互与视觉硬约束（迁自旧 CLAUDE.md，2026-11-03）

#### 3.7.1 标签与可点击元素

#### 3.7.2 按钮

1. 必须复用 `components/a11y-button.vue` 或 `u-button`，禁止新造按钮样式。
2. 固定四级层级：主填充（主色）、次描边、文本、危险（`$uni-color-error`）；同页主次一眼可辨，取消按钮不得比提交按钮醒目。

5. 表单提交按钮点击后立即 loading/禁用，禁止重复提交。
6. 底部固定操作栏：**禁用 `position: fixed`**（会被 H5 全局底栏遮挡），**禁用 `var(--window-bottom)`**（scoped 内可能为 0px）；用 `margin-top: auto` + 容器 `padding-bottom: calc(var(--tab-bar-height, 0px) + 间距)` 避让软键盘与安全区。
7. 一个卡片/一行操作按钮 ≤3 个；次要操作不做填充主按钮；悬浮按钮不遮挡列表内容与弹窗。
8. 品牌渐变只用 `$uni-gradient-primary`（`#fe3c72 → #ff655b`），禁止旧紫→粉渐变；主色白字仅用于大号/粗体，浅底小字用 `--color-primary-text`。

#### 3.7.3 表单、浮层、卡片

- label、必填星号、校验提示位置全站统一（提示固定字段下方，禁止上下飘动）。
- 输入框圆角/边框引用 `uni.scss`（输入框 `16rpx`）；键盘类型匹配（数字/验证码用 `type="number"` 与正确的 `confirm-type`）。
- 校验未通过前提交按钮保持禁用。
- 弹窗/抽屉/浮层优先 `a11y-dialog`、`uview-plus`；禁止写死宽高导致小屏溢出；长内容可滚动。
- 遮罩点击关闭、关闭按钮位置、按钮横/竖排全站统一。
- 下拉/级联/筛选浮层自动判断上下展开方向，不超出屏幕边界。
- 状态色只引用 Token（`$uni-color-success/warning/error`）；Tag/徽章大小圆角统一，长文本 `ellipsis`。
- 卡片圆角 `24rpx`（`$uni-border-radius-lg`）；禁止卡片套卡片、无差别套卡片。

#### 3.7.4 布局与间距

1. 间距只取刻度：`8/16/24/32/48rpx`（紧凑场景可用 8rpx），禁止 12、14、18 等随手值。
2. 同页元素左对齐基线一致；禁止左/居中/右随意切换。
3. 禁止硬编码宽高；必须验证小屏不溢出、大屏不空旷，兼容折叠屏。
4. 顶部避状态栏/刘海，底部避小黑条，全面屏不得裁切按钮。
5. 长文本截断；图片固定尺寸 + `mode` 防变形；数据条数变化不得错位。
6. 数据页必须有加载（`skeleton`）、空（`empty-state`）、错误（`error-boundary`）三态。

#### 3.7.5 生成结果黑名单（出现即返工）

- 主/次/取消按钮样式趋同，视觉层级失效
- 按钮小于 88rpx、热区拥挤、图标按钮难点
- 只有默认态，无禁用/loading/反馈；禁用按钮仍可点
- 底部按钮被软键盘、小黑条或弹窗遮挡
- 写死 px 宽高、小屏横向溢出、大量 `absolute` 拼页面
- 间距一页一个值、元素肉眼不对齐
- 状态色、主色硬编码且跨页面不一致
- 用 `view` 模拟按钮/下拉，无无障碍与键盘支持
- 长文本撑破布局、缺空/加载/错误三态
- 重复造已有组件、同业务组件跨页面不一致
- 新增 `uni-icons`、冒号类名、动态类名未 safelist、tabbar 改字体图标
- 表单可重复提交、点击无任何反馈

#### 3.7.6 输出前自检

按钮层级 → 热区 88rpx → 状态齐全 → 遮挡处理 → 全 rpx + flex → 间距刻度 → Token 引用 →
边界与三态 → 组件复用 → 图标 `i-ph-*` → `npm run type-check` 通过。

## 四、Git 与协作流程

### 4.1 分支模型

| 分支 | 用途 | 保护 |
|------|------|------|
| `main` | 生产分支，随时可发布 | 禁止直接 push |
| `develop` | 集成分支 | 禁止直接 push |
| `feature/<简述>` | 功能开发 | — |
| `fix/<简述>` | 缺陷修复 | — |
| `hotfix/<简述>` | 生产紧急修复，从 `main` 拉出 | — |

### 4.2 Commit 规范

格式：

```
<type>: <简述>

<可选正文>
```

`type` 取值：

| type | 用途 |
|------|------|
| `feat` | 新功能 |
| `fix` | 缺陷修复 |
| `refactor` | 重构（不改行为） |
| `docs` | 文档 |
| `chore` | 构建/依赖/配置 |
| `test` | 测试 |
| `perf` | 性能优化 |
| `style` | 格式（不影响逻辑） |

**必须**：
- 简述用中文，不超过 50 字。
- 一个 commit 只做一件事；跨模块的大改动必须拆。
- 关联需求时在正文写 `Refs: FR-ADMIN-04`。

示例：

```
fix: 举报确认违规后同步封禁被举报用户

- RESOLVED 时调用 freezeUser，封禁原因记录为「举报违规：<原因>」
- 封禁失败不回滚举报处理结果，仅记录告警

Refs: FR-ADMIN-04
```

### 4.3 提交前检查

**必须**执行（缺一不可）：

```powershell
# 1. 后端编译
mvn -pl xfjy-server -am -DskipTests compile

# 2. 前端构建
cd xfjy-admin; npm run build

# 3. 查看改动
git status --short
git diff
```

**禁止**：
- `git add .` 盲提交（必须先 `git status` 确认）。
- 提交 `node_modules`、`dist`、`.env`（含密钥）、IDE 配置。
- `git push --force`（除非明确要求且已备份）。
- `git reset --hard` / `git clean -fd`。

### 4.4 PR 要求

PR 描述必须包含：

```markdown
## 变更内容
- 一句话说明改了什么

## 关联需求
- FR-XXX-XX

## 验证方式
- [ ] 后端编译通过
- [ ] 前端构建通过
- [ ] 手测步骤与结果

## 风险与回滚
- 影响范围
- 回滚方式
```

**评审要求**：
- 至少 1 人 Approve。
- CI 必须全绿（配置后）。
- 涉及数据库变更必须附 SQL 与回滚 SQL。

## 五、测试规范

### 5.1 后端测试

**必须**：
- 新增/修改的 Service 方法必须有单元测试。
- 测试类命名 `<被测类>Test`，放 `src/test/java` 对应包下。
- 使用 JUnit 5 + Mockito，禁止依赖真实数据库（用 Mock）。
- 每个测试方法命名 `should_<预期>_when_<条件>` 或中文描述。

```java
@ExtendWith(MockitoExtension.class)
class AdminReportServiceTest {

    @Mock
    private ReportMapper reportMapper;

    @Mock
    private AdminUserService adminUserService;

    @InjectMocks
    private AdminReportService adminReportService;

    @Test
    void should_returnFalse_when_reportAlreadyHandled() {
        Report report = new Report();
        report.setStatus("RESOLVED");
        when(reportMapper.selectById(1L)).thenReturn(report);

        Boolean result = adminReportService.handleReport(1L, "RESOLVED", "note");

        assertFalse(result);
        verify(reportMapper, never()).updateById(any());
    }
}
```

**覆盖率目标**：
- 核心 Service ≥ 60%
- 整体 ≥ 40%

### 5.2 前端测试

**应该**：
- 工具函数（`utils/format.ts`）必须有 Vitest 单测。
- 关键交互（登录、举报处理、批量操作）用 Playwright 做 E2E。

```ts
// utils/format.spec.ts
import { describe, it, expect } from 'vitest'
import { formatDateTime } from './format'

describe('formatDateTime', () => {
  it('空值返回占位符', () => {
    expect(formatDateTime(null)).toBe('-')
  })
  it('裁剪秒', () => {
    expect(formatDateTime('2026-10-31 12:34:56')).toBe('2026-10-31 12:34')
  })
})
```

### 5.3 接口测试清单

以下链路必须有可重复执行的测试（Postman / REST Assured）：

| 链路 | 断言 |
|------|------|
| 后台登录 | 200 + Token + 角色 |
| 无 Token 访问后台 | 401 |
| OPERATOR 访问用户管理 | 403 |
| 举报处理 RESOLVED | 举报状态变更 + 用户 FROZEN |

| 公告发布 → C 端可见 | 状态 PUBLISHED + 列表包含 |

每次发版前必须手测：

| 场景 | 预期 |

## 附录 A：常见错误与正确写法

| 场景 | 错误写法 | 正确写法 |
|------|----------|----------|
| 更新字段为 null | `updateById` 设 null | `UpdateWrapper.set(field, null)` |
| 判断字符串空 | `str == ""` | `StringUtils.isBlank(str)` |
| 捕获异常 | `catch (Exception e) {}` | `catch (Exception e) { LOGGER.error(..., e); }` |
| 拼接日志 | `LOGGER.info("id=" + id)` | `LOGGER.info("id={}", id)` |
| 角色判断 | 前端隐藏按钮即认为安全 | 后端必须 `@RequireRole` |
| 分页参数 | `pagesize` / `size` | `pageSize` |
| 时间格式 | 各页面 `new Date().toLocaleString()` | `formatDateTime()` |
| 颜色 | `#6C5CE7` | `var(--xfjy-primary)` |
| 列表 key | `v-for="(item, i)" :key="i"` | `:key="item.id"` |
| 空数据 | 返回 0 或假数据 | 返回 `null` + 前端空态 |
| 批量操作 | 无条数限制 | 上限 100 条 |
| 图片上传 | 只校验大小 | 扩展名 + MIME + 大小 + 重命名 |
