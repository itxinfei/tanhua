## 一、产品概述

### 1.1 产品定位

心飞交友是一款面向年轻群体的**陌生人社交平台**（类陌陌/探探），通过 LBS 地理位置、智能推荐算法和实时互动，帮助用户发现附近有趣的人，建立社交连接。

### 1.2 目标用户

| 维度 | 描述 |
|------|------|
| 年龄 | 18-35 岁 |
| 场景 | 想拓展社交圈、结识附近新朋友的年轻用户 |
| 特征 | 移动端为主，注重颜值与兴趣匹配 |

### 1.3 核心价值

- **发现**：基于地理位置 + 协同过滤算法，精准推荐附近的人
- **互动**：圈子动态、小视频、即时聊天，多维度建立连接
- **匹配**：探花卡片左右滑动 + 陌生人问题，增加破冰趣味性
- **增值**：VIP 会员体系，付费解锁更多社交特权

### 1.4 非目标（明确不做）

以下内容**不在本产品范围内**，任何需求变更若要引入，必须先走变更评审：

| 非目标 | 说明 |
|--------|------|
| 直播 | 不做实时直播推流、直播多人连麦、打赏（1v1 音视频通话见 FR-IM-04，不属此列） |
| 电商/商城 | 不做实物交易、订单履约、物流 |
| 真实资金通道 | 当前仅沙箱支付，不接入支付宝/微信真实扣款 |
| 自研 IM | 消息通道采用开源自建 WuKongIM（私有化部署），不自研长连接与消息存储；音视频采用 LiveKit SFU，不自研媒体服务器 |
| 自研推送 | 不自研推送通道；实际直调极光 REST API v3（`PushService`，mock 兜底），场景化推送已实现（见 FR-SET-05），非自研豁免 |
| 多租户 | 单租户运营，不做 SaaS 多租户隔离 |
| 国际化 | 仅简体中文 + 国内手机号，不做多语言/多币种 |
| 内容自动审核 | 当前仅人工审核 + 敏感词命中，不做图像/视频 AI 审核 |

### 1.5 术语表

| 术语 | 含义 |
|------|------|
| BFF | xfjy-server，前端唯一后端入口，负责鉴权与聚合编排 |
| 域服务 | user / circle / video / match / message / pay / recommend / elasticsearch |
| 探花卡片 | C 端左右滑动浏览推荐用户卡片的交互形式 |
| 今日佳人 | 每日为当前用户计算的单个最佳匹配对象 |
| 混合评分 | PyTorch 双塔向量归一化（Qdrant Cosine）+ 距离衰减 + 画像相似度的加权得分（0~100） |
| 封禁 | 用户状态置 `FROZEN`，登录与关键接口被拦截 |
| 注销 | 用户状态置 `DELETED`，软删除，30 天后物理清理 |
| WuKongIM | 开源自建即时通讯服务（Apache-2.0），承担长连接、消息投递、离线消息与自定义信令 |
| LiveKit | 开源自建 WebRTC SFU（Apache-2.0），只做音视频媒体转发，客户端凭后端签发的短期 JWT 加入房间 |
| SFU | Selective Forwarding Unit，媒体服务器只转发不混流，1v1 通话与多人房间共用 |
| secure context | 浏览器安全上下文，HTTPS 或 localhost 才允许 `getUserMedia` 获取摄像头/麦克风 |

## 四、功能需求

> 约定：
> - `P0` = 核心链路，缺失即产品不可用；`P1` = 重要，缺失影响体验；`P2` = 增强，可延后。
> - 每条需求至少 1 条 Given/When/Then 验收标准，可直接转成测试用例。
> - 接口路径均为网关后的路径（网关会按前缀转发）。

### 4.1 用户账户模块

#### FR-AUTH-01 注册/登录（SSO 服务） · P0

- **描述**：用户通过手机号 + 短信验证码完成注册或登录。
- **规则**：
  - 新手机号自动注册并创建 `tb_user` 记录。
  - 登录成功由 Sa-Token 签发 Token（`StpUtil.login()`），Token 存 Redis 共享会话，后续请求通过 `Authorization: Bearer <token>` 携带。
  - Token 校验由各服务 `SaInterceptor` 统一拦截，`@SaIgnore` 标记免登录接口；所有服务共享同一 Redis 即可校验，无需回调 SSO。
  - 已注销（`DELETED`）用户禁止登录；已封禁（`FROZEN`）用户禁止登录并提示封禁原因。
- **验收标准**：
  - Given 一个新手机号，When 提交正确验证码，Then 创建 `tb_user` 记录并返回 Token，状态为 `NORMAL`。
  - Given 已封禁用户，When 尝试登录，Then 返回 403 且提示封禁原因，不签发 Token。
  - Given 已注销用户，When 尝试登录，Then 返回 403，不签发 Token。
  - Given 无 Token 请求受保护接口，When 调用 `GET /users`，Then 返回 401。

#### FR-USER-01 用户资料读取 · P0

- **接口**：`GET /users?userID=&huanxinID=`
- **描述**：查询用户资料，支持按用户 ID 或 IM 账号查询（`huanxinID` 为历史参数名，取值即 WuKongIM `uid`，保留以兼容存量前端）。
- **字段**：昵称、头像、性别、生日、城市、学历、婚姻状态、收入、行业、个性签名、照片列表。
- **验收标准**：
  - Given 存在用户 A，When 按 `userID` 查询，Then 返回 A 的完整资料，手机号做脱敏（中间 4 位掩码）。
  - Given 不存在的用户 ID，When 查询，Then 返回 404。

#### FR-USER-02 用户资料更新 · P0

- **接口**：`PUT /users`
- **描述**：更新当前登录用户资料，更新后清除用户缓存（`@CacheEvict`）。
- **验收标准**：
  - Given 用户已登录，When 修改昵称并提交，Then 资料更新成功且 `userInfo::id` 缓存被清除。
  - Given 用户 A 已登录，When 尝试修改用户 B 的资料，Then 返回 403。

#### FR-USER-03 关系统计 · P0

- **接口**：`GET /users/counts`
- **描述**：统计互相喜欢数、喜欢数（我关注）、粉丝数。
- **验收标准**：
  - Given 用户 A 有 2 个互关、3 个关注、5 个粉丝，When 查询统计，Then 返回 `{mutual:2, like:3, fans:5}`。

#### FR-USER-04 关系列表 · P0

- **接口**：`GET /users/friends/{type}?page=&pagesize=&nickname=`
- **type 定义**：1=互相关注，2=我关注，3=粉丝，4=谁看过我。
- **支持**：按昵称模糊搜索、分页。
- **验收标准**：
  - Given 用户 A 有 10 个粉丝，When 请求 `type=3&page=1&pagesize=5`，Then 返回 5 条且 `total=10`。
  - Given 昵称关键词"小"，When 带 `nickname=小` 查询，Then 只返回昵称包含"小"的用户。

#### FR-USER-05 取消喜欢 · P1

- **接口**：`DELETE /users/like/{uid}`
- **验收标准**：
  - Given 用户 A 喜欢过 B，When A 取消喜欢，Then B 从 A 的关注列表移除，互关关系同步解除。

#### FR-USER-06 关注粉丝 · P1

- **接口**：`POST /users/fans/{uid}`
- **验收标准**：
  - Given 用户 A 未关注 B，When A 关注 B，Then B 的粉丝数 +1，A 的关注数 +1。

#### FR-USER-07 注销账号 · P1

- **接口**：`POST /users/logoff`（body: `code`）
- **规则**：
  - 校验短信验证码：Redis 缓存验证码，或开发环境万能验证码 `DEV_MASTER_CODE`。
  - 软删除：`tb_user.status = DELETED`，数据保留 30 天后由定时任务清理。
  - 立即踢下线：Sa-Token 按 `userId` 注销所有会话（`StpUtil.logout()`）。
  - 已注销账号登录拦截：sso 登录 / Token 校验拦截 `DELETED` 状态用户。
- **验收标准**：

- **评分规则（圈子）**：

| 行为类型 | type | 评分 |
|----------|------|------|
| 发布动态 | 1 | 1~3 分（按文字长度）+ 图片数量加分 |
| 浏览动态 | 2 | +1 |
| 点赞 | 3 | +5 |
| 喜欢 | 4 | +8 |
| 评论 | 5 | +10 |
| 取消点赞 | 6 | -5 |
| 取消喜欢 | 7 | -8 |

- **存储**：按日分集合写入 MongoDB（`recommend_quanzi_yyyyMMdd` / `recommend_video_yyyyMMdd`）。
- **验收标准**：
  - Given 收到 type=5 评论消息，When 消费，Then 对应用户当日集合分数 +10。
  - Given 消费者抛出异常，When 消息重投，Then 不产生重复计分（幂等键 = `publishId + userId + type + date`）。

#### FR-ENGINE-02 推荐排序（xfjy-server 混合评分，Spark ALS 已退役，当前 PyTorch 双塔 + Neo4j） · P1

- **算法**：混合评分 = Qdrant 向量召回（双塔 Cosine, 64 维, pointId=userId）× w1 + Neo4j 二度好友扩散 × w2 + Haversine 距离衰减 × w3 + 画像相似度（tags Jaccard + 年龄差 + 同城）× w4；数据缺失维度自动降级，权重 YML 可配，enabled:false 时整段降级。
- **数据源**：Qdrant（PyTorch 双塔产出）+ Neo4j（好友关系 + 二度好友 + 共同好友）+ ES 位置 + MySQL 画像。
- **产出**：推荐列表 / 探花卡片按混合缘分值（0~100）降序排序。
- **演进**：阶段 2 双塔模型（行为 > 1000 条 / 用户 > 50 后渐进启用）。
- **验收标准**：
  - Given 三个维度数据齐全，When 计算缘分值，Then 结果落在 0~100 且按权重单调。
  - Given 距离数据缺失，When 计算，Then 自动降级为其余两维加权，不抛异常。
  - Given 修改 YML 权重，When 重启，Then 新权重生效。

#### FR-ENGINE-03 ID 生成（circle-service / video-service 各内嵌一份 IdService） · P1

- **方式**：Redis 自增 + Hashids 混淆。
- **键**：`XFJY_HASH_ID_` / `XFJY_ID_`。
- **用途**：生成动态、视频等业务 ID（两服务各自生成，键按 type 隔离互不冲突）。
- **验收标准**：
  - Given 并发 1000 次生成 ID，When 完成，Then 无重复且均为合法 Hashids 字符串。
  - Given Redis 重启且未持久化，When 生成 ID，Then 不得产生与历史冲突的 ID（需持久化或启动校准）。
  - 现行保障：compose 已开 `--appendonly yes`（持久化达标）；「启动校准」机制未实现，依赖 AOF 不丢，需在技术约束中固化该前提。

#### FR-ENGINE-04 向量/图召回组件（Qdrant + Neo4j，v3.0 成文：v2.5 已写码但未入需求） · P2

- **实现**：`xfjy-server/vector/QdrantClient`（互惠匹配向量召回）、`xfjy-server/graph/Neo4jClient`（二度好友推荐），均 `xfjy.qdrant.enabled / xfjy.neo4j.enabled` 默认 `false`；enabled=true 但组件不可用时 try-catch 静默降级，不影响主推荐链路。
- **规则**：生产开启前须完成数据回填方案（向量库与图库的初始化来源、更新触发点）与口径定义，本文档先行登记，开启须走变更评审。
- **验收标准**：
  - Given enabled=false，When 请求推荐，Then 组件零调用、结果与现状一致。
  - Given enabled=true 且 Qdrant 宕机，When 请求推荐，Then 主链路正常返回（降级），仅告警日志。

### 4.11 VIP 会员 / 支付模块（xfjy-pay-service）

#### FR-PAY-01 VIP 套餐查询 · P0

- **接口**：`GET /users/vip/packages`
- **描述**：查询上架的 VIP 套餐列表（月卡/季卡/年卡）。
- **数据**：`tb_vip_package`（`name`/`level`/`price`/`original_price`/`duration_days`/`description`/`status`/`sort`）。
- **验收标准**：
  - Given 有 3 个上架套餐，When 查询，Then 按 `sort` 升序返回 3 个，不含下架套餐。

#### FR-PAY-02 创建支付订单 · P0

- **接口**：`POST /users/vip/order`（body: `packageId`）
- **规则**：
  - 订单号：`VIP` + `yyyyMMdd` + 6 位序列（Redis 自增）。
  - 初始状态 `PENDING`，过期时间 = 下单后 30 分钟。
  - `order_no` 唯一约束。
- **验收标准**：
  - Given 用户选择有效套餐，When 下单，Then 返回 `orderNo`，`tb_pay_order` 新增 `PENDING` 记录，`expire_time` 为 30 分钟后。
  - Given 套餐已下架，When 下单，Then 返回 400。
  - Given 同一用户连续下单，When 生成订单号，Then 订单号不重复。

#### FR-PAY-03 模拟支付确认（沙箱） · P0

- **接口**：`POST /users/vip/pay/confirm`（body: `orderNo`）
- **规则**：
  - 校验订单存在、属于本人、状态允许、未过期。
  - 订单状态 → `PAID`，记录 `paid_time`。
  - 开通/续费 VIP：写入/更新 `tb_user_vip`。
  - **续费顺延**：已有 VIP 未到期时，新有效期 = 旧到期时间 + 套餐天数（非从当前时间起算）。
  - **等级保留**：续费低等级套餐时保留已达到的最高等级。
- **验收标准**：
  - Given 订单 `PENDING` 且未过期，When 确认支付，Then 状态变 `PAID`，VIP 到期时间按规则顺延。
  - Given 订单已过期，When 确认支付，Then 返回 400 且状态置 `EXPIRED`。
  - Given 用户当前 VIP 11-24 到期，When 购买 30 天月卡，Then 新到期时间为 12-24。
  - Given 用户已 3 级，When 购买 1 级月卡，Then 等级仍为 3。
  - Given 订单属于他人，When 确认支付，Then 返回 400（与「订单不存在」同一响应，避免订单号枚举）。

#### FR-PAY-04 VIP 状态查询 · P0

- **接口**：`GET /users/vip/status`
- **数据**：`tb_user_vip`（`user_id` 唯一约束）。
- **验收标准**：
  - Given 用户 VIP 未过期，When 查询，Then 返回 `level` 与 `expire_time`。
  - Given 用户 VIP 已过期，When 查询，Then 返回 `level=0`。

#### FR-PAY-05 订单详情查询 · P1

- **接口**：`GET /users/vip/order/{orderNo}`
- **验收标准**：
  - Given 订单属于当前用户，When 查询，Then 返回订单详情。
  - Given 订单属于他人，When 查询，Then 返回 404（不区分「不存在」与「非本人」，防枚举探测）。

#### FR-ADMIN-01 管理员登录 · P0

- **接口**：`POST /admin/login`（body: `username` + `password`）
- **数据**：`tb_admin`
- **描述**：登录成功返回 Token + 角色 + 昵称，前端按角色过滤菜单与按钮。
- **规则**：
  - 密码以 **BCrypt** 存储（v2.4 起由 MD5 迁移，验收标准以 `passwordEncoder.matches` 为准；本文此前"MD5 存储"表述为文档滞后，已修正）。
  - `status=DISABLED` 的管理员禁止登录。
  - 登录失败统一返回 401 + "账号或密码错误"，不区分账号不存在/密码错误。
- **验收标准**：
  - Given 正确账号密码且状态 `NORMAL`，When 登录，Then 返回 Token 与角色，前端进入看板。
  - Given 密码错误，When 登录，Then 返回 401，不泄露账号是否存在。
  - Given 账号 `DISABLED`，When 登录，Then 返回 403。
  - Given 未登录，When 访问任意后台页面，Then 重定向 `/login`。

#### FR-ADMIN-02 用户管理 · P0

- **用户列表**：`GET /admin/users`（分页/搜索：关键词手机号或昵称、性别、状态、VIP、注册时间范围）
- **行内操作**：封禁 / 解封 / 重置密码；支持批量封禁解封、导出。
- **用户详情弹窗 Tab**：
  - **基本信息**：头像、昵称、性别、年龄、城市、手机号、VIP 等级、账号状态、注册时间、最后活跃、签名、封禁原因。
  - **数据统计**：动态数、粉丝数、关注数、匹配数、被举报数、VIP 等级。
  - **照片墙**：个人相册（Mongo `quanzi_album`）缩略图网格，点击大图预览。
  - **个人标签**：用户标签列表。
  - **聊天记录**：`GET /admin/users/{id}/chat-sessions`（会话列表）/ `GET /admin/users/{id}/chat-messages?contactId=&pageSize=`（历史消息，走 WuKongIM 通道，cursor 游标翻页，一次 50 条）。
  - **发送的图片和视频**：复用 `GET /admin/movements?userId=` / `GET /admin/videos?userId=` / `GET /admin/comments?userId=`。
  - **被举报记录**：`GET /admin/reports?targetUserId=`。
  - **账号操作**：封禁（必填原因）/ 解封 / 重置密码。
- **验收标准**：
  - Given 运营在列表搜索手机号，When 提交，Then 只返回匹配用户。
  - Given 运营封禁用户并填原因，When 提交，Then 用户状态变 `FROZEN`，封禁原因落库，该用户立即无法登录。
  - Given 运营解封用户，When 提交，Then 状态变 `NORMAL` 且封禁原因被清空。
  - Given 运营重置用户密码，When 提交，Then 该用户旧 Token 失效，需重新登录。（⚠ 当前实现不满足：仅写 `md5("123456")` 不踢会话，见 11.7-16）
  - Given `OPERATOR` 登录，When 访问 `/user/list`，Then 菜单不可见且直接访问返回 403。
  - Given 用户被举报 3 次，When 打开详情「被举报记录」Tab，Then 展示 3 条含证据图与处理状态。

#### FR-ADMIN-03 内容管理 · P0

- **动态管理**：`GET /admin/movements`（分页 / 按 `userId` / 关键词）/ `DELETE /admin/movements/{publishId}`（下架）
- **视频管理**：`GET /admin/videos` / `DELETE /admin/videos/{videoId}`
- **评论管理**：`GET /admin/comments` / `DELETE /admin/comments/{commentId}`
- **描述**：内容列表 + 详情弹窗（动态含图片视频预览、视频可播放）+ 删除下架；补审核状态流转、可见范围（`seeType`）列与筛选、举报数列、批量操作、软删除。
- **验收标准**：
  - Given 运营下架一条动态，When 确认，Then 该动态在 C 端不可见，后台列表标记为已删除。
  - Given 运营批量下架 3 条评论，When 确认，Then 3 条同时标记删除，操作日志记录 3 条或 1 条批量记录。
  - Given 动态含 4 张图片，When 打开详情，Then 4 张均可预览，视频可播放。

#### FR-ADMIN-04 审核中心 · P0

- **内容审核**：`GET /admin/reviews`（待审核列表）/ `PUT /admin/reviews/{id}/approve` / `PUT /admin/reviews/{id}/reject` / `PUT /admin/reviews/batch-approve|batch-reject`
- **举报处理**：`GET /admin/reports` / `GET /admin/reports/{id}` / `PUT /admin/reports/{id}/handle` / `PUT /admin/reports/batch-handle`
- **描述**：
  - 审核工作台为队列式作业：键盘快捷键（A 通过 / R 驳回 / ←→ 上下条）、详情抽屉（长文 + 视频播放 + 大图预览）、处理后自动下一条、跨页批量、回显审核人 / 驳回原因。
  - 举报详情弹窗渲染证据图组、按 `targetType` 展示被举报内容本体、处理方式含警告/删内容/限时封禁/永封 + 强制备注。
- **验收标准**：
  - Given 待审核队列有 10 条，When 按 A 通过当前条，Then 状态变 `APPROVED`，自动跳到下一条。
  - Given 审核驳回，When 未填驳回原因，Then 提交被拦截并提示必填。
  - Given 举报 `PENDING`，When 选择「确认违规」，Then 举报状态变 `RESOLVED`，被举报用户被立即封禁，封禁原因记录为「举报违规：<举报原因>」。
  - Given 举报 `PENDING`，When 选择「驳回举报」，Then 状态变 `DISMISSED`，用户状态不变。
  - Given 举报已处理，When 再次处理，Then 返回 400，不覆盖首次结果。
  - Given 批量处理 5 条举报为 `RESOLVED`，When 确认，Then 5 条均变 `RESOLVED`，对应目标用户均被封禁。
  - Given 封禁目标用户失败（如用户不存在），When 处理举报，Then 举报处理结果仍成功，仅记录告警日志。

#### FR-ADMIN-05 运营管理 · P1

- **公告管理**：`GET/POST/PUT/DELETE /admin/notices` + `PUT /admin/notices/{id}/publish|offline`（发布 / 下线）；支持 `OFFLINE` 重新发布、内容预览。
- **VIP 套餐**：`GET/POST/PUT /admin/vip/packages` + `PUT /admin/vip/packages/{id}/status`（上下架）+ `GET/PUT /admin/vip/benefits`（权益）。
- **支付订单**：`GET /admin/pay-orders`（分页 / 时间范围 / 订单号）；补汇总、导出、订单号复制。
- **敏感词库**：`GET/POST/PUT/DELETE /admin/sensitive-words` + `PUT /admin/sensitive-words/refresh`（刷新）；补批量导入导出、命中测试框。
- **协议管理**：`GET/POST/PUT/DELETE /admin/agreements` + `PUT /admin/agreements/{id}/publish|offline`；支持按标题搜索。
- **验收标准**：
  - Given 公告为 `DRAFT`，When 点发布，Then 状态变 `PUBLISHED` 且 C 端公告列表可见。
  - Given 公告为 `PUBLISHED`，When 点下线，Then 状态变 `OFFLINE` 且 C 端不可见。
  - Given 公告为 `OFFLINE`，When 点重新发布，Then 状态回到 `PUBLISHED`。
  - Given 公告列表，When 查看创建时间，Then 显示 `YYYY-MM-DD HH:mm`，不出现空白。
  - Given 协议管理输入标题关键词，When 搜索，Then 列表按标题过滤。
  - Given 敏感词批量导入 100 条，When 完成，Then 返回成功/失败条数，失败项给出原因。
  - Given 支付订单按时间范围筛选，When 提交，Then 只返回范围内订单，汇总金额与明细一致。

#### FR-ADMIN-06 客服中心 · P1

- **FR-ADMIN-06a 客服工作台**：`GET /admin/kefu/agent/credential`（按登录人下发 WuKongIM 连接凭证）+ `POST /admin/kefu/users/info`（查用户信息）；前端用 WuKongIM SDK 拉会话列表与历史消息。
- **FR-ADMIN-06b 用户反馈**：`GET /admin/kefu/feedback` / `PUT /admin/kefu/feedback/{id}/reply`（回复）/ `PUT /admin/kefu/feedback/{id}/close`（关闭）。
- **FR-ADMIN-06c FAQ 管理**：`GET/POST/PUT/DELETE /admin/kefu/faq` + `PUT /admin/kefu/faq/{id}/status`（启停）。
- **描述**：多客服独立 WuKongIM uid（凭证按登录人下发）、已读回执、历史消息分页、图片/语音消息占位展示。
- **验收标准**：
  - Given 客服 A 登录工作台，When 获取凭证，Then 返回 A 专属 WuKongIM uid，不是硬编码 `kefu0001`。
  - Given 反馈状态 `0`（待处理），When 客服回复，Then 状态变 `1`（已回复），回复内容落库。
  - Given 反馈状态 `1`，When 客服再次回复，Then 允许再次回复，状态保持 `1`。
  - Given 反馈状态 `2`（已关闭），When 客服尝试回复，Then 按钮不可见/接口返回 400。
  - Given `OPERATOR` 登录 FAQ 页，When 查看开关，Then 开关置灰不可操作，增删改按钮不可见。
  - Given `OPERATOR` 登录用户反馈页，When 回复/关闭，Then 操作成功（允许）。

#### FR-ADMIN-07 系统管理 · P1

- **管理员管理**：`GET/POST/PUT /admin/accounts` + `PUT /admin/accounts/{id}/status`（禁用/启用）+ `PUT /admin/accounts/{id}/reset-password`（重置，重置后强制下线）；仅 `SUPER_ADMIN`。
- **操作日志**：`GET /admin/operation-logs`（分页 / `action` 筛选）；补详情弹窗、导出、日期快捷项。
- **规则**：
  - 不允许禁用 `SUPER_ADMIN`。
  - 不允许自我降级、自我禁用。
  - 重置密码后强制该账号所有会话失效。
  - 操作日志只记录**成功的写操作**（`ResponseEntity` 2xx），失败请求不落库。
  - 操作对象 ID 只从 URI 的纯数字路径段提取，批量接口无 ID 时置空。
- **验收标准**：
  - Given `SUPER_ADMIN` 编辑自己并改为 `ADMIN`，When 提交，Then 返回 400 并提示「不能修改自己的角色」。
  - Given `SUPER_ADMIN` 禁用自己，When 提交，Then 返回 400 并提示「不能禁用自己的账号」。
  - Given `ADMIN` 访问管理员管理，When 请求，Then 返回 403。
  - Given 重置某管理员密码，When 成功，Then 该管理员旧 Token 立即失效。
  - Given 一次写操作返回 500，When 查看操作日志，Then 不产生该条日志。
  - Given 请求 `PUT /admin/users/123/freeze`，When 记录日志，Then `targetId=123` 而非 `freeze`。
  - Given 按「支付管理」筛选，When 查询，Then 命中 `module=PAY_ORDER` 的日志（兼容历史 `PAY`）。

#### FR-ADMIN-08 数据看板 · P1

- **接口**：`GET /admin/dashboard/overview` / `trend` / `gender-ratio` / `age-distribution`
- **描述**：运营数据看板。首屏只展示有真实数据源的指标：总用户数、今日新增（含较昨日差值）、待审核内容、待处理举报、新增用户趋势、性别构成、年龄分布。
- **规则**：
  - 无统计源的指标（DAU / 匹配成功率 / 付费转化率 / 动态总数）**不得占位**：不渲染空卡片、空图表，仅在页面内用一行说明告知口径，**不得用 0 或随机数伪造曲线**。
  - 后端对应字段继续返回 `null`；前端不得回退到 mock 数据（含开发环境）。
  - 任一接口失败时必须给出可见提示与重试入口，不得静默显示 0。
  - ECharts 实例必须复用并正确 dispose，容器尺寸变化（窗口缩放 / 侧边栏折叠）必须自适应。
- **验收标准**：
  - Given DAU 无数据源，When 打开看板，Then 首屏不出现 DAU 卡片或空图表，仅出现「暂无统计源」说明文字。
  - Given 新增用户有真实数据，When 切换近 7 天 / 近 30 天，Then 曲线随区间变化且不闪白（实例复用）。
  - Given 今日与昨日均有新增用户，When 渲染 KPI，Then 展示「较昨日 +N / -N」，N 由趋势数据最后两天相减得出。
  - Given 点击「待审核内容」卡片，When 点击，Then 跳转 `/audit/review`；点击「待处理举报」跳转 `/audit/report`。
  - Given 某接口返回 500，When 打开看板，Then 顶部出现失败提示与「重新加载」，其余模块正常展示。
  - Given 折叠侧边栏，When 过渡结束，Then 所有图表自适应容器宽度，无横向滚动条。
  - Given 看板页面反复进出 10 次，When 检查内存，Then ECharts 实例数不持续增长。
  - Given 左侧菜单「数据看板」为当前页，When 渲染，Then 菜单项高亮（不出现 `//dashboard` 拼接错误）。

#### FR-ADMIN-09 用户资料编辑 · P1

- **修改用户资料**：`PUT /admin/users/{userId}/profile`（可编辑字段：`nickName`、`sex`、`age`、`city`、`birthday`、`signature`、`tags`、`industry`、`income`、`marriage`、`height`、`edu`）
- **替换用户头像**：`PUT /admin/users/{userId}/avatar`（请求体传 MinIO 图片 URL；后端校验 URL 属本站桶且图片可访问）
- **删除相册单张照片**：`DELETE /admin/users/{userId}/photos/{photoId}`（从 `tb_user_info.photo_album` JSON 数组移除单张，软删除标记）
- **不可编辑字段**：`mobile`（走 C 端换绑流程）、VIP 等级（走支付/后台赠送流程）、`status`（走封禁/解封）
- **写路径**：xfjy-server → user-service API → `tb_user_info`；**严禁后台直写**（遵守 6.1 数据归属）
- **缓存失效**：修改成功后清除 Redis `userInfo::{userId}` 缓存，C 端下次请求读到新值
- **审计**：每笔修改落 `tb_operation_log`（module=`USER_PROFILE`，detail 记录字段级旧值→新值，敏感字段脱敏）
- **验收标准**：
  - Given `ADMIN` 修改用户昵称，When 提交，Then `tb_user_info.nick_name` 更新，Redis `userInfo::{id}` 被清除，操作日志记录旧昵称→新昵称。
  - Given `OPERATOR` 调用 `PUT /admin/users/{id}/profile`，When 提交，Then 返回 403。
  - Given 请求体含 `mobile` 字段，When 提交，Then 该字段被忽略并返回警告（不可编辑字段）。
  - Given 替换头像传入非法 URL（非本站桶），When 提交，Then 返回 400。
  - Given 删除相册第 3 张照片，When 确认，Then `photo_album` 数组长度减 1，C 端相册不再展示该照片，操作日志记录被删 URL。

#### FR-ADMIN-10 用户媒体与内容编辑 · P1

- **修改动态文字**：`PUT /admin/movements/{publishId}`（请求体 `text`；敏感词过滤复用现有引擎）
- **移除动态单张媒体**：`DELETE /admin/movements/{publishId}/medias/{mediaIndex}`（`medias` 数组按索引移除单张图片或视频；移除后若 `medias` 为空且 `text` 为空则整条软删除）
- **修改视频信息**：`PUT /admin/videos/{videoId}`（可编辑字段：`text`、`picUrl` 封面）
- **软删除策略**：所有删除操作标记软删除，C 端查询过滤，保留 30 天后由定时任务物理清理（复用 6.6 保留策略）
- **写路径**：xfjy-server → circle-service API（动态/相册）/ video-service API（视频）；**严禁后台直写 Mongo**（遵守 6.1 数据归属）
- **审计**：每笔操作落 `tb_operation_log`（module=`CONTENT_EDIT`，detail 记录目标 ID + 操作类型 + 操作前内容快照/媒体 URL）
- **验收标准**：
  - Given 动态含 4 张图，When 移除第 2 张，Then `medias` 数组长 3，C 端该动态展示 3 张图，操作日志记录被移除的媒体 URL。

  - Given `OPERATOR` 调用 `PUT /admin/movements/{id}`，When 提交，Then 返回 403。
  - Given 视频封面被替换，When C 端加载视频流，Then 展示新封面，操作日志记录旧→新封面 URL。
  - Given 软删除的动态，When 30 天后定时任务执行，Then 物理清理该文档，清理数与软删除标记数一致。

### 4.15 新手任务与成长体系模块（Phase 2 · Phase 3 · xfjy-server）

> 详细设计见 `docs/需求文档/14-PRD-Phase2-新手任务与积分体系.md` 和 `docs/需求文档/17-PRD-Phase3-邀请好友得VIP.md`。

#### FR-GROWTH-01 新手 7 日任务 + 积分体系 · P1

- **描述**：新用户注册后触发 7 日任务流（完善资料/发布首发动态/首次滑动等），完成任务获取积分。积分**不兑换积分商城商品**，仅向 VIP 兑换通道开放：消耗 50 积分换主题皮肤（限时 7 天）、消耗 100 积分换 3 天 VIP、消耗 150 积分换 7 天 VIP（详见 PRD 14 §2）。积分独立于创作者等级和用户积分体系。
- **积分获取途径**：完成新手任务 + 每日签到 + 发布动态 + 被点赞/被关注。
- **任务进度状态**：`0=未完成 / 1=可领取 / 2=已完成 / 3=已过期`（过期后不可补领）。
- **验收标准**：
  - Given 新用户首次完成资料填充，When 通过任务，Then 获得 50 积分 + 任务状态变"已完成"。
  - Given 用户次日签到，When 完成任务，Then +10 积分（连续签到递增）。

#### FR-GROWTH-02 邀请好友得 VIP · P1

- **描述**：邀请体系按邀请人数分 4 阶梯奖励（铜/银/金/钻），邀请人和被邀请人均可获 VIP/超级喜欢/Boost 奖励。奖励与 VIP 等级体系（FR-PAY-01）联动。
- **阶梯**：铜牌（1人）→ 银牌（3人）→ 金牌（10人）→ 钻石（50人），每阶梯奖励叠加。
- **反作弊**：同设备指纹 24h 内多次注册不计为有效邀请；被邀请人注销账号时，触发 VIP 扣回流程（定时任务 02:00 + 触发式回滚）。
- **邀请记录状态**：`0=点击 / 1=注册完成 / 2=奖励已发 / 3=已失效/扣回`。
- **验收标准**：
  - Given A 邀请 B 注册完成，When 落库，Then tb_invite 记录 status=1 且双方获得铜牌奖励。
  - Given B 账号被注销（反作弊触发），When 定时任务执行，Then A 的 VIP 奖励被扣回 + 记录 status=3。

| NFR-AVAIL-02 | 域服务不可用时，BFF 返回降级数据而非 500 | P1 |
| NFR-AVAIL-03 | 所有容器配置 healthcheck，异常自动重启 | P1 |

**验收标准**：
- Given 停掉 xfjy-match-service，When 请求今日佳人，Then 返回默认推荐用户，HTTP 200。

### 5.3 安全

| 编号 | 要求 | 优先级 |
|------|------|--------|
| NFR-SEC-01 | 所有受保护接口必须校验 Token，未登录返回 401 | P0 |
| NFR-SEC-02 | 后台接口必须校验角色，越权返回 403 | P0 |
| NFR-SEC-03 | 用户只能操作自己的资源（越权访问他人资料返回 403；他人订单返回 404 防枚举） | P0 |

| NFR-SEC-05 | 日志不得输出明文密码、Token、完整手机号、身份证 | P1 |
| NFR-SEC-06 | 上传文件必须校验类型与大小（图片 ≤ 10MB，视频 ≤ 100MB） | P1 |
| NFR-SEC-07 | 富文本（公告/协议）渲染前必须 sanitize，防 XSS | P1 |
| NFR-SEC-08 | 登录接口需限流，防暴力破解（同 IP 每分钟 ≤ 10 次） | P1 |
| NFR-SEC-09 | 风控阈值基线（v2.9 成文，代码为准）：SSO 三层防线（IP 60s/10 次、账号连错 5 次锁 15 分钟、同手机号发码 60s/1 次）；BFF 发布 5 次/60s、评论 10 次/60s（失败也计数） | P1 |

## 七、状态机汇总

### 7.1 用户状态（`tb_user.status`）

```
注册 ──▶ NORMAL ──封禁──▶ FROZEN
           │                 │
           │◀────解封────────┘
           │
        注销
           ▼
        DELETED（终态，不可恢复）
```

| 当前状态 | 事件 | 目标状态 | 触发方 |
|----------|------|----------|--------|
| — | 注册 | NORMAL | SSO |
| NORMAL | 后台封禁 / 举报确认违规 | FROZEN | ADMIN / SUPER_ADMIN / OPERATOR（举报） |
| FROZEN | 后台解封 | NORMAL | ADMIN / SUPER_ADMIN |
| NORMAL | 用户注销 | DELETED | 用户本人 |
| DELETED | 任意 | 不允许 | — |

### 7.2 举报状态（`tb_report.status`）

```
PENDING ──开始处理──▶ PROCESSING ──确认违规──▶ RESOLVED
   │                      │
   └──────────────────────┴──驳回/无违规──▶ DISMISSED
```

| 当前状态 | 事件 | 目标状态 |
|----------|------|----------|
| PENDING | 打开详情 | PROCESSING |
| PENDING / PROCESSING | 确认违规（含批量） | RESOLVED |
| PENDING / PROCESSING | 驳回（含批量） | DISMISSED |
| RESOLVED / DISMISSED | 任意处理 | 拒绝，返回 400 |

> `RESOLVED` 时若 `targetUserId` 非空，自动封禁该用户；封禁失败不影响举报处理结果。

### 7.3 内容审核状态（`tb_review.status`）

```
PENDING ──通过──▶ APPROVED
   │
   └──驳回──▶ REJECTED
```

| 当前状态 | 事件 | 目标状态 |
|----------|------|----------|
| PENDING | 通过（含批量） | APPROVED |
| PENDING | 驳回（含批量，必填原因） | REJECTED |
| APPROVED / REJECTED | 再次审核 | 拒绝 |

### 7.4 公告 / 协议状态（`tb_notice.status` / `tb_agreement.status`）

```
DRAFT ──发布──▶ PUBLISHED ──下线──▶ OFFLINE
                    ▲                  │
                    └────重新发布───────┘
```

| 当前状态 | 事件 | 目标状态 |
|----------|------|----------|
| DRAFT | 发布 | PUBLISHED |
| PUBLISHED | 下线 | OFFLINE |
| OFFLINE | 重新发布 | PUBLISHED |

### 7.5 支付订单状态（`tb_pay_order.status`）

```
PENDING ──支付确认──▶ PAID
   │
   ├──超时──▶ EXPIRED
   └──用户取消──▶ CANCELLED
```

| 当前状态 | 事件 | 目标状态 |
|----------|------|----------|
| PENDING | 沙箱支付确认（未过期） | PAID |
| PENDING | 超过 `expire_time` | EXPIRED |
| PENDING | 用户取消 | CANCELLED |
| PAID / EXPIRED / CANCELLED | 再次确认 | 拒绝，返回 400 |

> ⚠ 现状为懒过期：仅 confirm/cancel 触发 EXPIRED 落库，无扫表任务，未操作的订单永挂 PENDING（见 11.7-25）。

> ⚠ **与消耗品订单状态机的关系**：本节为 VIP 订单等通用支付状态机。消耗品订单（FR-PAY-06，`biz_type=ITEM`）复用 `tb_pay_order` 表，但在 PAID 之后增加扩展态：`PAID → USED`（核销）/ `EXPIRED`（库存过期）/ `REFUNDED`（退款），详见 `docs/需求文档/15-PRD-Phase3-付费消耗品.md`。共存规则：VIP 订单走本节状态机，消耗品订单走扩展状态机，互不干扰。

### 7.6 管理员状态（`tb_admin.status`）

```
NORMAL ⇄ DISABLED
```

| 当前状态 | 事件 | 目标状态 | 限制 |
|----------|------|----------|------|
| NORMAL | 禁用 | DISABLED | 不可禁用 `SUPER_ADMIN`，不可禁用自己 |
| DISABLED | 启用 | NORMAL | — |

### 7.7 用户反馈状态（`tb_feedback.status`）

```
0 待处理 ──回复──▶ 1 已回复 ──关闭──▶ 2 已关闭
                      │
                      └──再次回复──▶ 1 已回复
```

| 当前状态 | 事件 | 目标状态 |
|----------|------|----------|
| 0 | 回复 | 1 |
| 1 | 再次回复 | 1 |
| 0 / 1 | 关闭 | 2 |
| 2 | 回复 / 关闭 | 拒绝 |

### 7.8 敏感词 / FAQ 启用状态

`1` 启用 ⇄ `0` 停用，无中间态。
