## 一、背景与目标

### 1.1 业务背景

当前每日 50 次滑动用完后，用户看到干巴巴的 toast"今日次数已用完"就离开了。这是**最大的流失节点**。

**核心问题**：
- 没有任何引导，用户不知道为什么不能滑了
- 付费转化路径断了（用户不被告知 VIP 可以无限滑）
- 缺少"补偿机制"留下用户

### 1.2 数据目标

| 指标 | 当前 | 目标 |
|------|:---:|:---:|
| 滑动耗尽用户 5min 内离开率 | 70% | ≤ 40% |
| 滑动耗尽 → VIP 点击率 | 0%（无入口）| 8%+ |
| 滑动耗尽 → 查看喜欢我 | 0%（不可用）| 15%+ |
| VIP 转化率（从滑动耗尽来）| <1% | 2.5%+ |

### 1.3 非目标

- 不在本版本实现"看广告解锁"（预留扩展位）
- 不做"邀请好友换取次数"
- 不区分不同等级用户的耗尽阈值

## 二、功能描述

### 2.1 触发条件

```
右滑（喜欢）第 51 次时触发：
  - 前端拦截：usedSwipes >= swipeLimit && !isVIP
  - 不调用后端接口（省流量）
  - 直接展示全屏引导页
```

### 2.3 用户流程

```
滑动第 51 次
  │
  ├─ 非 VIP → 跳转全屏引导页（无 toast、无延迟）
  │
  ├─ VIP → 正常滑动（不触发引导页）
  │
  └─ 引导页交互
       │
       ├─ 点"查看谁喜欢你（3 人）"
       │    └─ 调 GET /match/blurred-likes?limit=3
       │    └─ 展示 3 个高斯模糊头像 + "开通 VIP 查看完整"
       │    └─ 点击头像跳 VIP 页
       │
       ├─ 点"开通 VIP"
       │    └─ 跳 VIP 购买页
       │
       └─ 点"稍后再说"
            └─ 返回匹配页（保留"次数耗尽"提示）
```

### 2.4 高斯模糊实现

**头像处理**：前端 CSS 滤镜（`filter: blur(8px)`），无需后端处理图片

**昵称脱敏**：`林妙可` → `林**`

### 2.5 模糊预览数据来源

模糊预览列表数据由后端接口 `GET /match/blurred-likes?limit=3` 提供（接口定义见 §3.2），返回喜欢过当前用户的 N 个用户头像 + 脱敏昵称。前端仅做高斯模糊渲染，**不做客户端过滤**。

### 2.6 匹配页剩余次数提示

在滑动卡片区域底部增加常驻提示：

```
┌──────────────────────────────────────────┐
│                                          │
│         卡片区域                           │
│                                          │
├──────────────────────────────────────────┤
│  💎 剩余 12 次  ·  开通 VIP 无限滑动 →    │  ← 剩余 < 10 次时变红
└──────────────────────────────────────────┘
```

- 剩余 ≤ 10 次：提示变红，增加紧迫感
- 剩余 0 次：提示消失，直接触发引导页

## 三、接口设计

### 3.1 获取剩余滑动次数

- **接口**：`GET /match/progress`（复用已有接口）
- **响应**：

```json
{
  "code": 200,
  "data": {
    "swipeCount": 49,
    "swipeLimit": 50,
    "remaining": 1,
    "isVip": false
  }
}
```

### 3.2 获取模糊预览列表（非 VIP）

- **接口**：`GET /match/blurred-likes?limit=3`
- **响应**：

```json
{
  "code": 200,
  "data": {
    "total": 3,
    "likes": [
      { "userId": 1001, "nickname": "林**", "avatar": "https://.../avatar1.jpg", "blurred": true },
      { "userId": 1002, "nickname": "陈**", "avatar": "https://.../avatar2.jpg", "blurred": true },
      { "userId": 1003, "nickname": "王**", "avatar": "https://.../avatar3.jpg", "blurred": true }
    ],
    "hint": "开通 VIP 查看完整的 3 个喜欢你的人"
  }
}
```

### 3.3 依赖项与调用链

- **前置依赖**：FR-REC-02（探花匹配，提供 /match/progress）
- **新增接口**：GET /match/blurred-likes?limit=3（新增模糊预览列表，非 VIP 返回模糊头像 + 脱敏昵称）
- **下游被依赖方**：无
- **数据流**：前端触底 → GET /match/blurred-likes → 推荐引擎过滤出喜欢过当前用户的 N 个用户头像 + 高斯模糊处理

### 3.4 接口错误响应

| 接口 | HTTP | 错误码 | 场景 | message |
|------|:---:|:---:|------|---------|
| `GET /match/blurred-likes` | 401 | `AUTH_FAILED` | Token 过期 | "请先登录" |
| `GET /match/blurred-likes` | 429 | `RATE_LIMIT` | 1 分钟内重复请求 | "请求过于频繁" |
| `GET /match/blurred-likes` | 403 | `VIP_REQUIRED` | 非 VIP 尝试获取完整列表（传 full=true）| "该功能需要开通 VIP" |

> 前端统一处理：401 → 跳转登录；403 → 弹出 VIP 升级墙；429 → toast 后禁用刷新按钮 10 秒。

## 四、边界场景

| 场景 | 处理 |
|------|------|
| 滑动耗尽用户访问 VIP 页 | 购买成功后自动回到 VIP 权益页，toast"恭喜，你可以无限滑动了！" |
| 用户购买 VIP 但滑动缓存未更新 | VIP 接口拦截 + 每次购买成功后清除本地 usedSwipes 计数 |
| 用户用完全部次数 + 没有喜欢记录 | blurred-likes 返回空，隐藏该模块，突出 VIP 模块 |
| 用户多次滑动耗尽后再次进入 App | 不重复引导页，仅显示陪伴提示 |
| 账号状态异常（封禁）| 保持封禁拦截逻辑不变（不触发滑动引导）|
