# 心飞交友（xfjy）App 用户体验审查报告

> 审查对象：`xfjy-app`（uni-app H5 / App / 小程序多端）
> 审查方式：真实设备 H5 渲染 + Puppeteer 全流程驱动 + 源码核查（覆盖 18 个真实画面）
> 审查日期：2026-11-04
> 审查范围：易用性、交互流畅度、导航清晰度、视觉一致性、整体满意度；覆盖核心使用流程与常见操作场景

---

## 一、审查方法论

本次审查采用"真实运行 + 真实交互 + 源码对照"的方式，而非静态看代码：

1. **真实登录**：使用测试账号（id=1 手机号 `17671787093` + 固定验证码 `123456`）走完整登录流程，注入合法 token 后驱动 App。
2. **全流程驱动**：通过 `switchTab` / `navigateTo` 真实进入每一个核心页面，并触发关键交互（右滑喜欢、卡片点击、发布、播放视频、切 tab 等）。
3. **画面取证**：对 18 个关键状态截图（见 `docs/screenshots/ux/`），逐屏分析视觉与交互。
4. **源码核对**：对照 `match/index.vue`、`utils/ux.ts`、`pages.json`、各页面组件，确认问题根因并给出可落地的修复建议。

## 二、总体评分（5 分制）

| 维度 | 评分 | 说明 |
|------|------|------|
| 易用性 | 3.2 | 核心功能可达，但多处缺引导/反馈（发布禁用无说明、登录反馈弱、资料空白破相） |
| 交互流畅度 | 3.6 | 滑动/切换流畅，骨架屏与空状态齐备；偶发冷启动 401 闪烁 |
| 导航清晰度 | 3.4 | 底部 5 tab 清晰；中央"+"无文字、附近筛选冗余、"消息"入口含混 |
| 视觉一致性 | 3.8 | 品牌色/圆角/卡片风格统一；个别文案中英混排、计数对比度低 |
| 整体满意度 | 3.4 | 基础体验扎实（无障碍/反馈层是亮点），但决策信息不足与反馈缺口拉低首感 |

**综合：3.5 / 5** —— 架构与基础设施成熟，主要短板集中在"帮助用户做决策的信息密度"和"操作反馈的明确性"。

## 三、体验问题清单（按严重程度）

> 严重程度：🔴 高（阻断/严重误导） · 🟡 中（明显可用性问题） · 🟢 低（细节打磨）

### 🔴 高严重度

| 编号 | 问题 | 出现路径 | 描述 | 改进建议 |
|------|------|----------|------|----------|
| M1 | 滑动卡片无法查看完整资料 | 匹配页 → 任意推荐卡片 | 卡片仅显示昵称/年龄/标签，**无签名、身高、职业、距离、照片数量**；点击卡片无反应（`card-wrapper` 仅有滑动手势，无详情入口）。用户在"喜欢/不喜欢"决策前缺乏关键判断信息。 | ① 卡片点击进入 `match/detail` 详情页（页面已存在但未从卡片可达）；② 卡片增加"查看资料"入口或上滑看更多照片；③ 增加照片指示点（1/5）。 |
| P1 | 发布按钮禁用但无原因 | 圈子 → 发布页 | "发布"按钮置灰，但**没有任何文案说明为什么不能点**（需文本或媒体）。用户困惑。 | 禁用态显示 inline 提示"至少输入文字或添加一张图片"；或改为可点 + 提交时校验并高亮问题字段。 |
| V4 | VIP 套餐与权益等级映射不清 | 我的 → 开通会员 | 权益列标注 `VIP1+/VIP2+/VIP3+`，但月/季/年卡**未说明对应哪个等级**；底部 CTA 硬编码"立即开通 ¥258"（年卡）却无明确"当前选中：年卡"态。 | 明确映射（如 年卡=VIP3）；选中态高亮 + "已选：年卡"；补充自动续费/取消/退款说明。 |
| S1 | 退出登录被底部 TabBar 遮断 | 我的 → 设置 | 设置页底部"退出登录"被底部导航栏**截断**，难以看清与点击。 | 列表底部增加 `safe-area` / 足够 padding，确保退出登录完整可见可点。 |

### 🟡 中严重度

| 编号 | 问题 | 出现路径 | 描述 | 改进建议 |
|------|------|----------|------|----------|
| M2 | 卡片文字对比度不足 | 匹配页卡片 | 虽有 `.card-mask` 渐变遮罩但偏弱，白字叠在浅色照片（如白色连衣裙）上可读性差。 | 增强底部遮罩强度/范围，或在文字区加半透明暗底。 |
| M3 | 操作按钮可发现性差 | 匹配页底部五键 | "曝光提升 ⚡"无文字标签，新用户不理解；按钮尺寸层级不一致（X 与 心 更大）。 | 为 ⚡ 增加文字或首次引导气泡；统一按钮尺寸或明确主操作层级。 |
| C1 | 动态缺图与互动数据 | 圈子 → 信息流 | 真实帖子仅有文字+标签，**图片区空白、无点赞/评论数**。 | 补图片懒加载与占位；显示互动计数；无图时隐藏图片区而非留白。 |
| C2 | 内容疑似重复/占位 | 圈子 → 信息流 | 两条帖子内容完全一致（同用户、同文案、同标签），疑似 mock/未去重，损害真实感。 | 确认数据源，避免重复内容。 |
| P2 | 缺页面标题与字段标签 | 发布页 | 无"发布"标题，仅靠 placeholder 辨识；话题/位置行无视觉分组标题。 | 顶部加标题"发布动态"，字段加标签分组。 |
| P3 | 字数/媒体上限说明不清 | 发布页 | "0/500"未说明是上限；图片未标"最多 9 张"。 | 明确"500 字上限"；媒体区标注数量上限与格式。 |
| MN1 | 资料空白导致"破相" | 我的 → 个人中心 | 未完善资料时显示"未设置昵称 / 未知城市·一岁 / 你是谁"，个人中心像坏掉了。 | 资料缺失时给引导"完善资料得更多匹配"，而非直接显示空值。 |
| F1 | 空列表仍显示搜索框 | 我的 → 我的好友 | 0 互相关注时搜索框无意义；CTA"去探花频道"是纯文本不可点。 | 空态隐藏搜索框；CTA 做成可点击按钮。 |
| K1 | 仅 FAQ，无人工/工单入口 | 我的 → 在线客服 | 只有常见问题列表，用户问题解决不了时**找不到人工/提交入口**（kefu/chat、feedback 页已存在但未露出）。 | FAQ 外提供"联系客服 / 在线聊天 / 提交反馈"入口。 |
| L1 | 验证码发送反馈弱 | 登录页 → 获取验证码 | 点击后无明确倒计时/成功提示；失败亦无显式错误（测试环境因 CORS 拦请求，但生产也应保证反馈）。 | 成功后按钮变"60s 后重试"倒计时；失败用 `ux.fail` 明确提示；未勾协议时点登录给"请先同意协议"。 |
| N1 | 中央"+"发布键无文字 | 全 App 底部 | H5 中央键仅绘制"+"、无文字，新用户不知是发布；小程序端补了"发布" tab，多端不一致。 | 加首次引导/tooltip；统一多端发布入口语义。 |

## 四、做得好的地方（亮点）

1. **无障碍基础设施完善**：`a11y-button / a11y-dialog / a11y-picker / a11y-radio-group` 组件 + `aria-label` + 缘分值 `progressbar` 语义，读屏友好度明显优于同类小项目。
2. **统一反馈层 `utils/ux.ts`**：toast 全局去重、高频失败降噪、网络状态细分（离线/超时/连接失败），避免"toast 轰炸"。
3. **加载/异常状态齐备**：骨架屏（含与真实卡片同几何的 match 骨架）、空状态组件、全局错误边界、网络状态栏一应俱全。
4. **视觉风格统一**：粉紫品牌色、圆角卡片、底部 TabBar 一致；配对成功庆祝层（`match-popup`）交互完整。
5. **设置页分组清晰**：账号安全 / 通知 / 隐私 / 通用分组合理，开关启用态用品牌色。
