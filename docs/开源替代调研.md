# 环信 IM / 极光 JPush 开源替代调研（复核版 v2）

> 复核时间：2026-10-31。本版基于官方文档与 GitHub 仓库一手页面核实，纠正 v1 的两处不准确结论。
> 技术对接背景：uni-app（xfjy-app，Vue3）+ Spring 后端；偏好开源免费、本地化、资源占用可控。

## 一、复核结论（TL;DR）

- **v1 修正 1**：野火"免费版音视频"**核心引擎 EngineKit 闭源**（免费但不开源，仅通话 UI 开源），高级版 5.9 万/套且媒体服务与 SDK 全部闭源。不能简单说"野火开源音视频"。
- **v1 修正 2**：WuKongIM 的**独立 UniApp SDK 已停止维护**，需迁移到 JS SDK；它**只提供 WebRTC 信令，不内置媒体服务器与通话 UI**。
- **野火的真正优势**：有**官方、成熟、开源的 uni-app 方案**（原生插件 + UTS 插件，支持鸿蒙 NEXT），这一点明显优于 WuKongIM。
- **要全链路开源音视频**：消息用 WuKongIM/OpenIM，媒体用 **LiveKit（Apache-2.0 开源 SFU，v1.13.7，Docker 一条命令）**，自己做集成与 UI。
- 推送结论不变：国内安卓离线可靠到达只能走厂商通道，建议 **uni-push 2.0（免费、uni-app 原生）**。

## 二、WuKongIM vs 野火IM —— 一手核实数据

| 维度 | WuKongIM（悟空IM） | 野火IM（WildfireChat） |
|---|---|---|
| 语言/协议 | Go，**Apache-2.0，全开源** | 社区版开源；专业版闭源（2.9 万/套） |
| GitHub 量级 | **Star 5.0k、Fork 711、5778 commits** | 老牌，全平台，文档持续更新 |
| 维护状态 | 活跃（Go 1.25.11），**v3 仍 beta** | 活跃，文档 2026-10 仍修订 |
| 外部依赖 | **无**，内置存储/集群，单节点起步 | 社区版依赖 MySQL |
| 音视频 | **仅 WebRTC 信令通道**，无媒体服务器、无现成通话 UI | 免费版现成通话（4 视频/9 音频）；高级版 9 视频/20 音频 |
| 音视频是否开源 | 无（需另接，如 LiveKit） | **EngineKit 闭源（免费但不开源），仅 UI 开源** |
| 额外组件 | 用 SFU 需自备媒体服务 | 免费版需自备 **coTurn**；高级版需闭源媒体服务 |
| uni-app | **独立 UniApp SDK 已停，迁 JS SDK** | **官方 uni-chat / uni-chat-uts，开源，支持鸿蒙** |
| 录制/会议 | 取决于自接方案 | 免费版不支持；高级版支持（会议/屏幕共享/录制） |

## 三、音视频专题（重点）

### 1. 野火音视频（官方文档 2026-10-14 修订）

| 功能 | 免费版（Mesh/P2P） | 高级版（SFU） |
|---|---|---|
| 视频/音频路数 | 4 视频 / 9 音频 | 9 视频 / 20 音频 |
| 媒体服务器 | 不需要 | 需要（闭源） |
| coTurn | **必须自备**（开源，自带 STUN，开 3478） | 不需要 |
| 会议/屏幕共享/录制 | 不支持 | 支持 |
| 开源边界 | **EngineKit 闭源、UI 开源** | 媒体服务+SDK 闭源、UI 开源 |
| 价格 | 免费 | **5.9 万/套，且依赖 IM 专业版** |
| 互通 | 免费版与高级版不互通 | 同左 |

### 2. 全开源音视频拼图：LiveKit

- Go + Pion 实现的开源 **WebRTC SFU**，**Apache-2.0**；当前 **v1.13.7（2026-09-14）**，社区高度活跃。
- 自带信令、NAT 穿透、RTP 路由、自适应降级；客户端用 JWT 接入。
- 自托管无按分钟计费，Docker 一条命令即可启动：`docker run --rm -p 7880:7880 livekit/livekit-server:latest --dev --bind 0.0.0.0`。
- 定位：**IM 消息与音视频媒体解耦**——WuKongIM/OpenIM 负责聊天与离线消息，LiveKit 负责通话媒体，自行实现通话 UI。

## 四、按场景决策建议

| 场景 | 推荐 | 理由 / 代价 |
|---|---|---|
| **A. 以 IM 消息为主，省资源、音视频后补** | **WuKongIM** | 全开源、无外部依赖、单节点省资源；音视频需自接（可配 LiveKit），uni-app 走 JS SDK 迁移 |
| **B. 要开箱即用音视频 + 是 uni-app** | **野火IM** | 官方 uni-app/UTS 插件开源成熟、支持鸿蒙；但免费版引擎闭源、需自备 coTurn，高级版 5.9 万 |
| **C. 坚持全链路开源（消息+音视频）** | **WuKongIM + LiveKit** | 两者均 Apache-2.0、可本地 Docker 部署；代价是集成与通话 UI 全部自研，工作量最大 |

> 个人倾向：你是 uni-app 且明确"开源免费"，若音视频是刚需，**优先评估野火的 uni-chat-uts 做快速验证**，同时确认能否接受 EngineKit 闭源；若不能接受任何闭源，则走 **WuKongIM + LiveKit** 的全开源组合，分阶段实施。

## 五、推送（替代极光 JPush）——结论不变

- 国内安卓离线可靠送达必须走系统级厂商通道（华为/小米/OPPO/vivo/荣耀），纯开源自建（Gotify/ntfy/MQTT）会被杀后台，仅适合在线/内网。
- 主力建议 **uni-push 2.0**：免费、uni-app 原生、聚合厂商通道；uniCloud 云函数按量费用极低（约 1 万次 0.0133 元）。

## 六、扩展方案：用户量更大、社区更活跃的主流开源栈

> 以下为本次扩大范围核实的候选，量级与资源均来自 2026 年实测/资料页；star 为页面时点值，以 GitHub 实时为准。

### 1. 全候选横向总表

| 项目 | 类型 | 核心协议 | 量级(star) | 技术栈 / 资源 | 音视频 | 官方 uni-app |
|---|---|---|---|---|---|---|
| **Rocket.Chat** | 一体化团队/全渠道 IM | **MIT（核心，open-core）** | **约 46.3k** | Node+MongoDB，生产建议 4核8GB，空闲约 1GB | 内置视频会议 | 无，走 REST |
| **Jitsi Meet** | 视频会议/媒体 | **Apache-2.0** | 顶级（8x8 维护） | Prosody+Jicofo+JVB+coTurn，单分片实测 1000+ 人 | 专业级会议 | 无，走嵌入 |
| **Tinode** | 轻量 IM（对标 WhatsApp） | **GPL-3.0（强 Copyleft）** | 约 13.5k | Go，轻量，2026-09 仍提交 | 支持 HD 视频 | 无，走 gRPC/WS |
| **Matrix（Synapse/Element）** | 去中心化联邦 IM | **AGPL-3.0（强 Copyleft）** | Element 约 13.6k | Synapse(Python) 吃内存；可选 Dendrite(Go)/Conduit(Rust) 轻量 | 内置 E2E 加密 | 无，走 API |
| WuKongIM | 轻量消息基础设施 | Apache-2.0 | 5.0k | Go，无外部依赖，2核4G 起 | 仅信令 | 独立 SDK 已停 |
| OpenIM | 大而全 IM | Apache-2.0 | 万星级 | Go+多组件，4GB 起 | 需另接 | 需 JS 接入 |
| 野火IM | 成熟 IM+音视频 | 社区开源/专业闭源 | 老牌 | 全平台，含 uni-app 官方插件 | 免费版引擎闭源 | **有，最成熟** |
| LiveKit | 开源 SFU 媒体 | Apache-2.0 | 高活跃 | Go，Docker 一条命令，v1.13.7 | 专业 SFU | 有客户端 SDK |

### 2. 各方案要点与社交适配

- **Rocket.Chat（用户量最大的一体化选择）**：约 46.3k star，含 IM、视频会议、文件、白标定制、官方 iOS/Android/桌面客户端、OAuth/LDAP/2FA；2核4GB 可承载 50–100 活跃用户。代价：Node+MongoDB 偏重（生产建议 4核8GB），无官方 uni-app 插件，需用 REST/WS 接入并自研界面；高级能力属付费层。
- **Jitsi Meet（最知名的纯开源视频）**：Apache-2.0、月度更新、单分片可超 1000 人、无需账号、支持 E2EE；但定位是"会议"，不是社交 IM，适合作为音视频能力嵌入而非聊天底座。
- **Tinode（轻量 Go、对标 WhatsApp）**：约 13.5k star、活跃维护、提供 gRPC/WebSocket 与全平台客户端；注意 **GPL-3.0 强 Copyleft**，对闭源商业分发有合规要求。
- **Matrix（去中心化、生态大、端到端加密）**：联邦互通、可桥接 Slack/Discord/Telegram/WhatsApp；Synapse 内存占用高、架构最复杂，可换轻量服务端 Dendrite/Conduit；**AGPL-3.0** 合规要求更严，社交产品通常还需关闭联邦。

### 3. 协议合规提醒（重要）

- 宽松可商用：**Apache-2.0 / MIT**（WuKongIM、LiveKit、Jitsi、Rocket.Chat 核心）。
- 强 Copyleft：**GPL-3.0（Tinode）、AGPL-3.0（Matrix/Element）**，若计划闭源商业化或提供网络服务，需评估开源义务，必要时联系作者取得商业授权。

### 4. 结合"社交交友 + uni-app + 开源活跃 + 用户量多"的最终建议

1. **要最活跃、用户量最大、一体化且能接受较重部署**：评估 **Rocket.Chat**（社区量级最大、MIT 核心、含音视频与白标），但需接受 MongoDB 资源占用与 uni-app 自研接入。
2. **要纯开源、大规模、专业音视频**：IM 用 **Rocket.Chat/WuKongIM**，媒体用 **Jitsi（会议向）或 LiveKit（嵌入式 SFU）**。
3. **要轻量 + 活跃 + 对标 WhatsApp 且能接受 GPL**：**Tinode**。
4. **uni-app 落地成本最低、要现成音视频**：仍是 **野火 uni-chat-uts**（唯一带官方 uni-app 插件的方案），代价是免费版引擎闭源。

> 综合判断：你"用户量多 + 活跃"的诉求里，**Rocket.Chat 是新增中最值得做 POC 的一体化方案**；但它和野火一样存在"核心免费、高级付费"的边界，且没有野火的 uni-app 原生插件。若坚持全开源且想省事，**WuKongIM + LiveKit** 仍是协议最干净的组合。
