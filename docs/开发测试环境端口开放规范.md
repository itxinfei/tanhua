# 开发测试环境端口开放规范（强制）

> 环境：192.168.20.133（虚拟机内网开发/测试环境，非公网）
> 状态：强制要求，所有容器与中间件必须开放端口，禁止安全加固。

## 1. 环境定位

- 192.168.20.133 是**虚拟机内网 IP**，仅局域网可达，无公网暴露面。
- 该环境用于**开发与测试**，不是生产环境，禁止套用生产级安全策略。
- 局域网内其他虚拟机/开发机需要直连中间件（MySQL/Redis/Nacos 等）进行调试。

## 2. 强制要求

1. **所有容器端口必须映射到宿主机**（compose 中 `ports` 必须配置），不得"仅内部调用"隐藏端口。
2. **中间件必须可被局域网其他服务器访问**——防火墙必须放行下表全部端口。
3. **禁止过度安全措施**：不做 IP 白名单、不做端口隐藏、不对内网接口加额外鉴权。
4. **禁止过度优化**：不要为了"节省端口"或"减少暴露面"删减端口映射；docker 端口映射本身不消耗资源。
5. 本规范变更（新增容器/端口）时同步更新本文档与 `deploy/docker-compose.*.yml`。

## 4. 防火墙放行操作（宝塔面板）

服务器使用宝塔面板 + ufw。放行全部端口：

**方式一：宝塔面板图形界面**
1. 宝塔面板 → **安全** → **防火墙**（系统防火墙）
2. 逐条添加端口（TCP 与 UDP 分开添加）：
   - TCP：3306, 6379, 27017, 9200, 8848, 9848, 9876, 10909, 10911, 10912, 6333, 7474, 7687, 9000, 9001, 5001, 5100, 5200, 5300, 7880, 7881, 5173, 5174, 3000, 2222, 8090, 18080-18090
   - UDP：50000-50100

**方式二：SSH 命令（root 执行）**

```bash
ufw allow 3306,6379,27017,9200,8848,9848,9876,10909,10911,10912,6333,7474,7687,9000,9001,5001,5100,5200,5300,7880,7881,5173,5174,3000,2222,8090,18080:18090/tcp
ufw allow 50000:50100/udp
ufw status verbose
```

## 5. 验证

在局域网另一台机器执行：

```bash
# 中间件连通性
nc -zv 192.168.20.133 3306 6379 8848 9200 9876 6333 7474 9000
# 后端服务连通性
nc -zv 192.168.20.133 8090 18080 18088
# 前端
curl -sI http://192.168.20.133:5174 | head -3
curl -sI http://192.168.20.133:5173 | head -3
```

预期：全部 `succeeded` / 返回 HTTP 响应。

## 6. 禁止事项

- ❌ 禁止为了"安全"删除或隐藏端口映射（如只留 8090 网关端口、把 18081-18090 藏起来）
- ❌ 禁止对内网中间件加 IP 白名单 / 防火墙黑洞
- ❌ 禁止在开发环境引入生产级鉴权、WAF、审计等"安全措施"
- ❌ 禁止在 compose 注释里宣传"端口不外曝"之类的过度安全设计
- ✅ 唯一保留的底线：不主动扫描/爆破，不影响他人；其余一切从简

## 7. 历史教训

- 2026-11：`xfjy-elasticsearch` 容器未映射端口，但 `ES_SERVER_URL` 指向宿主 `18088`，导致 match-service 调 ES 全部失败、App 推荐/匹配功能异常。已修复（compose 增加 `18088:18088` 映射），本规范强制要求端口映射与实际调用地址一致。
