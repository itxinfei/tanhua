# 后台管理系统（xfjy-admin）页面设计审查报告

- 审查日期：2026-11-05
- 审查对象：xfjy-admin（Vue 3 + Element Plus + SCSS）
- 规范基线：AGENTS.md §7.2（视觉约束）、§11（存量豁免）
- 审查方法：全量阅读 src 页面/组件/layout/style.css + rg 取证 + 实跑 npm run lint:style

> 重要前提：lint:style 实测 0 warning（exit 0），但 stylelint 仅拦 color-no-hex，并不拦 rgb()/rgba() 与硬编码 border-radius，存在"规则—工具"缺口（详见 P1-5）。

---

## 一、总体结论

| 维度 | 评分 | 说明 |
|---|---|---|
| 设计 token 体系 | 9 / 10 | 颜色/间距/字号/圆角/阴影/图表色/EP 映射非常完整 |
| 组件化与复用 | 8 / 10 | 5 个骨架组件抽象好、复用率高；但存在两套 KPI 卡 |
| 视觉一致性 | 6.5 / 10 | 圆角、表单标签宽度、页面标题不统一 |
| 交互完整度 | 8.5 / 10 | 看板/审核台/客服台交互专业；列表空态偏弱 |
| 规范符合度（§7.2） | 5.5 / 10 | 颜色 hex 已收敛，但 rgb/圆角/label-width 大面积偏离 |
| 可访问性 | 6 / 10 | 次级文字对比度不足，缺 skip-link/focus 强化 |

综合约 7 / 10。底子很好（体系化、有设计语言），主要问题是执行层不一致与规范/工具脱节，而非设计思路问题。

## 二、做得好的地方（亮点）

1. 设计语言成体系：style.css 定义主色（暖玫红 #fe3c72）、色阶、渐变、图表色板（CVD 验证）、间距 4–32px、三级圆角（12/8/4）、EP 全量 token 映射，注释质量高。
2. 骨架组件抽象到位：PageHeader / SearchBar / TableCard / StatCard / StatusTag，SearchBar 与 TableCard 复用率 15/24。
3. 数据看板质量高：响应式栅格（xs/sm/lg/xl）、el-empty 空态、v-loading、自动刷新+倒计时、sparkline、数字 count-up、实时呼吸点。
4. 审核工作台专业：左队列+右详情双栏、键盘快捷键（A 通过 / R 驳回 / ←→JK 切换）、批量操作、处理后自动跳转、三种空态（队列已清空/无筛选/加载失败可重试）。
5. 客服工作台完整：移动端 tab 切换、未读角标、图片/语音气泡、会话列表。
6. 响应式做得细：断点 token、移动端隐藏次要列、分页精简、超宽屏限宽居中。
7. 登录页品牌感强：左右分栏、极光光斑、漂浮爱心、玻璃拟态表单，900px 以下自动隐藏品牌区。

## 三、问题清单（按严重级别）

### P1（高，建议优先处理）

**P1-1 表单 label-width 严重不统一（规范 96px，现实 80/90px）**
- 现状：80px 13 处、90px 4 处、96px 仅 1 处。
- 证据：user/index.vue:102,122（80）、agreement/index.vue:71（80）、kefu/faq.vue:65（80）、notice/index.vue:76（80）、report/index.vue:190（80）、review/index.vue:194（80）、system/admin.vue:75,100（80）、sensitive/index.vue:114,143（80）；layout/components/Header.vue:54（90）、profile/index.vue:69（90）、vip/index.vue:119,156（90）；仅 user/detail.vue:54 为 96。
- 影响：不同弹窗/表单左侧标签宽度跳变，观感不齐。
- 建议：按 AGENTS.md §0.3 登记裁决——要么 §7.2 改为 80px（迁就现状），要么全量迁移 96px；二选一，不要并存。

**P1-2 卡片圆角不统一（KPI 卡 8px vs 其余 12px）**
- §7.2 要求卡片固定 --xfjy-radius-lg（12px）。但 StatCard.vue 用 --xfjy-radius-md（8px，约 L44），全局向后兼容 .stat-card（style.css）同为 8px；而 TableCard/SearchBar/KpiCard 均为 12px。
- 影响：同屏 KPI 卡（8px）与表格卡（12px）圆角不一致。
- 建议：StatCard 改 --xfjy-radius-lg。

**P1-3 存在两套 KPI 卡实现**
- 看板用自建 dashboard/components/KpiCard.vue（sparkline/count-up/脉冲），支付页用 StatCard；§7.2 要求"数值概览 StatCard"，全站 StatCard 仅 1 处使用。
- 影响：两套视觉与能力，维护双份，新人困惑。
- 建议：把 KpiCard 的增强能力（spark/趋势/脉冲）下沉进 StatCard 并全站统一；或明确登记"看板 KPI 卡为 StatCard 增强变体"。

**P1-4 列表空态覆盖严重不足**
- 仅 4 页使用 el-empty（dashboard / report / review / user/detail）；其余 15+ 列表页依赖 el-table 默认空文本，且全仓无一处 #empty 插槽。
- 影响：无数据时是干巴巴"暂无数据"，缺引导与操作入口。
- 建议：在 TableCard 内统一提供空态插槽（默认渲染 el-empty），或全局给 .el-table__empty-block 注入统一空态。

**P1-5 规范禁 rgb() 但工具不拦，登录页大面积违反**
- §7.2：.vue/.scss 禁止十六进制、rgb()、hsl() 字面量。实测 login/index.vue 有 16 处 rgba()，StatCard.vue:73 也有 1 处；而 npm run lint:style 为 0 warning，说明 stylelint 只校验 hex，rgba 全部漏网。
- 影响：规范形同虚设，后续会持续劣化。
- 建议：stylelint 增加 "function-disallowed-list": ["rgb","rgba","hsl","hsla"]（登录页玻璃拟态可抽成 --xfjy-glass-* token 或局部 disable 并注明）；这是本报告最推荐的流程修复。

### P2（中，影响观感与体验）

**P2-1 pay / vip 两页缺页面标题（PageHeader）**
- pay/index.vue 第 3 行直接是 el-row（KPI 卡），vip/index.vue 第 3 行直接是 el-tabs，均无页内 H1；其余 13 页有 PageHeader。
- 影响：标题层级不一致，用户仅靠面包屑判断位置。
- 建议：补 PageHeader（如"支付订单""VIP 套餐"）。

**P2-2 圆角硬编码（值对但未走 token）**
- 大量 border-radius: 8px / 12px / 4px 写死：review（6 处）、report（2 处）、profile、kefu/workbench（3 处）、user/detail（3 处）、movement、video；StatCard.vue:110 另有 20px。
- 影响：将来统一调整圆角需全量搜索替换，易漏。
- 建议：替换为 --xfjy-radius-*；stylelint 加 declaration-property-value-allowed-list 约束 border-radius。

**P2-3 !important 覆盖 EP 内部样式，多数无原因注释**
- Sidebar.vue 15 处、movement.vue:437、comment.vue:295（均 :deep() 但无同行原因注释）。
- §7.2：确需穿透必须 :deep() 且同行注释原因。Sidebar 虽用了 :deep()，但除最后一条外都没注释。
- 建议：逐条补原因注释，或改用更精确的 EP 变量覆盖。

**P2-4 表格行高 token 实际未生效**
- style.css 定义 --xfjy-table-row-height: 44px，但只作用于 .el-table--medium；全仓 175 处 el-table 中仅 user/detail 用 size="small"，其余为默认尺寸，44px 规则基本没落地。
- §7.2 要求行高 44–48px。影响：信息密度与设计意图不符。
- 建议：统一 size="medium"，或把 height: var(--xfjy-table-row-height) 直接挂到 .el-table__body td。

**P2-5 数据列宽度 < 80px**
- user/index.vue：头像 70 / 性别 70 / 年龄 70 / VIP 70；user/detail.vue：头像 72。§7.2 要求列宽 ≥80px（操作列固定右侧已满足）。
- 建议：放宽到 ≥80，或把"头像/序号/选择"这类工具列统一登记为例外。

**P2-6 次级文字对比度偏低（可访问性）**
- --xfjy-text-secondary #86909c 白底对比约 3.4:1，低于 WCAG AA 4.5:1，却被大量用于副标题/标签/提示（PageHeader subtitle、表格次要列、KpiCard label 等）。
- 建议：次级文字改用更深的值（如 #6b7280 一档），或仅用于 ≥16px 文本。

### P3（低，细节/打磨）

- P3-1 魔法间距/尺寸：StatCard padding:1px、border-radius:20px；KpiCard gap:2px、letter-spacing:-0.5px、line-height:18px；Sidebar 折叠 padding:0 18px（已豁免）。建议归入 8px 栅格或 token。
- P3-2 登录页写死营销数字："128万 / 23万 / 9.6万" 非真实数据（login/index.vue）。作为装饰可接受，建议标注"示意"或接真实统计，避免误读。
- P3-3 客服工作台空态不统一：用 .empty-tip 纯文本（"暂无会话"），未用 el-empty。
- P3-4 搜索区输入框内联宽度：style="width: 180px/100px/260px" 多处（组件尺寸，非间距 token，可接受；可抽常量）。
- P3-5 全局 hover 抬升与"列表卡片禁止 hover 抬升"存在张力：style.css 给 .search-bar:hover/.table-container:hover 加 shadow-hover，StatCard:hover 有 translateY(-2px)。建议区分"可点卡片"与"纯展示容器"。

## 六、建议改进路线（分三批）

### 第 1 批（规范收口，低风险高收益）
1. 裁决并统一表单 label-width（§0.3 登记，96 或 80 二选一）。
2. StatCard 圆角改 --xfjy-radius-lg，与 TableCard 对齐。
3. stylelint 增加 function-disallowed-list: ["rgb","rgba","hsl","hsla"] + border-radius 白名单，把 P1-5/P2-2 变成 CI 可拦。
4. TableCard 增加统一空态插槽，批量替换列表页默认空态。

### 第 2 批（一致性）
5. 统一 KPI 卡（StatCard 增强 或 KpiCard 登记），去掉双实现。
6. pay/vip 补 PageHeader。
7. 表格统一 size="medium" 让 44px 行高生效；列宽 <80 的调整或登记例外。
8. Sidebar !important 逐条补注释。

### 第 3 批（打磨与可访问性）
9. 登录页 rgba 抽 token 或局部 disable；营销数字标注"示意"。
10. 次级文字对比度提升到 AA。
11. 圆角魔法值全面 token 化；魔法间距归 8px 栅格。
