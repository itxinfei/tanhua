# 一、P0 — 核心流程阻断（3 个）

## P0-1 匹配卡片滑完后页面空白卡死，空态与重试永不出现

**证据链**（`src/pages/match/index.vue`）：
- L25 空态门控是 `cardList.length === 0`，但滑动只递增 `currentCardIndex`（L588），历史卡数组从不清空，门控永不成立
- L369-374 `visibleCards` 用 `slice(currentCardIndex, currentCardIndex + N)` 取窗口，索引越界后返回空数组，v-for 零渲染
- L680-685 服务端返回非空但 id 全部重复时，filter 后零新增，`exhausted` 反被显式置 `false`；L681 注释自认「分页间隙服务端可能重复下发同一用户」
- L593-595 滑动中有自动补拉，但补拉命中上述重复批次时无解；L524-526 `swipeOut` 取不到 card 直接 return，五个操作按钮全部空转
- 唯一缓解：onShow（L751）切 tab 回来会重拉，页内无任何提示；服务端持续重复时仍卡死

**用户场景**：连续滑完首批卡片后页面只剩背景图，无提示无按钮，用户被困，只能切走 tab 再回来。

**修复建议**：
1. 空态门控改为 `visibleCards.length === 0 && !loading`（或 `currentCardIndex >= cardList.length`）
2. `loadMoreCards` 中「去重后零新增」也置 `exhausted = true`，让「重新加载」按钮（L29-34）能出现
3. 补一条首屏加载失败的独立错误态（见 S3），不要把失败混进空态

**验证**：模拟接口返回重复 id 批次，滑到最后一张后出现「推荐已看完 + 重新加载」，点击可恢复；`npm run type-check`、`npm run build:h5` 通过。

## P0-2 视频搜索结果卡片完全不可点击，搜索链路是死路

**证据链**：
- `src/pages/video/search-result.vue:101-125` 瀑布流 `.card` 无任何 `@tap/@click`；全文件事件只绑定在返回、搜索、Tab、推荐词、重试上
- `src/pages/video/index.vue:283` 只导入 `onShow/onHide`，**没有 onLoad**，视频页不接收任何参数，无深链播放机制
- 技术约束：视频页是 tabBar 页（`pages.json:211-216`），`uni.navigateTo` 不能跳 tab 页，`switchTab` 不支持带参数——深链必须走 store/事件总线中转，不能走 URL query

**用户场景**：用户搜到视频、看到封面标题，点击任何卡片毫无反应，搜索功能实际不可用。

**修复建议**：
1. `search-result.vue` 卡片用 `a11y-button` 包裹（禁止裸 view 绑 @tap，AGENTS.md §7.1），点击时把目标视频（id + 搜索项数据）写入 `src/store/system.ts` 的待定深链字段，再 `uni.switchTab` 到视频页
2. `video/index.vue` 在 onShow 消费深链：当前频道列表含该 id → `swiperIndex` 定位（参照 L795-797 现有 `-1` 复位手法）；不含 → 把该视频插到列表头部再定位，消费后清除深链字段防止重复触发
3. 注意 `VideoSearchItem` 与视频页 `Video` 类型字段差异，缺字段走详情/播放接口补齐或做映射，禁止 `as any` 强转

**验证**：搜索 → 点卡片 → 落到视频页且自动播放对应视频；返回后再进视频页不重复定位；三端构建通过。

## P0-3 IM 断连期间发消息被静默丢弃，前端却显示「已发送」

**证据链**：
- `src/utils/wukongim.ts:548-560` `sendMessagePayload` 只检查模块级布尔 `isLoggedIn`（L87，不随 WebSocket 实际状态翻转）；`chatManager.send()` 不抛异常即 `return true`
- SDK 行为（子 agent 核查 `node_modules/wukongimjssdk`）：消息入 sendPacketQueue 后每 100ms 无条件 shift，ws 为 null 时可选链静默丢弃、不抛错、重连后不补发
- 消费方 `src/pages/chat/chat.vue:396`、`src/pages/kefu/chat.vue:201` 据返回值置 sent（成功气泡）
- 反证 API 可用：同文件 L257、L266 已在使用 `connectManager.connected()` 判活

**用户场景**：进电梯/弱网断连后发消息，气泡显示成功，对方永远收不到，无失败红点、无重发入口。

**修复建议（本次只做第一步，小而稳）**：
1. `wukongim.ts` 导出 `isIMConnected()`（内部读 `WKSDK.shared().connectManager.connected()`）
2. `sendMessagePayload`（及结构化消息发送入口）发送前判活，未连接直接 `return false`，不进 SDK 发送队列
3. 两个聊天页现有「失败红点 + 点击重发」链路已完整（chat.vue:37-39、408-411；kefu/chat.vue:24-31、191-194），false 会自然走到 failed 态，无需新做 UI
4. 后续增强（另开卡）：注册 sendack/reasonCode 监听按投递 ACK 回写状态，覆盖「发送瞬间在线、传输中断开」的窗口

**验证**：断网状态发消息 → 气泡立即显示失败态而非成功；恢复网络后点重发成功；`npm run type-check` 通过。
