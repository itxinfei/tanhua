# 心飞交友部署文档

本文档覆盖项目所有需要部署的组件，统一使用 Docker 部署中间件，后端 Java 服务和前端在宿主机运行。

## 二、前置条件

### 2.1 软件版本要求

| 软件 | 版本 | 用途 |
|------|------|------|
| Docker Desktop | 4.x+ | 中间件容器化部署 |
| JDK | 25（Temurin） | 后端运行（Spring Boot 4.1.1 最低要求 JDK 17） |
| Maven | 3.9+ | 后端构建 |
| Node.js | 22+ | 前端构建（admin + app） |

### 2.2 Docker 环境

Windows 安装 Docker Desktop（WSL2 后端）：

```powershell
winget install Docker.DockerDesktop
```

安装后启动 Docker Desktop，确认 WSL2 后端已启用（Settings → General → Use the WSL 2 based engine）。

### 2.3 网络模式说明

> **重要**：Windows Docker Desktop 不支持 `--network host` 模式。本文档所有中间件容器均采用**端口映射模式**（`-p 宿主机端口:容器端口`），映射到 `127.0.0.1`，后端 Java 服务在宿主机运行，通过 `127.0.0.1` 直连各中间件，与项目默认配置一致，无需修改任何连接地址。

Linux 服务器可选 `--network host` 模式（更简单，无需端口映射），命令中去掉 `-p` 参数加上 `--network host` 即可。

## 三、核心中间件部署

### 3.1 MySQL 8.0

```bash
docker run -d \
  --name xfjy-mysql \
  --restart unless-stopped \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -e MYSQL_DATABASE=xfjy \
  -e TZ=Asia/Shanghai \
  -v xfjy-mysql-data:/var/lib/mysql \
  mysql:8.0 \
  --character-set-server=utf8mb4 \
  --collation-server=utf8mb4_unicode_ci
```

**验证**：
```bash
docker exec xfjy-mysql mysql -uroot -p123456 -e "SELECT VERSION();"
```
预期输出 `8.0.x`。

**注意事项**：
- 必须指定 `utf8mb4`，否则中文和 emoji 存储异常
- 数据持久化到 Docker 卷 `xfjy-mysql-data`，容器删除数据不丢
- JDBC 连接串已含 `allowPublicKeyRetrieval=true`，MySQL 8 认证插件 caching_sha2_password 无需额外处理

### 3.2 Redis 7

```bash
docker run -d \
  --name xfjy-redis \
  --restart unless-stopped \
  -p 6379:6379 \
  -v xfjy-redis-data:/data \
  redis:7-alpine \
  redis-server --appendonly yes
```

**验证**：
```bash
docker exec xfjy-redis redis-cli ping
```
预期输出 `PONG`。

**注意事项**：
- 开发环境未设密码（`REDIS_PASSWORD` 留空）；生产环境加 `--requirepass 你的密码` 并设置 `REDIS_PASSWORD` 环境变量
- `--appendonly yes` 开启 AOF 持久化

### 3.3 Nacos 3.x

> Spring Cloud Alibaba 2025.1.0.0 要求 Nacos 3.x，Nacos 2.x 不兼容。

```bash
docker run -d \
  --name xfjy-nacos \
  --restart unless-stopped \
  -p 8848:8848 \
  -p 9848:9848 \
  -e MODE=standalone \
  -e NACOS_AUTH_ENABLE=false \
  -e TZ=Asia/Shanghai \
  nacos/nacos-server:v3.0.0
```

**验证**：
```bash
curl -sf -o /dev/null http://127.0.0.1:8848/nacos
```
预期返回 0（HTTP 302 重定向到控制台）。浏览器访问控制台：http://127.0.0.1:8848/nacos

> **注意**：Nacos 3.x 移除了 `/v1/console/health/readiness` 端点，健康检查改用首页 302 状态判断。

**注意事项**：
- 9848 是 gRPC 端口，客户端（Spring Cloud Alibaba）通过 gRPC 注册服务，**必须映射**，否则服务注册失败
- 开发环境关闭鉴权（`NACOS_AUTH_ENABLE=false`），代码默认 `NACOS_USERNAME=nacos` / `NACOS_PASSWORD` 留空
- 生产环境开启鉴权需设置 `NACOS_AUTH_ENABLE=true`、`NACOS_AUTH_TOKEN`、`NACOS_AUTH_IDENTITY_KEY/value`，并配置 `NACOS_USERNAME`/`NACOS_PASSWORD` 环境变量
- 单机模式使用内嵌 Derby 存储，重启不丢数据；生产建议外置 MySQL 存储

### 3.4 RocketMQ 5.x

RocketMQ 需要部署 NameServer 和 Broker 两个容器，Broker 需要配置文件指定 `autoCreateTopicEnable=true`。

**第一步：创建 Broker 配置文件**

```bash
# Linux / Git Bash
mkdir -p /tmp/rocketmq && cat > /tmp/rocketmq/broker.conf << 'EOF'
brokerClusterName = DefaultCluster
brokerName = broker-a
brokerId = 0
deleteWhen = 04
fileReservedTime = 48
brokerRole = ASYNC_MASTER
flushDiskType = ASYNC_FLUSH
autoCreateTopicEnable = true
autoCreateSubscriptionGroup = true
EOF
```

Windows PowerShell：
```powershell
New-Item -ItemType Directory -Force -Path D:\docker-data\rocketmq
@"
brokerClusterName = DefaultCluster
brokerName = broker-a
brokerId = 0
deleteWhen = 04
fileReservedTime = 48
brokerRole = ASYNC_MASTER
flushDiskType = ASYNC_FLUSH
autoCreateTopicEnable = true
autoCreateSubscriptionGroup = true
"@ | Set-Content -Encoding UTF8 D:\docker-data\rocketmq\broker.conf
```

**第二步：启动 NameServer**

```bash
docker run -d \
  --name xfjy-rocketmq-namesrv \
  --restart unless-stopped \
  -p 9876:9876 \
  apache/rocketmq:5.3.1 \
  sh mqnamesrv
```

**第三步：启动 Broker**

```bash
# Linux / Git Bash（配置文件挂载 /tmp/rocketmq/broker.conf）
docker run -d \
  --name xfjy-rocketmq-broker \
  --restart unless-stopped \
  -p 10909:10909 \
  -p 10911:10911 \
  -p 10912:10912 \
  -v /tmp/rocketmq/broker.conf:/home/rocketmq/rocketmq-5.3.1/conf/broker.conf \
  apache/rocketmq:5.3.1 \
  sh mqbroker -n 127.0.0.1:9876 -c /home/rocketmq/rocketmq-5.3.1/conf/broker.conf
```

Windows PowerShell（配置文件挂载 D 盘路径）：
```powershell
docker run -d `
  --name xfjy-rocketmq-broker `
  --restart unless-stopped `
  -p 10909:10909 -p 10911:10911 -p 10912:10912 `
  -v D:\docker-data\rocketmq\broker.conf:/home/rocketmq/rocketmq-5.3.1/conf/broker.conf `
  apache/rocketmq:5.3.1 `
  sh mqbroker -n 127.0.0.1:9876 -c /home/rocketmq/rocketmq-5.3.1/conf/broker.conf
```

**验证**：
```bash
docker exec xfjy-rocketmq-broker sh mqadmin clusterList -n 127.0.0.1:9876
```
预期看到 `broker-a` 节点信息。

**注意事项**：
- `autoCreateTopicEnable = true` 必须开启，否则生产者发送消息报 `topic not exist`。生产环境建议关闭并手动建 topic
- 环境变量 `ROCKETMQ_NAME_SERVER` 默认值 `127.0.0.1:9876`，与 NameServer 映射端口一致，无需修改
- Broker 启动后需 10-30 秒向 NameServer 注册心跳，验证前稍等
- 10909 是 VIP 通道端口，10911 是主端口，10912 是 HA 端口，三个都要映射
- RocketMQ 5.x 兼容 4.x 的 Remoting 协议，rocketmq-spring-boot-starter 2.3.6 无需改动

### 3.5 MongoDB 7

```bash
docker run -d \
  --name xfjy-mongo \
  --restart unless-stopped \
  -p 27017:27017 \
  -e TZ=Asia/Shanghai \
  -v xfjy-mongo-data:/data/db \
  mongo:7
```

**验证**：
```bash
docker exec xfjy-mongo mongosh --eval "db.runCommand({ping:1})"
```
预期返回 `{ ok: 1 }`。

**注意事项**：
- 开发环境未设认证，连接串 `mongodb://127.0.0.1:27017/xfjy` 直连即可
- **Spring Boot 4.1.1 专有**：MongoDB 连接配置属性前缀为 `spring.mongodb.*`（而非旧版 `spring.data.mongodb.*`），redis/datasource 前缀不变。项目代码已适配，升级 Spring Boot 时注意
- 生产环境加认证：`-e MONGO_INITDB_ROOT_USERNAME=xfjy -e MONGO_INITDB_ROOT_PASSWORD=你的密码`，连接串改为 `mongodb://xfjy:密码@127.0.0.1:27017/xfjy?authSource=admin`

### 3.6 Elasticsearch 8.x

**第一步：调整系统参数（WSL2 必须）**

ES 8.x 要求 `vm.max_map_count >= 262144`，Docker Desktop (WSL2) 默认值不够，需手动设置：

```powershell
wsl -d docker-desktop sysctl -w vm.max_map_count=262144
```

> 每次 Docker Desktop 重启后需重新执行。Linux 宿主机执行 `sudo sysctl -w vm.max_map_count=262144` 并写入 `/etc/sysctl.conf` 持久化。

**第二步：启动 ES**

```bash
docker run -d \
  --name xfjy-es \
  --restart unless-stopped \
  -p 9200:9200 \
  -p 9300:9300 \
  -e discovery.type=single-node \
  -e xpack.security.enabled=false \
  -e ES_JAVA_OPTS="-Xms512m -Xmx512m" \
  -v xfjy-es-data:/usr/share/elasticsearch/data \
  docker.elastic.co/elasticsearch/elasticsearch:8.17.0
```

**验证**：
```bash
curl http://127.0.0.1:9200
```
预期返回 JSON，含 `"version" : {"number" : "8.17.0"}`。

**注意事项**：
- `xpack.security.enabled=false` 关闭安全认证，开发环境简化配置；生产环境必须开启并配置 TLS + 密码
- `ES_JAVA_OPTS` 建议设为宿主机内存的 1/4~1/2，最小 512m，否则启动可能 OOM
- `vm.max_map_count` 不设置时 ES 启动直接崩溃退出，`docker logs xfjy-es` 会看到 `max virtual memory areas` 报错
- Spring Boot 4.1.1 使用新 Elasticsearch Java Client，兼容 ES 8.x，连接地址 `http://127.0.0.1:9200` 无需账号密码（安全关闭时）

## 四、可选中间件部署（AI 推荐增强）

以下两个组件未部署时，推荐引擎自动降级（向量召回/二度好友返回空集），不影响主业务流程。建议先跑通核心链路，再按需部署。

### 4.1 Qdrant（向量检索）

用于双塔模型产出的用户 embedding 向量检索（T3 互惠匹配）。

```bash
docker run -d \
  --name xfjy-qdrant \
  --restart unless-stopped \
  -p 6333:6333 \
  -p 6334:6334 \
  -v xfjy-qdrant-data:/qdrant/storage \
  qdrant/qdrant:v1.12.0
```

**验证**：
```bash
curl http://127.0.0.1:6333/healthz
```
预期返回 `healthz check passed`。

**注意事项**：
- 6333 是 HTTP/REST 端口，6334 是 gRPC 端口，项目用 HTTP 客户端，6333 必须映射
- 首次使用需创建 collection：`PUT http://127.0.0.1:6333/collections/user_embedding`，body 指定 `vectors.size=64, distance=Cosine`。或由 xfjy-spark 训练脚本自动创建
- 训练数据由 `xfjy-spark/train.py` 产出并 upsert 到 Qdrant，未训练时 collection 为空，推荐降级为 ALS+Geo 评分

### 4.2 Neo4j 5.x（二度好友推荐）

用于图查询实现二度好友推荐（P2 功能）。

```bash
docker run -d \
  --name xfjy-neo4j \
  --restart unless-stopped \
  -p 7474:7474 \
  -p 7687:7687 \
  -e NEO4J_AUTH=neo4j/你的密码 \
  -v xfjy-neo4j-data:/data \
  neo4j:5
```

**验证**：
```bash
curl http://127.0.0.1:7474
```
预期返回 200。浏览器访问 http://127.0.0.1:7474 可打开 Neo4j Browser。

**注意事项**：
- `NEO4J_AUTH=neo4j/你的密码` 首次启动设置密码，必须至少 8 位，否则容器启动失败
- 对应环境变量 `NEO4J_PASSWORD` 需填入相同密码，配置项 `xfjy.neo4j.password` 引用它
- 7474 是 HTTP 端口，7687 是 Bolt 协议端口（代码连接用），两个都要映射
- 项目配置 `xfjy.neo4j.uri` 默认 `http://127.0.0.1:7474`；Spring Data Neo4j 实际用 Bolt 连接，启动时会自动探测 7687
- 好友关系数据需自行导入（业务侧写入好友关系时同步写 Neo4j），空库时二度推荐返回空集，自动降级

## 五、数据库初始化

中间件全部启动后，导入全量 SQL 脚本（表结构 + 初始数据，一键完成）：

**验证**：
```bash
mysql -h 127.0.0.1 -u root -p xfjy -e "SHOW TABLES; SELECT COUNT(*) FROM tb_user; SELECT COUNT(*) FROM tb_sensitive_word;"
```
预期：15 张表；`tb_user` 103 条；`tb_sensitive_word` 50 条。

**默认账号**：
- 用户端：`17602026868` / `123456`
- 管理后台：`admin` / `admin123`

> 完整测试账号、万能验证码与基础设施凭证见 [测试账号.md](测试账号.md)。

## 六、后端服务启动

### 6.1 环境变量配置

复制 `.env.example` 为 `.env`，按实际环境填写（默认值适配本机 Docker 部署，开发环境可不改）：

```bash
# 核心变量（默认值已适配本机 Docker 部署，无需修改）
NACOS_SERVER_ADDR=127.0.0.1:8848
MYSQL_URL=jdbc:mysql://127.0.0.1:3306/xfjy?...
REDIS_HOST=127.0.0.1
ROCKETMQ_NAME_SERVER=127.0.0.1:9876

# 需填写的变量
NEO4J_PASSWORD=        # 部署了 Neo4j 才填，与 NEO4J_AUTH 密码一致
HANXIN_APPKEY=         # 接入环信 IM 才填，否则留空（IM 功能降级）
```

### 6.2 编译

```bash
mvn clean compile -DskipTests
```

### 6.3 启动顺序

> 必须先启动 Nacos，再启动业务服务，最后启动 Gateway。各服务通过 Nacos 注册发现，Gateway 依赖服务注册表路由。

```bash
# 1. 认证服务（其他服务依赖其校验 Token）
cd xfjy-sso && mvn spring-boot:run

# 2. BFF 编排层（前端统一入口的代理层）
cd xfjy-server && mvn spring-boot:run

# 3. 各域服务（顺序无要求，建议并行启动）
cd xfjy-user-service && mvn spring-boot:run
cd xfjy-match-service && mvn spring-boot:run
cd xfjy-circle-service && mvn spring-boot:run
cd xfjy-video-service && mvn spring-boot:run
cd xfjy-message-service && mvn spring-boot:run
cd xfjy-pay-service && mvn spring-boot:run
cd xfjy-recommend && mvn spring-boot:run
cd xfjy-elasticsearch && mvn spring-boot:run

# 4. 网关（最后启动，确保路由表就绪）
cd xfjy-gateway && mvn spring-boot:run
```

### 6.4 后端验证

```bash
# Nacos 控制台查看服务注册（应看到 11 个服务实例）
# http://127.0.0.1:8848/nacos → 服务管理 → 服务列表

# 网关健康检查
curl http://127.0.0.1:8090/actuator/health

# SSO 登录接口
curl -X POST http://127.0.0.1:8090/user/login -H "Content-Type: application/json" -d '{"phone":"17602026868","password":"123456"}'
```

## 九、常见问题与注意事项

### 9.1 端口冲突

宿主机已有 MySQL/Redis 等服务占用 3306/6379 等端口时，Docker 端口映射失败。两种解法：
- 停掉宿主机原有服务
- 改映射端口（如 `-p 3307:3306`），同时修改 `MYSQL_URL` 环境变量中的端口

### 9.2 ES 启动即崩溃

`docker logs xfjy-es` 看到 `max virtual memory areas vm.max_map_count [65530] is too low`：
- WSL2：`wsl -d docker-desktop sysctl -w vm.max_map_count=262144`（Docker Desktop 重启后需重跑）
- Linux：`sudo sysctl -w vm.max_map_count=262144` 并写入 `/etc/sysctl.conf`

### 9.3 服务注册不上 Nacos

- 确认 9848 端口已映射（gRPC 端口，缺失时注册失败但日志报错不明显）
- 确认 Nacos 鉴权配置与 `NACOS_USERNAME`/`NACOS_PASSWORD` 一致
- **Nacos 3.x 必须设置 `NACOS_AUTH_TOKEN`/`NACOS_AUTH_IDENTITY_KEY`/`NACOS_AUTH_IDENTITY_VALUE`**，即使 `NACOS_AUTH_ENABLE=false` 也必须设置，否则容器启动直接退出 255（docker-compose.middleware.yml 已配置）
- 查看 `docker logs xfjy-nacos` 是否有报错

### 9.4 RocketMQ 发送消息报 topic not exist

Broker 未开启 `autoCreateTopicEnable=true`。检查挂载的 broker.conf 是否生效：
```bash
docker exec xfjy-rocketmq-broker cat /home/rocketmq/rocketmq-5.3.1/conf/broker.conf
```

### 9.5 MongoDB 连接报 AuthenticationFailed

Spring Boot 4.1.1 属性前缀变更：`spring.mongodb.uri`（非 `spring.data.mongodb.uri`）。项目代码已适配，若自行升级 Spring Boot 版本需检查此项。

### 9.6 中文乱码

MySQL 导入和连接必须统一 utf8mb4：
- 导入加 `--default-character-set=utf8mb4`
- 连接串已含 `characterEncoding=utf8`
- 容器启动参数已含 `--character-set-server=utf8mb4`

### 9.7 Docker Desktop 重启后中间件未自启

所有容器已配置 `--restart unless-stopped`，Docker Desktop 启动后容器自动恢复。但 ES 需要重新设置 `vm.max_map_count`（见 9.2），否则 ES 容器会反复崩溃。

### 9.8 数据卷备份与清理

```bash
# 查看数据卷
docker volume ls | grep xfjy

# 备份 MySQL 数据（导出 SQL）
docker exec xfjy-mysql mysqldump -uroot -p123456 --single-transaction xfjy > backup-xfjy.sql

# 彻底清理（危险操作，确认后执行）
docker rm -f xfjy-mysql xfjy-redis xfjy-nacos xfjy-rocketmq-namesrv xfjy-rocketmq-broker xfjy-mongo xfjy-es
docker volume rm xfjy-mysql-data xfjy-redis-data xfjy-mongo-data xfjy-es-data
```

### 9.9 生产环境部署建议

- 所有中间件开启认证：MySQL 密码、Redis 密码、MongoDB 认证、Nacos 鉴权、ES TLS+密码
- 配置外置：通过 Nacos 配置中心管理各服务 application.yml，敏感信息用环境变量注入
- 用 docker-compose 统一编排（见第十章 Linux 服务器部署）

- 阿里云 AK 务必通过环境变量注入或配置中心管理，禁止硬编码入库

**Gitea 1.22 + act_runner 踩坑（实测，2026-10-30）**

1. **act_runner 环境变量名**是 `GITEA_INSTANCE_URL`，不是 `GITEA_INSTANCE`；写错会报 `instance address is empty` 且 runner 一直重试注册。
2. **Gitea 1.22 的 act v0.259.1 不支持 `workflow_dispatch.inputs`**：解析 `on:` 时会把事件值当分支过滤条件，`inputs` 映射触发 `unknown on type` → **整个 workflow 被忽略**（push 也不再触发）。参数要放在**顶层 `inputs:`**，`on.workflow_dispatch:` 留空。
3. **job 容器解析不到 `gitea`**：act_runner 给每个 job 自建独立网络，其中没有 `gitea` 服务名，checkout 报 `Could not resolve host: gitea`。解决：`deploy/gitea/config.yaml` 里 `container.options` 加 `--add-host gitea:172.19.0.2`（Gitea 容器在 gitea-net 上的地址）。
4. **不要在工作流里重复挂载 docker.sock**：act_runner 默认已挂载，再声明 `container.volumes` 会报 `Duplicate mount point: /var/run/docker.sock`，容器创建直接失败。
5. **本地构建的镜像**（如 `xfjy/ci:latest`）没有对应 registry，act 在镜像不存在时会去 `docker pull` 拉取并失败 → **必须先在宿主机构建好 CI 镜像再触发流水线**。
6. **CI 镜像网络源**：服务器访问 Docker Hub 极慢（node:22 拉 30 分钟未完成）。CI 镜像基底用本地已有的 `eclipse-temurin:25-jre-jammy`，Node 走 npmmirror、Maven 走阿里云、apt 走腾讯云、compose 插件走阿里云 docker-ce 源。
7. **Dockerfile 里 `npm config set registry` 会报 exit 129**：改为直接写 `/etc/npmrc`（不要写 `/root/.npmrc`，该路径在部分基础镜像里已是同名目录）。
8. **`/bin/sh`(dash) 会展开 `*` 通配符**：`git config --global --add safe.directory "*"` 要加双引号，或在 Dockerfile 里声明 `SHELL ["/bin/bash", "-c"]`。
9. **compose 构建上下文**：compose 文件在 `deploy/` 下时，`context: .` 会解析成 `deploy/` 子目录，Dockerfile 路径变成 `deploy/deploy/...`。应写 `context: ..` + `dockerfile: docker/Dockerfile.java`。
10. **`.dockerignore` 不能排除整个 `target/` 目录**：Docker 排除目录后会跳过子项，否定规则救不回，jar 拷不进镜像。改为 `**/target/*` + `!**/target/*.jar`。
