# 头像裁剪交互规范

> 状态：待实现（本文档先行，代码按此改造）
> 适用页面：`xfjy-app/src/pages/mine/avatar-crop.vue`
> 唯一真源：`xfjy-app/src/constants/avatar.ts`（比例、导出尺寸、最小源图、格式、质量、最大倍率、2MB 上限）

## 0. 术语与换算

| 术语 | 定义 |
| --- | --- |
| `STAGE` | 裁剪舞台边长（px），即 canvas 的 CSS 边长 |
| `GAP` | 舞台与取景框之间的留白（px），`48rpx` |
| `FRAME` | 取景框边长（px），`STAGE - 2 × GAP` |
| `rotW / rotH` | 原图按当前旋转角（0/90/180/270）后的宽 / 高 |
| `base` | 缩放基准，`= max(STAGE / rotW, STAGE / rotH)` |
| `zoom` | 用户缩放倍率，`1.0 – 4.0` |
| `scale` | 实际绘制缩放，`= base × zoom`（导出时再乘 `导出边长 / STAGE`） |

换算：项目按 375 宽设计，`1rpx = 0.5px`；`--space-xl = 48rpx = 24px`。

## 1. 视觉规格

### 1.1 舞台

| 项 | 规则 |
| --- | --- |
| 宽度 | `100%`（等于 `100vw`） |
| 高度 | `min(100vw, 55vh)`，375×812 下 = `375px` |
| 位置 | 水平居中、贴页面顶部（导航栏之下）；不与底部操作面板重叠 |
| 背景 | `var(--bg-sub)` |
| 溢出 | `overflow: hidden` |

### 1.2 取景框

| 项 | 规则 |
| --- | --- |
| 形状 | 正方形 |
| 边长 | `FRAME = STAGE - 2 × GAP`；375 宽下 `375 - 48 = 327px`（±1px） |
| 居中 | 舞台内水平、垂直居中，四边各留 `GAP = 24px` |
| 圆角 | `0`（直角） |
| 圆形辅助线 | **需要**：框内画 1px 圆，直径 = `FRAME`，颜色 `rgba(255,255,255,.35)`，不加阴影 |

**结论与理由**：App 内头像最终以圆形展示，但导出产物是 400×400 方形。取景框保持方形 + 内部圆形辅助线，既保证「方框所见即所得」，又提示圆形成品会裁掉四角；若直接做圆形取景框，用户无法判断方形导出图四角的构图，且圆形边缘在深色图上看不清。

### 1.3 遮罩（框外压暗）

| 项 | 规则 |
| --- | --- |
| 颜色 | `rgba(0, 0, 0, .55)`，固定值，不随主题变化 |
| 覆盖范围 | 取景框以外的全部舞台区域（四边矩形拼接，不用整体遮罩挖洞） |
| 层级 | 在 canvas 之上、取景框与倍率徽标之下 |

**为什么是 .55**：低于 `.45` 时深色照片与遮罩几乎同色，用户看不出框边界；高于 `.65` 时暗部细节被吃掉，无法判断构图。`.55` 在深色与浅色照片上都能保留轮廓，同时让框内亮度明显高于框外。遮罩压的是「图片」，不是页面底色，所以不能用会随主题变灰白的 `--bg-page`。

### 1.4 框边

| 项 | 规则 |
| --- | --- |
| 宽度 | `1px`（`2rpx`） |
| 颜色 | `rgba(255, 255, 255, .9)` |
| 描边方式 | **内描边**：`box-sizing: border-box`，边框绘制在 `FRAME` 内，框外尺寸仍为 `FRAME` |
| 阴影 | `var(--shadow-float)`，仅用于与浅色图分离 |

### 1.5 三分网格

| 项 | 规则 |
| --- | --- |
| 线宽 | `1px` |
| 颜色 | `rgba(255, 255, 255, .25)` |
| 位置 | 垂直 33.33% / 66.66%，水平 33.33% / 66.66% |
| 显隐 | **常显**（不做「拖动时才出现」） |
| 层级 | 在取景框之上、倍率徽标之下 |

### 1.6 倍率徽标

| 项 | 规则 |
| --- | --- |
| 位置 | **顶部居中**：舞台上沿居中，`top = (GAP - 20px) / 2 = 2px` |
| 显示时机 | 图片加载完成后**常显** |
| 格式 | `1.0×`（数字在前，保留 1 位小数，范围 `1.0× – 4.0×`） |
| 字号 | `var(--fs-sm)`（`24rpx = 12px`） |
| 行高 | `20px`（无对应 token；取 20px 是为了在 24px 遮罩带内上下各留 2px，不压到框边） |
| 底色 | `rgba(0, 0, 0, .45)` |
| 文字色 | `rgba(255, 255, 255, .95)` |
| 圆角 | `var(--radius-pill)` |
| 内边距 | `0 var(--space-sm)`（水平 8px） |

### 1.7 token 映射

| 用途 | token / 数值 |
| --- | --- |
| 框留白 | `--space-xl`（48rpx） |
| 面板左右内边距 | `--space-lg`（32rpx） |
| 面板顶圆角 | `--radius-lg` |
| 按钮间距 | `--space-md`（24rpx） |
| 工具按钮间距 | `--space-xl` |
| 提示/徽标字号 | `--fs-sm` |
| 面板/文案颜色 | `--bg-card` / `--text-hint` |
| 舞台底色 | `--bg-sub` |

遮罩、框边、网格、圆形辅助线、徽标底色为**固定中性 rgba**：它们必须压在任何照片上成立，语义色 token（会随主题变化）不适用。

## 2. 手势规格

### 2.1 初始缩放

- 取景框 cover 基准：`coverFrame = max(FRAME / rotW, FRAME / rotH)`。
- 实际基准：`base = max(STAGE / rotW, STAGE / rotH) = coverFrame × (STAGE / FRAME)`。
- **`zoom = 1.0` 的定义**：图像铺满取景框，且四边各保留 `GAP = 24px` 可拖余量（375 宽下每边 24px）。
- **为什么不是严格 coverFrame**：若 `base = coverFrame`，`zoom = 1.0` 时钳制余量为 0，单指拖动完全无响应，与「按住即拖」冲突。多留 `GAP` 后，1.0 即可拖动，且拖到边仍不露底色。
- 图片加载完成、旋转完成、重置后，`zoom` 回到 `1.0`、偏移回到 `0,0`。

### 2.2 缩放范围

| 项 | 规则 |
| --- | --- |
| 范围 | `1.0 – 4.0`（`AVATAR_MAX_ZOOM`） |
| 越界行为 | **硬停**，`clamp` 到边界；不做回弹 |
| 理由 | 回弹必须依赖动画或定时器，会和下一帧拖动争抢位姿，窄框内容易出现「拉回—再被拖走」的抖动 |

### 2.3 单指拖动

| 项 | 规则 |
| --- | --- |
| 启动条件 | `touchstart` 单指即进入拖动，**无阈值** |
| 跟手 | 像素 1:1：`offset = 起点偏移 + (当前触点 - 起点触点)` |
| 动画 | **禁止** CSS `transition` / 动画；每帧直接写变换参数并重绘 |
| 松手 | 立即停在原位，**不做惯性**；理由：惯性会把图甩到边界并停顿不稳，与「停顿要稳」冲突 |
| 与双指 | `touches ≥ 2` 时单指拖动立即失效；抬起一指后以剩余手指为新起点继续拖 |

### 2.4 边界钳制

```
maxX = max(0, (rotW × base × zoom - FRAME) / 2)
maxY = max(0, (rotH × base × zoom - FRAME) / 2)
offsetX ∈ [-maxX, maxX]
offsetY ∈ [-maxY, maxY]
```

- 缩放后立即重新钳制（余量随 zoom 实时变大）。
- 旋转后宽高互换，重新计算 `base / maxX / maxY`，偏移归零后再钳制。
- 任一时刻，图片覆盖区域都不得让取景框内出现舞台底色。

### 2.5 双指缩放

| 项 | 规则 |
| --- | --- |
| 进入 | `touches ≥ 2` 时记录 `pinchStart = 两指距离`、`pinchZoom = 当前 zoom` |
| 计算 | `zoom = clampZoom(pinchZoom × 当前距离 / pinchStart)` |
| 锚点 | 以两指中点为锚（等价 `zoomAtPoint`），缩放后钳制 |
| 结束 | `touchend` 后若剩 1 指，重置拖动起点（`dragOrigin = 当前 offset`），避免跳变 |

### 2.6 H5 桌面端

| 项 | 规则 |
| --- | --- |
| 拖动 | canvas `mousedown`（仅左键）+ `window` 级 `mousemove` / `mouseup`；`mouseup` 与 `onUnload` 必须移除监听 |
| 滚轮 | 每档 `1.1` 倍；`deltaY > 0` 缩小，否则放大 |
| 锚点换算 | `anchor = clientX/Y - canvasRect.left/top`；`C = STAGE / 2`；`ratio = newZoom / oldZoom`；`offset' = (anchor - C) - ratio × (anchor - C - offset)`，再钳制 |
| 阻止滚动 | `wheel` 必须 `preventDefault` |

### 2.7 旋转

| 项 | 规则 |
| --- | --- |
| 步进 | `0 → 90 → 180 → 270 → 0` |
| 坐标系 | `translate(W/2 + offsetX, H/2 + offsetY) → rotate(angle) → scale(scale) → drawImage(img, -w/2, -h/2, w, h)`，即始终以图片中心为原点旋转 |
| 旋转后 | 偏移归零、重新计算 `base` 与钳制上限、重绘 |
| 反馈 | 旋转按钮可重复点击；不改变 `zoom` |

## 3. 状态与异常

| 状态 | 触发 | 界面表现 | 按钮 | 文案 |
| --- | --- | --- | --- | --- |
| 图片加载中 | 进入页面、`getImageInfo` 未返回 | 舞台中央 loading 遮罩：spinner + 文案 | 旋转/重置/完成全部禁用 | `图片加载中` |
| 加载失败 | `getImageInfo` fail | toast 后 1.5s 自动返回上一页 | — | `图片读取失败，请重新选择` |
| 无有效图片地址 | `src` 为空 | toast 后返回上一页 | — | `图片地址无效，请重新选择` |
| 分辨率过低 | 任一边 `< 200px` | toast 后返回上一页 | — | `图片分辨率过低（需 ≥200×200），请重新选择` |
| 超出 2MB | 资料页选图后校验 | toast，不进入裁剪页 | — | `图片不能超过 2MB` |
| 格式不支持 | 资料页选图后校验 | toast，不进入裁剪页 | — | `仅支持 JPG/PNG/WebP 图片` |
| 导出中 | 点击完成、`canvasToTempFilePath` 未回调 | 完成按钮 loading，禁止重复点击 | 取消/旋转/重置/完成全部禁用 | 按钮文案保持 `完成` |
| 上传中 | 裁剪页回传后，资料页 `uploadImage` | 资料页头像上叠 spinner，更换头像按钮禁用 | 更换头像禁用 | 资料页现有 loading 态 |
| 上传失败 | 上传接口失败 | toast | 恢复可点 | `上传失败，请检查网络后重试` |
| 网络异常 | 上传抛异常 | toast | 恢复可点 | `网络异常，头像未更新，请重试` |
| 上传成功 | 保存资料成功 | toast，头像替换 | — | `头像已更新` |

**「完成」禁用条件**：`!imageReady || exporting || 无有效 src`。任一条件成立即禁用并降低视觉权重。

## 5. 多端差异

### 5.1 dpr 与预览清晰度

| 项 | 规则 |
| --- | --- |
| dpr 取值 | `dpr = min(window.devicePixelRatio \|\| 1, 2)` |
| 预览 canvas 实际像素 | `round(STAGE × dpr)`；CSS 尺寸仍为 `STAGE`（不放大布局） |
| 绘制 | 先 `ctx.scale(dpr, dpr)`，之后所有坐标继续按 CSS px 书写（`drawInto` 不变） |
| 封顶 2 的理由 | 3x 屏按原始 dpr 会让 375×375 的预览画布达到 1125²，移动端内存与每帧重绘成本翻倍，收益肉眼不可辨 |
| 导出 | **不按 dpr 放大**：固定 400×400，避免头像文件随设备变大 |

### 5.2 微信小程序

| 项 | 规则 |
| --- | --- |
| canvas 类型 | 预览使用 `type="2d"`（可通过 node 设置真实像素尺寸）；H5 继续用 `canvas-id` 旧版接口 |
| 尺寸设置 | `node.width = round(STAGE × dpr)`、`node.height` 同上；`node.getContext("2d")` 后 `scale(dpr, dpr)` |
| 导出 | 离屏/隐藏 canvas 固定 `400×400`；`uni.canvasToTempFilePath({ canvas: node, x/y/width/height: 0/0/400/400, destWidth: 400, destHeight: 400, fileType: "jpg", quality: 0.9 })`；2d canvas **必须传 `canvas` 节点**，不能只传 `canvasId` |
| 旧版接口 | 若保留旧版，只能传 `canvasId`，且无法设置 dpr 像素尺寸；不作为目标实现 |

### 5.3 两端统一

- 取景、变换、导出全部共用同一 `drawInto(ctx, W, H)`，导出时 `factor = W / STAGE`。
- 输出：`400×400`、`jpg`、`quality 0.9`，参数只来自 `constants/avatar.ts`。

## 6. 验收清单

- [ ] 375×812 下 `STAGE = 375px`、`FRAME = 327 ± 1px`，四边留白各 `24px`。
- [ ] 用纯白图验收：框内约 `#ffffff`，框外约 `#737373`（255×0.45），框内外亮度差明显。
- [ ] 框边 1px 白线在纯白图、纯黑图上均能看清；网格三分线常显且位置 33.33% / 66.66%（±1px）。
- [ ] 倍率徽标常显、格式 `1.0×`，缩放时按 0.1 步进变化，位于顶部居中。
- [ ] `1.0×` 时四向拖动均有 ≥24px 余量，松手即停、无回弹。
- [ ] `4.0×` 时向四角拖到边界，取景框内任一像素都不露舞台底色。
- [ ] 双指缩放过程中图像无跳变；松开一指后继续单指拖动无跳变。
- [ ] 旋转 90° 后边界重新计算，四向拖到边仍不露底色。
- [ ] 预览 canvas 在 dpr=2 设备上实际像素 = `2 × CSS 边长`，放大 4× 后无明显锯齿。
- [ ] 导出文件为 `400×400`、`jpg`、`quality 0.9`，体积 ≤ 2MB。

## 7. 禁止事项

1. 禁止在页面内写死 hex / rgb 颜色；仅本文档列出的中性 `rgba()` 例外。
2. 禁止用 CSS `transition` / 动画模拟拖动手感，拖动必须像素级直写。
3. 禁止加拖动惯性。
4. 禁止给单指拖动设置启动阈值。
5. 禁止用 `as any`、`@ts-ignore`、`@ts-nocheck` 绕过 canvas 类型。
6. 禁止引入第三方裁剪库或新建第二个裁剪页面。
7. 禁止把 `400 / 1:1 / 200 / 2MB / 4×` 等口径写在页面里；只允许从 `constants/avatar.ts` 引用。
8. 禁止改动上传接口、后端字段与资料页保存流程。
9. 禁止在 `zoom = 1.0` 时把钳制余量算成 0（会导致「只能缩放不能拖」）。
