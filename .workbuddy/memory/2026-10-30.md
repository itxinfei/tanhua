## CI/CD 补齐：Jenkins 部署后端服务 (16:00-17:20)
### 架构澄清（用户说明）
- 后台管理(xfjy-admin)、App(xfjy-app) 在**本地电脑运行**；Java 接口服务在服务器上通过 **CI/CD 部署**。
- 服务器 192.168.20.133：Jenkins 容器 xfjy-jenkins(8888)，job `xfjy` 为 Declarative Pipeline（scriptPath=Jenkinsfile, lightweight，SCM=gitee */master，GiteePushTrigger 触发）。
- 应用服务**不是容器**，是宿主机 `nohup java -jar ~/mytanhua/<svc>/target/*.jar` 进程（setsid 脱离会话，勿用 `nohup bash -c '... &'` 双层后台，SSH 断开会被连带杀死）。
- 环境变量：MYSQL_URL/USERNAME/PASSWORD、REDIS_*、NACOS_SERVER_ADDR、ROCKETMQ_NAME_SERVER、NEO4J_PASSWORD、JAVA_HOME=~/tools/jdk25。

### 部署通道（重要）
- Jenkins 容器内 **jenkins 用户无 docker.sock 权限**；nsenter 进宿主 mount ns 被拒。
- 可行方案：Jenkins 容器 → **SSH 到宿主机 172.18.0.1:8848 网关**（专用密钥 /var/jenkins_home/.ssh/xfjy_deploy_key，comment=xfjy-ci-deploy，公钥已加到宿主机 ~/.ssh/authorized_keys）。
- 通过 SSH+scp 投递 jar，SSH 调 `bash deploy/deploy-service.sh <svc>` 完成 备份→停旧→换jar→setsid重启→健康检查。
